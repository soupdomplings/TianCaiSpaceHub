# 天才 Hub 微信小程序

两个底部标签共用 iPhone 风格组件和浅深配色。源码在 `miniprogram/`。电脑配对、原生会话和个人充值分别通过统一服务、目标 Hub 和小分队账本完成。

## 无 AppID 的本地体验

`preview/` 是独立的开发者工具工程。在微信开发者工具的「导入项目」选择该目录，使用游客模式或工具提供的测试号。导航栏会显示「本地演示」。这份工程内的「演示工作电脑」可以打开历史、发送示例消息、选择答案或拒绝审批。个人充值使用本地模拟账本。测试数据与正式版使用各自的缓存，演示工程的登录、支付与网络入口保持关闭。

从仓库重新生成体验工程时，在当前目录依次执行：

```powershell
npm ci
npm run build
npm run preview
npm run check:preview
```

## 正式接入

1. 部署统一服务，在公众平台为 AppID 配置该服务的 HTTPS request 合法域名并完成支付能力开通。项目中的 `touristappid` 仅用于开发者工具本地导入。
2. 将 `project.config.json` 的 `appid` 设置为真实 AppID，指定公共服务地址，再构建正式工程：

   ```powershell
   $env:HUB_MOBILE_ORIGIN = 'https://你的已配置域名'
   npm run build
   npm run check
   npm test
   ```

3. 使用开发者工具导入本目录，上传登记的体验版。AppSecret、支付 AppKey 与支付验签密钥只配置在服务端。
4. 打开目标电脑的 Hub，生成手机二维码，用小程序「远程连接 → 扫码配对电脑」扫描并在电脑上确认。再次打开可恢复上次使用的设备和会话。清除手机数据后需扫码重新配对。
5. 个人首页按当前微信身份绑定小分队账户，充值订单以站点到账确认为准。关闭支付界面或从后台回来均可复查相同订单。

`build.cjs` 生成 AES-GCM 库，库及许可证随小程序内置。所有 RPC 在手机加密后发往统一服务。密钥通过微信本地缓存的加密选项保存。模型凭据、真实对话及文件正文不进入服务端。V1.0.58 起，思考过程、工具执行、文件变更和产物四项勾选只在会话所在电脑（发送端）Hub「远程连接 → 设置 → 显示内容（本机发送）」管理；A 查看 B 的会话时使用 B 的选择，A 的勾选只管 A 自己提供的会话。小程序作为接收端，根据历史和每条实时事件中的 `displayContent` 跟随；旧手机 `display` 缓存不再使用。四项默认关闭，仅影响之后收到的新内容；已读取的生成文件仍可从「本会话产物」手动下载。将 `HUB_MOBILE_ORIGIN` 设置到另一部署前，应清除本地绑定并在该部署重新配对。

## 本次如何验收

无 AppID 的演示工程用于核对页面：会话上方显示「显示内容由会话所在电脑 Hub（发送端）」的提示，没有四个手机开关；发送演示消息后仍能在「本会话产物」找到文件。演示使用固定的模拟目标设置，不能验证真实电脑勾选后的手机同步。

真实联动时，安装本批新版 Hub，并将正式小程序工程按上节配置、构建并上传体验版。在手机微信打开这份体验版，配对目标电脑后进入原会话；在目标 Hub 逐项勾选，在同一任务的后续实时内容上核对网页与小程序一致。关闭产物时仍可手动下载，重新打开旧会话不补旧过程。重启 Hub 后勾选应保留。小程序版本独立于 MSI，更新电脑安装包后仍需重新构建或上传小程序。完整交付见[V1.0.58](../docs/releases/v1.0.58.md)。

## 离线核验

`npm run check` 调用微信 WCC 和 WCSC 编译本工程全部 WXML、WXSS，再检查页面代码及清单语法。`npm test` 核验双向加密、配对输入、实时显示边界及审批语义。正式 AppID、手机微信、真实充值、电脑配对和文件分享需单独验收。
