## 未发布 · 2026-10-03 · 天工多模型、上游流式聚合与外部消息执行端

关联 TC-011、TC-012；基于 `3b3f213` 的开发已保存为 `9b9702ec2368eb0ec9956b9c8505569772ca8597`，该保存点源码版本为 `0.4.29-5`，尚未发布。下列构建属于这个上游合并前保存点；当前版本状态见本页顶部整合记录。此前单模型与厂商适配条目保留当时开发状态，最终一并包含于该提交。

- 用户反馈天工支持多个模型，原固定 `tiancaispacehub` 行无法分别保存多个渠道。现在新增条目拥有独立 UUID、数据库行、`gmclaw:<entryId>` 渠道和地址；同一模型可通过不同渠道或参数保存，旧行/渠道/入口兼容保留。可新增、编辑、设为默认和删除，并撤销最近一次对应操作。
- 页面版本覆盖全部管理模型、默认选择和天工专用 Hub 渠道；普通渠道和普通模型非默认字段变化不误拒。备份元数据升级 v2、兼容读取旧 v1；新 UI token 为 `gmclaw-v3`，旧页面需刷新。旧程序不保证读写新备份或理解新条目路由，降级前需处理新条目并备份配置。
- 新来源渠道关联指纹忽略 `is_active/updated_at` 变化，保留天工内改变默认模型后的来源显示；旧完整行指纹在时间戳改变后需重选来源并保存一次。完整页面版本与备份核验继续包含行内容和默认标志。桥接界面保存后台重读最新 Hub 配置、仅合并未被外部改动的桥接字段，保留期间模型保存等无关变更。
- 用户已确认上一轮模型保存成功且无需完全退出重开天工。当前移除模型保存/还原的强制重启提示，`restartRequired=false`；该有限验收不覆盖本轮新增多模型、流式或 IM 功能。
- 天工继续接收非流式 Chat JSON；OpenAI Responses 上游启用流式并有界聚合，其他 Responses 与 Chat 路径兼容有效 JSON/SSE。完整结束、错误、断流、大小和超时检查避免返回空成功结果，已开始的响应不自动重放。
- 新增 TC-012 第二阶段首版：用户通过天工启动环境 `GMCLAW_AUTH_TOKEN` 与 Hub 本地 `gmclawBridge` 显式授权，飞书/微信/企微用 `/gmclaw` 绑定发送者独立会话；复用当前账号权限和回复通道，串行执行文字任务，父会话工具审批使用完整参数、当轮调用 ID 和短期确认码。子 Agent 审批拒绝转交父会话，需回天工处理。
- `tool_execution_mode=confirm` 固定使用且 Hub 不自动批准，但是否产生待审批事件仍由天工自身策略决定；项目目录内读写等工具可能直接执行，工作目录需由用户明确选择授权，不能宣称每个工具都经 IM 确认或拥有文件系统沙箱。天工自有 MCP 设置由天工继续管理，不作为本轮或默认后续目标。
- 外部消息首版不提供 Telegram 天工执行、完整 Codex 会话卡片、附件、主动取消或 MCP CRUD；会话身份隔离不等于共享工作目录的数据隔离。执行中断或超时不自动重试，也不声称已取消工具；普通答案超过 16000 个 Unicode 字符明确截断，审批超过 16 调用或 24 KiB 说明则拒绝批准而非截断。
- 验证：该保存点源码通过 Windows x64 GUI/测试代码 `cargo check` 与调试 EXE `cargo build`，`cargo fmt --check`、差异空白、当轮文档链接、PE/GUI 子系统和哈希静态核对通过；直接 DLL 导入文件已确认，系统 API-set 列在依赖记录中，未执行加载器验证。编译保留未使用代码等警告。该阶段历史 EXE 为 `55,158,784` 字节，哈希与完整命令见模型专题；不是后续上游整合产物。新增 SQLite、多条目路由、流式聚合、Harness 事件及审批夹具，按用户分工未执行；未主动启动 Hub/Codex/天工、未发起真实模型或工具执行、未修改用户实际配置。Windows 待用户验收，macOS 待构建和实机验证，不新增 Linux 范围。
