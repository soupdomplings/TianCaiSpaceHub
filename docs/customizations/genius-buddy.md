## V1.0.25 正文、草稿和配置刷新

用户反馈助手正文末行被裁切、Ctrl+Enter 已发送却留下输入文字，另要求隐藏消息区和编辑框的可见滚动条。正文旧高度以 wx 基础字体字高乘估算行数，不能代表 RichEdit 的中文回退字体、混合样式与实际软换行。Windows 现在在确定控件宽度后，使用 RichEdit 的同步 [EM_REQUESTRESIZE 尺寸通知](https://learn.microsoft.com/en-us/windows/win32/controls/em-requestresize) 读取实际内容高度，再向消息块、正文和气泡逐层传递；测量通知仅临时监听本控件，结束即恢复原事件掩码和监听。保留宽度/内容缓存，不增加每次轮询的全量排版。macOS 保留现有估算路径，需单独验收。

输入快捷键旧回调没有显式消费事件，而 wxDragon 默认 `Skip(true)`；原生多行框继续插入换行，导致异步成功响应中的原文比较失败。Ctrl+Enter 现在明确 `skip(false)`，只有成功且输入仍为原提交草稿时才清空；发送失败和提交后新写的草稿保留。Esc 和输入框末端的定向 Tab 同样消费已处理事件。对话 ScrolledWindow 隐藏滚动指示，输入框增加 `NoVScroll`，正文继续使用已有原生无竖栏样式；滚轮、键盘滚动及原生选择复制保留，不将输入框滚轮转给消息区。

助手状态新增读取现有 Hub 配置的 `configurationRevision`，首次有效及后续非空修订变化通知页面刷新，不等待整轮工具对话结束。缺字段不覆盖已观察修订；不解析回复正文、不新增哈希或独立版本层。`AssistantUi::on_configuration_changed` 由 GUI 接线到已有模型/渠道刷新流程，后台实际写入与客户端来源显示修正的集成状态由管理会话记录。常规配置、账号切换和工具权限语义不变。

准备/移除 Server 的确认接入统一主题确认框，仍只确认一次。清空临时内容、准备和移除完成后使用统一短提示，明确操作失败使用可展开的统一错误提示；轮询、消息流、业务详情及当前运行状态仍就地展示，不因每次刷新或发送重复弹提示。未增加下载、自动安装或新确认步骤。

维护入口为 `src/gui/assistant.rs`、`src/gui/assistant_markdown.rs`，统一反馈依赖 `src/gui/feedback.rs`；无需配置迁移。回滚这些界面修复不撤销已保存的模型和渠道。新增非交互隐藏合成用例 `assistant_composer_acknowledgement_preserves_drafts_and_refreshes_configuration`、`native_text_height_contains_mixed_fonts_wrapping_and_preserves_selection`，仅设置合成状态并测量/断言，覆盖成功清空、失败留稿、新稿保留、修订通知、混合字号与中文软换行和选区保留。另有 `assistant_composer_native_shortcut_and_scroll_without_indicators` 使用合成原生键盘/滚轮消息，显式标为 ignored，本批不执行此输入夹具。开发会话仅完成源码及差异检查，未运行 Cargo、产品、客户端或模型；编译和必要离线执行交管理会话，真实显示、滚动手感及用户环境留待用户验收。

## V1.0.24 配置读取与真实模型来源

管理会话最终通过本轮 45 个不同 Rust 定向用例、7 项 ZCode 脚本检查；其中搭档原生滚轮、Markdown、展开收起、菜单动效与模型草稿均有实际执行结果。真实 Server/管理员模型在隔离目录同一对话完成 5 轮、15 次工具调用：未知 `gpt-6.2` 不造源、`gpt-6-a` 前缀列候选、选定 WorkBuddy 别名实际保存、默认强度 `max` 回读、生成 Codex 独立可见副本并确认 `using:true`。不启动用户客户端，不请求夹具来源推理接口，没有新建账户密钥；V23 密钥验收保持原归属。Windows 包和实机待验边界以 [V24 交付](../releases/v1.0.24.md) 为准。

用户反馈请求配置 WorkBuddy 模型时助手称无法读取，配置 ChatGPT 的 `gpt-6.2` 时却向普通来源添加名称后声称已完成。代码确认 WorkBuddy、天工成功状态会包含 `error: null`，旧桥接把 error 字段存在视为失败；本轮改为仅非 null 错误或失败 HTTP 状态报错。尚无该次工具轨迹，不能断言用户原回复完全由这一个缺陷造成。读取客户端原生文件真正失败时，`hub_read_configuration` 继续返回已读 Hub 渠道和目标，客户端部分为 `readStatus: error` 与具体原因；不伪造空 entries，不据此覆盖损坏文件。目标发现或 Hub 配置读取本身失败仍沿原错误处理。

新增 `hub_resolve_model`，只在已启用普通来源的实际 models 和别名中先精确、再前缀匹配；固定 Codex 能力目录、停用来源、专用副本及通配符不证明上游模型存在。唯一候选返回真实 channel/model，多个候选或没有匹配时先说明/询问必要选择，不把用户输入的近似名称自动塞进来源。配置客户端必须调用 `hub_configure_client`，保存普通来源不等于完成接入。

用户明确要求新增外部来源或新上游 ID 时，可调用 `hub_read_channel_models`：已有渠道传 channel；新连接先用原本机表单取得凭据引用，再传 settings 与 credentialReference。目录复用外部导入读取器，单次 GET、按现有出站代理、不跟随重定向、不发起推理；响应体及目录格式沿原限制。成功读取或小分队 prepare 返回的真实目录只保留在当前搭档内存，绑定协议、地址、模型目录、兼容参数和本机密钥，不把密钥发给模型。新增 ID/别名上游必须来自该连接已有声明或上述目录；此次保存自己声称的 models 不能自证。目录失败、不支持或 ID 不在其中时不保存猜测结果，可提示核对接口或使用原模型与渠道入口。已存模型、正常修改权重/参数及替换密钥沿原行为保留，不增加确认或重复目录读取；更换连接后新增声明重新核对实际来源。

Codex 回读 models 增加 `using`、`enabled`、实际 routes；唯一来源时同时提供 `providerRoute`、`channel` 和 `upstreamModel`，多个来源通过 routes 如实列出。配置返回的独立 model 是后续回读身份，不给 Codex 写普通 desktop_binding。WorkBuddy、天工仍按实际 entryId 回读原生条目；客户端加载和真实模型推理另外验收。指引同步要求简短 Markdown 汇报，仅有选择时列少量候选，不复述大段内部流程，也不在未调工具或工具未失败时声称无法读取。

本轮未改功能默认开关、共享 Server 发现/安装、登录和删除确认语义；无需配置迁移。停用或回滚代码不会撤销已经保存的渠道/客户端配置，恢复沿各原生 writer 的备份及后改保护。

新增离线夹具覆盖 error:null 与真实读取错误、未知/歧义 ID 不写入、真实别名生成 Codex 独立副本、WorkBuddy 原生保存/参数回读/一次删除确认，以及目录证明只能用于其连接。原生路径用测试子进程与临时目录隔离，不修改用户 WorkBuddy/天工文件；新增 opt-in 真实验收保持同一个对话完成未知模型、前缀选择、WorkBuddy 保存/参数及 Codex 独立副本五轮流程，仅其子进程覆盖用户目录。实现与测试入口为 `src/assistant/{tools,acceptance,guide}.rs` 和 `src/web.rs::assistant_configuration_operation`。开发交接仅做格式及差异检查，Cargo、真实 Server/管理员模型和 Windows 包由管理会话统一执行并在 V24 交付记录登记；未执行项不计为通过，macOS 保持待验收。

## V1.0.23 原生浮层与操作指引

V1.0.22 的普通子 Panel 在业务页上方仍会被嵌套原生卡片、图表及输入控件重绘覆盖。修复限定于浮层宿主：显式启用 Windows 原生兄弟/子级裁剪，再以不激活的子窗抬升维护顺序。保持 Hub 内子窗、纯对话图标、无产品标题，展开、定位和切页后维护层级。根因、vendor 维护入口和回滚见 [桌面视觉](../development/desktop-visual-system.md#2026-11-11-天才搭档原生遮挡修复本轮开发)。

助手现在使用随源码维护的 [中文操作指引](../../src/assistant/guide.md)，同一份内容注入 thread 的 developerInstructions，并由 `hub_help` 返回。要求读取当前身份及支持参数、执行明确的常规配置、保存后回读核对，再汇报真实结果；工具失败或能力不支持时说明限制。维护能力时应同时更新工具 schema、读回投影及这份指引，不能只教模型宣称成功。

本轮补齐渠道参数回读、普通客户端副本的实际 model/label、Codex 动态模型继承后的有效能力，以及顶层 parameterHelp。精确内置 Codex 模型的固定能力不宣称可直接覆盖，按需采用独立动态别名。WorkBuddy 仅公布原生 writer 确实保存的默认思考强度，拒绝未支持的值；工具不改该端图片、工具开关和派生 reasoning 对象。页面导航返回 queued，只表示已提交意图。普通写入继续复用原配置接口、保留原密钥，删除维持一次本机集中确认。

本轮真实验收复用已登录的小分队模型和既有共享 Server；Hub 配置、凭据表单测试值和 VS Code 原生文件全部放在 `target/` 下临时目录，执行前逐项约束工具目标，不改用户原生客户端。已有登录 transport 可能正常续期会话。实际对话测试与原生屏幕夹具分别记录，不把合成业务页当成用户真实页面通过；结果和新包身份见 [V23 交付](../releases/v1.0.23.md)。本轮不安装运行包、不运行 MSI、不测试计费。

打包前追加两项界面要求：WebStorm / VS Code 的客户端页面和可选入口隐藏，保留已有后台配置与历史记录，见 [客户端适配](desktop-client-adapters.md)；MiniMax 加入大模型厂商表单，见 [厂商预设](desktop-capability-management.md)。另补齐已登录小分队用户的密钥流水线：可先读取脱敏 API 密钥列表选择已有项，也可按明确要求创建，再指定 keyId 准备导入。Hub 保存返回的真实地址、协议及模型，并通过本机凭据引用配置渠道和指定客户端；模型不接触明文密钥或一次性票据，详见 [账户专题](tiancai-squad-account.md)。用户密钥后续模型调用按用户原站点规则，不能与管理员承担的搭档对话费用混同。

最终57项定向回归与GUI测试目标编译通过。追加密钥流程已用真实 Server/管理员模型完成3轮、8次工具调用：创建临时密钥、从列表搜索选定、准备导入、保存渠道和临时ZCode指定模型，再回读并核对原生文件；测试密钥已撤销。原7轮配置/删除/停止验收和原生屏幕夹具保持各自输入归属，不重复执行。可直接让助手“列出我的 API 密钥”，选定后再要求“把这把密钥的某模型配置到某客户端”；多项有歧义时才补问目标。

## V1.0.22 对话调用与 Hub 内浮层

用户实测新版 Server 返回 `invalid request:readonly access is no longer supported use permissionprofile for restricted reads`，旧实现每个 `turn/start` 都附带已退休的 `readOnly.access`，导致任何文本都失败。修复改为复用 Hub 现有 Codex 的请求构造，后续回合继承已建立的会话配置，不再反复发送权限覆盖。临时配置与模型能力目录同样复用现有 Codex 处理，助手仅保留自身工具范围及小分队返回的模型能力。

共用入口为 `local_assistance::codex_configuration` 的纯 TOML 基础、`remote_control_backend::ThreadStartOptions::to_params` 与 `turn_start_params`、`ai_gateway::catalog::configured_models_response`；原天工协助和远控消费者保留原参数行为。模型目录沿 Hub 的 GPT 目录及动态模型匹配，再覆盖管理员能力和助手工具范围，不为目录读取计算额外 etag/hash。启动继续使用已兼容的 `app-server` stdio 入口。

Server RPC 失败、错误通知及回合终态保留失败阶段与可用的 RPC/HTTP 状态，展示固定中文原因；不会回显上游私有正文或凭据，也不主动重放请求。尚无回复正文的失败消息会填入原因，已有部分回复保留。压缩及真实工具调用的验证边界继续按各版记录，不以合成协议证明真实服务通过。

模型 ID、API、能力及鉴权继续来自天才小分队配置 GET，管理员费用约定保持；复用 Codex 流程不代表改用用户普通渠道或读取个人 Codex 配置。共享 Server、确认后安装、临时会话清理与账号切换边界沿用。

对话改为 Shell 内容区的普通子 Panel，始终属于 Hub，受主窗口裁剪；不创建独立系统窗口。右下角只有对话图标，框内没有产品标题。消息分侧排列，文字可选择复制，输出增量更新保留阅读位置；底部固定输入与发送/停止，顶栏提供状态、清空和收起。收起继续当前对话，重新展开定位在内容区右下，尺寸随可用区域收敛。键盘操作、主题和真实缩放效果仍需用户验收，视觉规范见 [桌面规范](../development/desktop-visual-system.md)。

## V1.0.21 运行端来源与准备提示修正

用户反馈已安装并启动过 ChatGPT，天才搭档仍返回 HTTP 409“Codex CLI 程序不存在”，缺少运行端时也没有出现安装询问。本轮随 [V21 唯一测试交付](../releases/v1.0.21.md) 修正，构建和用户验收状态以交付记录为准。

准备运行包时，旧版把天工协助保存的来源路径视为必需文件；Store 升级删除旧目录后直接报错，无法继续发现新版内置程序。现在已失效的来源偏好会在本人确认准备后重新查找，本机存在兼容程序则复制为共享品牌包；现存但不兼容的明确选择继续说明缺少的组件，不静默替换用户选择。来源位置错误使用“天才搭档 Server”提示，官方程序名称保留在来源诊断中。

Windows 自动发现读取当前用户登记的官方 Codex/ChatGPT 安装根，兼容非默认安装卷和数字版本排序；登记不可用时才查看已知 WindowsApps 目录。补齐 npm 新 `vendor/<target>/bin/codex.exe` 与旧 `codex/codex.exe` 布局，并保留桌面内置程序、旧运行缓存和必要配套组件核对。旧 npm 的相邻 `path/rg.exe` 使用完整路径，不再因自己生成的 `..` 路径被拒绝。状态轮询不执行这些来源扫描，也不运行程序探针或文件哈希。

启用或重新进入已启用但未就绪的模块时提供一次准备确认，取消保持未就绪且不下载、不复制、不启动；用户之后可主动选择“准备天才搭档 Server”。刷新状态不反复询问。界面在消费启用结果后释放忙状态，再处理待提醒意图，避免原异步竞态吞掉确认框；状态读取失败则重读实际保存状态，兼容顶层与嵌套就绪字段。天才搭档与天工协助继续共用一份长期运行包，取消、停用和临时内容清理均不删除已安装共享包。真实首次准备、品牌程序初始化与管理员服务仍由用户验收。

维护范围：`src/local_assistance/{binary,runtime}.rs`，界面状态流位于 `src/gui/assistant.rs`。新增定向夹具覆盖失效来源回退、现存不兼容来源、现代 npm 与登记 Store 布局、旧搜索组件路径；确认前不发现、不安装的回归保留。Windows GUI 编译及来源发现 5、共享准备 7、安装提醒纯状态 3 项定向用例已由管理会话统一核对通过，纳入 V21 唯一新包，不与历史 V18 结果混计。真实来源复用、下载与对话仍待用户验收。

## 当前行为

左侧独立“天才搭档”模块集中管理启用、运行端、登录、模型服务和临时清理，默认关闭。启用且共享“天才搭档 Server”已准备后显示右下角对话图标，Hub 内浮层支持发送、停止、收起和清空；小分队已登录且管理员模型配置有效后才创建后台、允许发送。缺少运行端时界面提供用户确认后的准备入口，复用 [本机协助](tiangong-local-assistance.md) 的同一共享运行包；不会自行安装系统 Codex、修改用户 PATH 或个人 Codex 配置。两功能均停用且后台退出后可由用户手动移除 Hub 自管运行包。

助手通过官方 Codex app-server stdio、`experimentalApi` 动态工具协议工作。一次 Hub 运行仅保留当前账户的一个 app-server thread，多轮消息继续该 thread；收起界面不停止任务、不丢失当前对话。停止发送 `turn/interrupt`，撤销待确认删除/凭据询问并关闭本轮上游流；已发生的配置修改保留。清空先关闭整棵后台进程树，再清临时目录、内存消息与临时凭据，下次发送才新建会话。没有闲置五分钟自动清理。

用户退出或切换小分队账户时中断旧会话、清空内存和临时凭据，界面未发送草稿随 `conversationId` 变化清除。工具分派、确认后写入及结果返回再次核对原账户代次和会话 epoch，防止旧对话继续修改。Hub 退出同样停止树并清理；启动时仅回收该功能的 UUID 临时会话目录。清理失败保留后台归属并显示原因，暂停新消息，用户可点击清空重试。Windows 使用 Job Object 随 Hub 句柄关闭结束树；macOS 使用独立进程组，异常遗留只在 PID、启动身份、运行端绝对路径、原 Hub 已退出同时匹配时结束原组。无法确认归属则保留并记录原因。

临时 `CODEX_HOME` 和 workdir 位于本机 feature 状态目录 `assistant/runs/<UUID>/home` 与 `work`，不读取个人聊天、历史、插件或项目配置，也不跨 Hub 重启恢复对话。永久共享运行包位于 `companion-server/`，与临时会话分别管理。

## 模型与费用

只使用小分队管理员配置的模型，接口见 [配置契约](../contracts/assistant-server.md)。登录后只从一个 GET 取得开关、名称、普通 API 地址/助手专用凭据、协议/流式偏好及模型参数，Hub 直接连接已有普通模型 API；不新增助手专用推理或压缩 POST。Hub 不使用用户普通渠道、不查看用户余额，也不把登录 JWT 或模型密钥给 app-server。运行端仅取得随机本机会话 token。

模型参数为 ID/显示名、上下文窗口、可用/默认推理强度和推理支持；不再要求远端工具、压缩或费用声明对象。协议支持 `responses` 和 `chat_completions`，使用 Hub 已有转换器把 Chat / 非流式结果适配给 Server。Chat SSE 按完整行解码，保留跨网络分片的中文和工具参数；取消、上游错误及缺少结束信号的提前断流结束请求，不补造完成事件。上下文写入 app-server 模型目录，压缩阈值为 80%，显式使用 Server 本机摘要（`remote_compaction="unsupported"`）；摘要继续请求同一普通 API，不依赖独立压缩接口。配置每 60 秒更新；临时读取失败保留已知配置与对话，成功确认管理员关闭或模型/连接变化时隔离旧会话。关闭功能不访问远端配置。

模型实际调用时，请求日志来源为“天才搭档”，渠道为“天才搭档管理员服务”，模型为管理员 ID，usage 如实记录；用户成本记为 `0`。管理员承担费用及用户零余额可用，由返回凭据对应的现有服务额度规则实现，客户端说明不替代真实服务计费。关闭请求日志时仍有短时实际活动证据；不因仅打开窗口、读取目录或待命而伪造模型请求。模型凭据仅在本次内存中保留，不进入助手对话、工具内容、界面状态、日志或临时 Server 配置。

## 工具与真人操作

模型只获得 Hub 的受控配置工具：读取渠道/模型/客户端能力、添加或修改普通渠道、添加模型与别名、把来源模型配置到已发现客户端、修改支持的客户端参数、明确列出的批量删除、打开 Hub 相关页面、读取帮助、申请本机凭据表单。读取结果列出对应客户端支持的参数字段；配置到 Codex 时返回实际生成的独立模型别名，后续操作沿用该身份。保存沿现有配置 API，保留独立客户端副本、已有密钥和配置后改保护。

当前小分队密钥提供 `hub_squad_list_api_keys`、`hub_squad_key_options`、`hub_squad_create_api_key` 与 `hub_squad_prepare_api_key` 四项工具。只按当前账户已有权限操作，创建结果未知时沿原待确认写入机制核对，不能自动重复创建。准备导入复用站点原票据及模型目录，返回 reference / mask / settings；随后用原渠道保存和客户端配置工具完成。用户可在任一步停止或只要求读取，工具不代替用户修改已有站点密钥、组织、账户资料或支付。站点不支持导入、密钥没有绑定可导入分组、模型目录失败等原因按实际结果说明，不能编造可用模型。

没有 shell、任意文件操作、web、MCP、其他代理或任意配置路径写入。运行端使用禁用 shell 的模型目录、只读沙箱与关闭原生功能的配置；模型代理再仅保留 Hub 动态函数，所有非当前 thread/turn 的回调及其他 server request 均拒绝。此限制不影响用户自己的 Codex/天工客户端能力。

删除集中弹出一次本机批量确认，等待真人批准后执行，模型不能代替用户作决定。密钥通过界面密码表单输入，只向模型返回本次会话引用与掩码；取消表单结束此次工具等待，清空/退出/切号清除引用。普通停止撤销等待和导航，已录入的临时凭据可继续本次对话。聊天中不应发送明文密钥。

## 本机 API 与维护入口

`/api/desktop/assistant/` 提供 `GET status` 和 `POST settings {enabled}`、`send {text}`、`stop {}`、`clear {}`，另有工具路由 `confirm`、`credential`、`navigation/ack`。桌面请求需无网页 Origin 且 `x-tiancai-desktop: 1`。状态返回开关、运行端检查、登录、管理员模型、运行状态、内存消息、待删除/凭据/导航，`conversationId` 仅为本次内存会话身份，`cleanupPending` 表示需要重试清理。

开关只写本机 `assistant/settings.json` 的 `enabled`，默认 `false`。不改变产品版本、用户运行中的客户端配置、安装包关联或已交付包。停用可保留运行包供本机协助共用；卸载共享 Server 需先停用两个功能且确认后台已退出，不能删用户系统 CLI。

关键源码：`src/assistant/{mod,settings,model,worker,proxy,telemetry,web,tools}.rs`，账户 transport 位于 `src/desktop/squad.rs`；可信来源/实际活动分别在 `src/desktop/request_source.rs`、`activity.rs`；顶层 daemon、HTTP 和 GUI 接线由管理会话集成。共享运行端见 `src/local_assistance/{runtime,brand,process}.rs`。
