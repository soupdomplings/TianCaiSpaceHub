# 已重建部分 Codex 项目时，补回其余卡片和会话

适用于 V1.0.40 起的 Hub 本机 AI Gateway 身份。历史已经可读，但桌面侧栏比原来少项目，或已手动建回部分项目却没有会话。若整个历史库都找不到，先参照[历史位置恢复](codex-history-recovery.md)。

## V1.0.61 · 历史库有项目，侧栏却为空

在「检查与修复」选择「删除配置后，项目或分组会话不见了」，点击「检查所选问题」。“11 个项目、39 条已归组”统计整份历史库。下方分别给出可补回的卡片和需要重新归类的会话数。如果 39 条都已关联正确项目，修复只需补回卡片，因此可归类会话数可以为 0。

- 当前账号的本机桌面对话已有原生项目 ID，工作目录等于唯一项目根或位于其子目录时，可以补回缺失卡片。未分组的会话仍按原规则精确匹配项目根。
- 两项账号字段都缺失的已分组旧会话，需要原项目 ID、匹配目录和本机桌面来源。侧栏为空且同目录桌面备份能核对同一账号、项目 ID 和原根时，可以补回卡片。缺少这份佐证时，检查页给出可选项目数。确认这些旧记录属于自己后，勾选「包含我确认属于自己的旧会话（未记录账号）」再检查。
- 检查结果会指出账号冲突、ChatGPT 云端项目、目录问题或无法识别的库结构。涉及原账号的项目请在该账号中打开。有多份同目录项目时，在 Codex 打开原目录并手动移入一条确认属于该项目的会话，再完全退出并检查。仍无可核实目标时，应用按钮保持灰色。

已静态核对 Windows Codex 26.1117.3838.0 安装资源的项目读写和账号迁移逻辑。桌面迁移后优先使用 `.codex-global-state.sqlite`，旧版读取同目录 JSON。Hub 按当前存储检查，SQLite 支持版本 1 的 `settings(scope,key,value)`，核对活动账号与当前 Hub 身份后在事务中更新本次涉及的项目键。无法核对 SQLite 时请用原账号正常打开并退出 Codex，再检查。证据来源包括同目录 `.codex-global-state.json.bak` 的活动账户卡片、原生项目和会话关联。原项目仅有本地外观元数据时可参与匹配。带 ChatGPT 关联的项目交给原账号恢复。

撤销沿「备份与撤销」执行，并检查原账号、历史库、侧栏存储和后来的手动修改。JSON 继续沿用原回执格式，SQLite 项目修复使用第 6 版回执，请在本版或兼容版本完成撤销。合成回归覆盖 11 个项目、39 条已有分组会话、遗留 JSON、SQLite 写入与撤销、账号、备份及目录冲突。实机验收保留原现场，在安装本批后重新检查，再打开一条原会话核对。[项目证据](../../src/codex_app_config/project_membership.rs) · [侧栏存储](../../src/codex_app_config/sidebar_store.rs) · [V1.0.61 交付记录](../releases/v1.0.61.md)

## 检查和恢复

**V1.0.41 误点过“恢复所选记录”的用户**：该按钮会撤销上次修复。V1.0.42 无需先还原备份：直接检查当前项目，核对自动补回数量，勾选想放回重建项目的对话，再在主窗口应用项目修复。已撤销的卡片和仍可核实的原会话会重新纳入同一批。只有想退回修复前的状态时才去单独的撤销入口。未记录账号的旧会话仍需按本人情况显式选择。详见 [V1.0.42](../releases/v1.0.42.md)。

1. 保留现有项目与会话，完全退出 ChatGPT / Codex。在 Hub 打开「ChatGPT / Codex → 接入设置 → 检查与修复」，选择「删除配置后，项目或分组会话不见了」。
2. 先检查。数据库项目行数可以大于应显示的卡片数：手动重建项目可能产生同一目录的新旧两行。看检查结果里的**可补回项目数、可归类会话数**。修复会把缺失卡片加到已有卡片之后。已有手动归属不覆盖。
3. 如有本人早期使用 Hub 的旧会话未记录账号，可先勾选「同时归类未记录账号的旧会话」再检查，**再**选择要归回的独立会话。改变旧会话选项会清除上一份预览和勾选。此项默认关闭；只有明确标为桌面用户对话、未归档、没有现有归属，且精确对应已核实项目目录的旧记录才会计入。共享电脑上无法确认这些旧记录属于自己时，保持关闭。V1.0.42 在底部显示本次项目数、会话总数与勾选数，主按钮为「应用项目修复」。
4. 修复完成后打开桌面客户端，查看项目卡片并打开其中一条原会话。再次检查不应重复补回同一批。如果检查先切回了另一份历史库，以新库的检查结果为准。

## 匹配和撤销

- 同一目录已有一张确认过的项目卡时，未归类的当前用户对话可以补到该卡；重新连接仍指向旧项目的历史，须有同根新旧项目及已归类会话的证据。其他账号、子任务、已归档、远程归属、目录不匹配或目标不唯一的记录不按名称猜测。
- V1.0.40 会保留所有「无项目」标记。从 V1.0.41 起，检查后如果有会话的工作目录恰好是手动重建的项目目录，界面会列出可选的**会话标题 → 项目**。只有同目录有可核实的新旧项目、侧栏目标唯一、会话属于当前本机身份、没有其他归属时才会列出。目录相同不能证明原先一定分在该组，所以默认不勾选。勾选需要的会话再点「修复所选问题」；不必勾选“未记录账号的旧会话”。可与其他常规修复同时执行。
- 此操作复用原会话 ID，只移除所选会话的「无项目」标记，并更新桌面和历史库的项目关联。撤销后可恢复该标记；未选的独立会话及后来新增的其他标记保留。候选以桌面名称优先显示，标题仅用于当前本机检查窗口，不写入回执或普通初始化响应。验收见 [V1.0.41](../releases/v1.0.41.md)。
- 检查只读；修复更新本机历史库的项目关联和桌面侧栏状态，不重新创建会话。修复后需要撤销时，完全退出客户端，在检查与修复中还原本次项目修复。发生冲突时不覆盖后来的手动整理。
- 实现入口：`src/codex_app_config/project_membership.rs`（归属证据）、`src/codex_app_config/sidebar_projects.rs`（侧栏、归属与撤销）、`src/codex_repair_center.rs` 和 `src/gui/startup_repair.rs`（检查与选项）。验证与平台状态见 [V1.0.40](../releases/v1.0.40.md)。
