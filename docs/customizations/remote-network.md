# 远程连接与个人设备网络

维护日期：2026-11-17。本轮基于 `main/dc9f288` 将 EasyTier v2.6.4 改为 Hub 内的 Rust 源码组件，不再下载或启动外部组网程序。网络配置、设备配对、TLS 和会话网关继续复用；本轮库／完整 GUI 编译及 91 项定向离线测试已通过，真实双机组网、桌面会话续聊及 macOS 实机仍待用户验收。构建与唯一包见[V34 交付](../releases/v1.0.34.md)，此前 V1.0.32 下载组件方案的包身份和验证仅归属[当时交付](../releases/v1.0.32.md)。会话协议见 [协作契约](../development/remote-session-contract.md)，总体功能及联合验证见[远程连接](remote-connection.md)。

## 当前使用流程

“远程连接”默认关闭。两台电脑都运行 Hub，目标端的 Codex／天工 Work 客户端须已启动并接入 Hub。每台 Hub 同时保存一个个人网络，设备可以互相访问；浏览器只连接访问端 Hub 的本机入口。

1. 在两台 Hub 启用远程连接。组网能力随 Hub 编译分发，直接可用，没有单独安装、准备或下载步骤；未启用时不启动组网运行域或网关。
2. 在一台 Hub 创建网络并复制连接码，另一台粘贴加入。已在网络中再次创建仅生成新连接码，保留已有网络。
3. 目标 Hub 显示设备名称和配对请求，确认一次后双方持久保存设备授权。未配对的组网设备不能使用会话接口。连接码有效期十分钟，每次邀请只能建立一项新的配对请求。
4. 选择已配对设备打开网页。本地入口兑换为 HttpOnly、SameSite=Strict 的会话 Cookie，并移除 URL 中的临时入口凭据；目标设备令牌、网络口令、原客户端令牌及模型密钥不交给网页。
5. 撤销设备授权后，目标请求及仍在等待新内容的事件流一并断开。重新配对会更换设备令牌，并结束旧令牌对应的流。撤销远程访问不自动取消目标端已经开始的模型任务。

设备名称保存不重启网络。启用状态、节点地址或设备证书变化，以及运行域已经退出时，才重新建立后台连接。加入时遇到虚拟 IPv4 冲突，自动更换本机虚拟地址和证书，再重新配对。持久凭据被外部删除时不静默重新授权：显式启用／创建／加入时可以重建本机证书并清除旧配对；创建网络发现网络口令缺失时建立新的个人网络，其他设备需要重新加入。

最小化和关闭到托盘保持网络；真正退出 Hub 时，关闭本机网页网关、HTTPS 会话服务和内置 EasyTier 运行域，不关闭用户的原客户端。退出不会删除网络设置、配对记录、会话附件或产物。本轮运行配置仅保存在内存，不再创建含网络口令的临时 TOML 或外部程序 PID 文件；升级时仍回收旧版本带归属标记且所属进程已退出的残留目录，未知或仍在使用的目录保留。

## 组件、节点与真实状态

固定基于官方 EasyTier **v2.6.4** 源码集成：`vendor/easytier/easytier/` 保留运行库，配套 RPC 代码生成与 smoltcp 使用仓库内的源码；具体裁剪和来源由 vendor 改动说明记录。Hub 不启动 `easytier-core`／`easytier-cli`，也不向用户要求单独安装组网程序、Node.js、TUN 驱动或授予管理员权限。运行模式保留 `no_tun + use_smoltcp + socks5`、AES-GCM、TCP／UDP 穿透及 ACL，只承载本功能的会话访问。

| 运行边界 | 当前实现 |
| --- | --- |
| 启动 | 独立 owner 线程建立专用 Tokio runtime，内存 `TomlConfigLoader` → `Instance::new` → `run().await`；不经过 launcher 或外部命令 |
| 就绪 | `run` 完成本机监听和 SOCKS 绑定后通知 Hub；启动失败或超时返回可读错误 |
| 状态 | 每秒从 `PeerManager` 的活连接及原生路由采样，Hub 读取内存快照，不另起 CLI 或管理 RPC 端口 |
| 停止 | 发送停止信号、释放 Instance 资源并结束专用 runtime，等待 owner 线程退出；启动等待被取消也会通知后台退出 |
| 无 TUN | 不创建系统网卡；该模式不启动 RAW ICMP 代理，避免不必要的管理员权限和不可随 runtime 回收的阻塞线程 |

源码来自 [官方 v2.6.4 标签](https://github.com/EasyTier/EasyTier/tree/v2.6.4)，其 [LICENSE](https://github.com/EasyTier/EasyTier/blob/v2.6.4/LICENSE) 为 **LGPL-3.0**；原许可、来源和 Hub 所作修改保留在 vendor 与第三方声明中。网页页脚的站点许可不作为程序许可；历史下载包的资产映射不再用于本轮运行。

默认节点为 `tcp://us01.225284.xyz:11010`，来自运营者在 [EasyTier 官方组织讨论 #1848](https://github.com/orgs/EasyTier/discussions/1848) 公布的社区节点。用户可修改节点；清空设置恢复这个默认地址。旧 `public.easytier.cn` 在本轮开发环境无法解析，不再作为默认值。社区节点由第三方运营，持续可用性需要实际网络验证，Hub 未部署自己的公共中继。

EasyTier 优先尝试设备直连，失败时使用可达节点中继。`PeerManager::has_directly_connected_conn` 标识真实直连设备，其他可达路由显示为中继；本机、无地址、非本功能 `10.203.0.0/16` 地址及不可达路由不作为设备展示。公共中继已有实际连接但暂时没有其他 Hub 设备时，网络可以显示已连接、设备列表仍为空；仅创建网络或启动运行域不会冒充已连通。

状态区分三层：`runtimeReady`／`runtimeEmbedded` 表示当前 Windows 或 macOS 构建具备内置能力，`networkReady` 表示运行域和网关已启动，`connected` 表示 PeerManager 存在真实活连接。`runtimeInstalled` 仅兼容记录旧 Hub 下载副本，不能用于本轮就绪判定。设备 `online` 依据已发现虚拟路由，`connectionType` 为 `local`／`direct`／`relay`／`pairing`。未连通或运行域退出时保留可读原因，用户可以检查网络、更换节点或停用后重启；平台可用状态不等于对应平台实机验收通过。

## 隔离链路与本机数据

固定访问链路：访问端浏览器 → 访问端本地 HTTP 网关 → EasyTier 用户态连接 → 目标端 HTTPS 3861 → 独立会话接口。

- 目标 HTTPS 服务仅承载设备公开身份、配对接口和 `/api/remote/v1`。现有 Hub 管理 Router、组件管理接口及通用系统接口不合入该服务。
- EasyTier 入站和转发两条 ACL 链均默认拒绝，只允许目的为本机虚拟 IPv4 的 TCP **3861**。两条链同时限制，是因为 `no_tun` 可将虚拟地址转换成本机回环，不能仅依靠服务绑定地址隔离其他端口。
- 不启动 EasyTier 管理 RPC。SOCKS 仅监听随机回环端口，不通过远程 ACL 放行；禁用陌生网络中继。内存配置不经过 CLI／`ET_*` 环境参数合并。
- 网络口令只通过内存传给运行库。Instance 初始化不打印完整配置；解析错误也不向用户或日志带回包含口令的 TOML 全文。
- 配对时根据连接码中的证书固定校验目标 HTTPS；不关闭证书验证。会话请求还校验每对设备独立的访问令牌。
- 本地网关检查 Host、Origin 和跨站来源。网页用 `X-Hub-Target` 选择设备，网关持有并补入目标令牌。SSE、上传和下载流式转发，保留会话文件的 sandbox CSP。
- 附件／产物下载和预览也必须通过带 `X-Hub-Target` 的 fetch 后使用 Blob，不能直接把相对 URL 作为 `img.src`／下载链接而漏掉目标设备。

所有数据放在 `desktop::state_root(config_path)/remote-network/`，即配置路径扩展为 `.desktop` 后的独立子目录：

| 位置 | 内容与保留策略 |
| --- | --- |
| `network.json` | 设备公开身份、虚拟 IP、网络名称、节点地址、启用状态及已配对设备证书；长期保留 |
| `protected/` | 平台凭据存储：网络口令、本机 TLS 私钥、每设备令牌；不进入状态响应或普通日志 |
| `runtime/easytier-<platform>-v2.6.4/` | 仅旧版本可能留下的 Hub 自管程序、来源、许可及标记；本轮不创建、不读取为运行端，只允许显式移除合法归属副本 |
| `active/hub-*/` | 仅旧版本运行目录；本轮不创建，只按所有权／原进程状态回收既有残留 |
| 内存 | 本次 EasyTier 配置、运行实例与 peer 快照；停用或真正退出时随专用运行域释放 |

远程会话附件由独立会话服务管理，不在搭档临时内容目录。网页不复制保存一套聊天历史。

## 管理接口与维护定位

本机既有受信管理入口增加 `/api/remote-network`，远程侧不开放此入口：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /status` | 启用、组件、真实连接状态、设备、待确认配对和可读错误；无私有凭据 |
| `POST /settings` | `{enabled,deviceName?,relayUrl?}`；保存设置并按需启动内置运行域，不下载组件 |
| `POST /prepare` | 仅为旧本机调用保留；须已启用，检查内置能力并按需启动，无下载、安装或确认流程 |
| `POST /uninstall` | 仅兼容清理旧包；须先停用，只删除版本／平台／归属标记匹配的旧 Hub 下载副本，不会卸载内置能力 |
| `POST /create` | 创建个人网络或为当前网络生成新的连接码，响应包含 `code` |
| `POST /join` | `{code}`；加入后由后台重试网络配对握手，不重发会话消息 |
| `POST /pair/approve`、`/pair/reject` | `{requestId}`；每项请求仅处理一次 |
| `POST /revoke` | `{deviceId}`；持久撤销并通知正在等待内容的流 |
| `POST /open` | `{deviceId?}`；返回带临时入口凭据的本机网页 URL |

主要代码：`src/remote_network/mod.rs` 管理设置／生命周期／配对；`runtime.rs` 托管内置 Instance、原生 peer 快照、ACL 配置及旧包兼容清理；`pairing.rs` 连接码；`transport.rs` 独立 HTTPS、浏览器鉴权和流代理。`startup`／`shutdown` 接入 Hub 生命周期，网页资源由 `remote_frontend` 提供，会话 Router 由 `remote_sessions` 提供。

## 停用、移除与验证边界

停用结束本模块运行域和网关，保留网络及配对配置；再次启用直接使用随 Hub 分发的源码能力。内置运行库随 Hub 更新，不提供单独卸载。旧 Hub 下载副本可在停用后通过兼容管理接口清理；无正确所有权标记的外部目录不删除。回滚到旧下载组件方案须使用对应旧版 Hub，不能将本轮内存状态或 `runtimeReady` 含义当作旧包已经安装。

2026-11-17 本轮新增／调整离线用例：内置就绪和兼容准备不落运行文件、TomlConfigLoader 实际解析无 TUN／AES-GCM／ACL 配置、原生 Route 与直连信息映射、断线不保留虚假在线设备、公共中继连接和设备列表独立、停止等待 owner 线程及启动句柄丢弃取消后台。生命周期用合成线程与信号验证，不启动 Instance、监听端口或组网。本模块 20 项用例全部通过，计入本批 91 项不同定向回归；网络库、完整 GUI／测试目标和 Windows 依赖树检查通过，依赖树没有 pnet_datalink／WinPcap、驱动或系统服务。结果及包身份见[V34](../releases/v1.0.34.md)。
