## 范围

Hub 复用已有飞书、微信、企业微信账号的接收与回复通道，通过显式 `/gmclaw` 指令把当前发送者的文字消息交给本机天工 Harness 执行。此流程拥有独立会话和工具审批，不接管 Codex remote-control 连接，也不把天工会话冒充 Codex 线程。

首版支持文字、最终答复、当前轮工具批准或拒绝。Telegram 沿用原流程；Codex 的完整会话卡片、会话历史选择、附件、逐字进度展示和主动取消未扩展到天工。平台卡片回调及欢迎事件继续交给原流程。第二阶段不包含 MCP 连接的新增、修改、删除或启停；天工已安装的工具由 Harness 执行，其中被天工策略标记为需要确认的调用按本节审批。

## 本机授权与配置

天工 Harness 默认地址为 `http://127.0.0.1:7861`，Hub 请求 `POST /v2/chat`。连接地址仅接受本机回环 HTTP/HTTPS 根地址或 `/v2/chat` 地址；`localhost` 固定解析到 `127.0.0.1`。请求使用 `Authorization: Bearer ...`，不经过系统代理、不跟随重定向；地址不能携带账号、查询参数或片段。

1. 由用户自行设置天工启动环境变量 `GMCLAW_AUTH_TOKEN`，值为用户掌握的本地连接令牌。环境变量对随后从该环境启动的天工进程生效；若天工已经运行，需要先让其从包含该变量的环境启动，再配置外部消息连接。
2. 在 Hub「天工 Claw 接入」的外部消息配置中填写相同 Token、Harness 地址、已存在的绝对工作目录，并启用外部消息接入。Hub 不自动发现、读取进程内存中的随机 token，也不修改天工安装资源或自动重启天工。
3. 可填写执行模型 ID；这是天工数据库的 `model_id`，例如某个 Hub 条目的 `tiancaispacehub-<entryId>`，不是上游模型名或别名。留空时不发送 `model_id`，由天工选择当前默认模型。
4. 先按 Hub 原流程配置并启用飞书、微信或企业微信账号，启动其消息通道。然后由允许的发送者在该 IM 会话中发送 `/gmclaw`，再发送文字开始执行。

Windows 首次配置授权时，可先退出天工，再在 PowerShell 中使用占位示例手动启动；将两处占位值替换为自己的安装路径与令牌，不要把实际令牌发到聊天或提交仓库：

```powershell
$env:GMCLAW_AUTH_TOKEN = '<与 Hub 配置相同的本地连接令牌>'
Start-Process -FilePath '<安装路径>\tiangong-desktop.exe'
```

该示例只影响当前 PowerShell 及其随后启动的子进程。以后从其他环境启动天工时，也需要由用户提供相同的环境变量。Hub 不提供随机运行 token 的发现接口。

模型保存后无需强制重启的用户反馈属于 [模型配置流程](gmclaw.md#使用与多模型管理)。外部消息接入的环境变量用于天工进程启动时授权，不会自动由模型保存步骤写入。

Hub 将下列配置保存在自身 TOML 中；Token 属于私密配置，文档和日志不得保存实际值。以下仅为禁用状态的占位示例：

```toml
[gmclawBridge]
enabled = false
endpoint = "http://127.0.0.1:7861"
authToken = ""
projectPath = "D:\\path\\to\\project"
maxSteps = 30
# modelId = "tiancaispacehub-<entryId>"
```

| 字段 | 默认与约束 |
| --- | --- |
| `enabled` | 默认 `false`；停用后不把新文字交给天工 |
| `endpoint` | 默认 `http://127.0.0.1:7861`；仅本机回环地址 |
| `authToken` | 默认空；启用时要求非空 ASCII 值，不含控制字符，最多 8192 字节 |
| `projectPath` | 默认空；启用时必须为本机已存在的绝对目录，不自动创建或解释相对目录 |
| `modelId` | 默认省略；可指定天工模型配置行 ID，最多 256 字节，不含控制字符 |
| `maxSteps` | 默认 `30`，允许 `1–200` |

配置通过现有 `GET/POST /api/config` 保存，使用全量配置 `_revision` 冲突保护。界面后台先重读最新 `AppConfig`，只有桥接字段仍与本页加载值一致时才合并新的桥接字段，再带最新整体版本保存；因此先保存模型或修改其他无关配置不会必然导致桥接保存冲突，桥接本身被改动仍要求刷新。`AppConfig::save` 统一校验启用状态的参数，执行前还会再次校验。保存成功只表示配置持久化，不代表天工已连接成功；第一条实际文字请求才建立 Harness 调用。

## 指令、会话和权限

| 指令 | 行为 |
| --- | --- |
| `/gmclaw` | 切换到天工，随后普通文字交给当前天工会话 |
| `/gmclaw new` | 建立新的天工会话；不删除旧桌面记录，不取消旧工具执行 |
| `/gmclaw status` | 查看当前模式、待审批或执行状态未知的提示 |
| `/gmclaw help` | 显示帮助 |
| `/gmclaw off` | 返回原 Codex 文字流程并清除该绑定的待审批；不声称取消已提交任务 |
| `/gmclaw approve <确认码>` | 仅批准当前会话最近一轮完整列出的全部工具调用 |
| `/gmclaw reject <确认码>` | 拒绝该轮工具调用 |

会话身份包括平台、Hub 账号、会话 ID 和发送者 ID。群聊中不同发送者各自绑定，审批码也只能由对应发送者在对应会话使用；这些回复仍在原 IM 会话发送，群内可见性由平台决定。传给 Harness 的 `user_id` 与 `project.id` 使用同一身份组合派生的 `hub-im-<hash>`，避免直接复用桌面本地用户的记忆身份。

所有天工请求仍使用用户明确选择并授权的同一个 `projectPath`。会话与记忆身份隔离不等于工作目录或文件权限隔离；首版不为不同发送者建立独立文件系统沙箱。天工自身策略可能直接执行项目目录内读写、部分低风险命令或未声明需要审批的工具，因此不能依赖 IM 审批逐次拦截所有文件或工具操作。

进入天工前，原 IM 账号的允许名单与飞书群提及规则继续生效；天工分派还会按当前配置核对账号启用状态、发送者与会话权限，并在等待队列结束后及发送结果前再次检查。允许名单为空延续原平台配置的“允许所有”语义。当前 Codex 任务或审批尚未结束时，不允许切入天工。

会话和待审批保存在 Hub 内存，最多 128 个绑定；不用的会话可发送 `/gmclaw off`。Hub 重启不会自动恢复这些绑定或未完成审批。连接配置改变后，已有绑定要求 `/gmclaw new`，旧审批不能用于新连接。非空消息 ID 按发送者身份在内存中去重，保留最近 512 条；它不是跨进程重启的持久去重账本。

## 执行、事件与审批

执行器按天工 1.1.1 的 `prefix|JSON` 行事件读取 `text`、`confirm` 和 `over`，处理跨网络分块和 UTF-8 边界；这不是 Codex remote-control JSON-RPC，也不是普通 `data:` SSE。Hub 当前先发送等待提示，随后发送完整答复或审批消息；不会把任意工具进度载荷直接公开到 IM。

每次请求显式使用 `tool_execution_mode=confirm`，Hub 不自动批准工具。是否需要审批由天工自身工具策略决定，`confirm` 不表示每个工具都必须确认；只有 Harness 返回待确认事件时才进入 IM 审批。收到该事件后，Hub 展示工具名和完整 JSON 参数，生成 12 位确认码，15 分钟内有效。一次最多展示 16 个工具、合计 24 KiB 的审批说明；超过展示边界就拒绝在消息中批准，不截断参数后继续授权。批准和拒绝只包含该轮记录的调用 ID，不提供自动批准全部未来工具、跨发送者审批或逐个工具选择。

首版只支持父会话工具审批。携带 `run_id` 或 `child_session_id` 的子 Agent 审批需要不同的续执行协议，当前拒绝在 IM 中处理并提示回天工桌面确认，不把子 Agent 调用 ID 填入父会话 `confirm_action`。

同一发送者一次只能执行或等待一个请求；全局同时向 Harness 提交一个请求，容量为 1 个执行和最多 32 个等待名额。等待执行槽最多 30 秒，超时消息未提交天工，用户需重新发送。单次执行等待最多 15 分钟，连接超时 5 秒、读取空闲超时 300 秒；排队后还会重新检查配置和审批有效期。单条普通文字最多 128 KiB，过旧消息拒绝执行。

解析器限制单条事件与累计文字为 4 MiB、整体响应为 16 MiB；缺少 `over`、空结束结果、流中断、错误或超限均按失败处理。普通最终答复最多向 IM 发送 16000 个 Unicode 字符，超出时明确提示已截断并到天工桌面查看；工具审批不使用这种截断规则。

Harness 调用不自动重试：网络中断时工具可能已执行。超时、流中断或配置变化后的执行状态会标记为未知，后续消息不会自动重放该任务；用户先在天工确认结果，再使用 `/gmclaw new`。关闭连接、切换模式或新建会话均不证明天工工具已取消，首版没有独立取消能力。

## 回滚与维护定位

停用 `gmclawBridge.enabled` 可停止把新的文字交给天工；在对应会话发送 `/gmclaw off` 返回 Codex 模式。撤回 Token 或修改授权后，需要让两端配置保持一致。模型条目和 IM 桥接是独立配置：关闭桥接不删除模型，模型备份恢复也不回滚桥接 Token 或工作目录。
