## 目标与入口

Hub 左侧「远程连接」连接自己的 Windows／macOS 设备，再由访问端打开浏览器继续目标电脑的 Codex 或天工 Work 原始会话。两端 Hub 及目标客户端均须运行并已接入 Hub；关闭到托盘保留连接，真正退出 Hub 关闭自有网络与网页服务。

首版仅自己的设备、一台 Hub 同时加入一个个人网络。手机、Linux、WorkBuddy、成员权限和通用远程桌面不在本批范围。网页为两种客户端分别提供会话布局，不复制桌面程序私有前端。

## 使用与默认值

1. 在两端进入「远程连接」，打开启用开关。组网能力随 Hub 内置，启用后即可使用，无需另行下载、准备或安装组件。
2. 在目标端创建网络并获取限时连接码，在另一台 Hub 粘贴加入。
3. 在目标 Hub 的「待确认的设备」允许一次。之后记住设备，随时可以撤销。
4. 在访问端选择目标设备并打开会话网页，选择 Codex／天工、项目及原会话续聊。

启用开关默认关闭。组网能力基于 EasyTier 2.6.4 源码内置，不再使用官方独立运行包作为启动前提；保留来源及许可声明。无 TUN 用户态链路只开放远程会话服务。默认公共节点、穿透直连优先，无法直连时中继；用户不需要自备服务器，可以在同页修改节点。没有可用路线时显示连接失败，不将节点在线写成客户端或模型已就绪。

源码位于 `vendor/easytier/easytier/`，由 `src/remote_network/runtime.rs` 在 Hub 进程内的独立 Tokio 运行域管理；相关 `rpc-build` 与 `smoltcp` 采用本地源码依赖。运行时保留无 TUN、smoltcp、SOCKS、TCP／UDP 穿透及双向访问规则，不再启动外部 `core`／`cli` 程序或组件管理 RPC。

停用保留网络与配对记录，并结束本机自管组网及网页服务；真正退出 Hub 时同样结束这些服务，关闭到托盘继续保持连接。内置能力随 Hub 更新，不再提供独立的移除组件按钮，不更改系统已有 EasyTier 程序或其他网络。

状态展示以 `runtimeReady` 为准，支持的平台由后端返回 `runtimeEmbedded=true`。`runtimeInstalled` 仅表示旧外置副本是否存在，不能据此判定内置组网未就绪。旧 `prepare`／`uninstall` 接口仅为兼容保留，新界面不调用；不会再弹出下载确认或自动补装。

## 会话与文件

- 网页、桌面复用原始会话 ID 与原运行端历史；浏览器刷新／关闭不会自动取消任务，重连补事件和历史，不重发输入。
- 同一原会话的忙状态和审批沿用目标运行端，原权限不因远程连接被提升。停止调用真实中断接口，审批回答只发给对应连接及请求。
- 天工既有会话保持原账号／AI Gateway 归属；网页新建仅在确认 AI Gateway 增强工作区仍活动时开放，普通账号不猜测新建归属。
- 上传文件存入目标端独立的远程会话目录，已发送附件和关联产物长期保留，不属于天才搭档临时文件。文件读取限于当前会话的关联记录。
- 访问端浏览器不保存目标设备或模型凭据。访问端 Hub 代理请求、事件流和文件，目标 Hub 使用隔离会话路由，不公开现有管理 API。

## 构建与回滚

开发网页使用 `npm ci`、`npm run build`，构建产物进入 `assets/remote-web/` 并作为运行资源入库。Rust 编译时嵌入资源，用户不需要 Node.js。Windows／macOS 发布工作流均先构建网页，再构建 Rust；本次只修改流程定义，不触发工作流。

关闭启用开关即可撤销本机远程入口；也可逐台撤销设备。回退旧 Hub 前先停用远程连接，旧版忽略独立网络资料，不改变原客户端会话或模型配置。保留已发送文件以免破坏历史引用。
