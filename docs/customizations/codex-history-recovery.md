# Codex 历史会话加载恢复

维护日期：2026-10-29。适用版本：`v0.4.30-9`，关联 TC-006 / TC-007。已实现，Windows 本地测试包由用户验收；具体构建、包身份及验证结果见 [v9 交付](../releases/v0.4.30-9.md)。

## 触发与使用

先完全退出 Codex，再从 Hub **增强启动**。启动时安装内存适配器，点击具体历史会话、实际触发恢复时才等待执行配置；不在启动时遍历、加载全部历史。

本机历史恢复的配置准备返回 `execution-config-loading` 时，沿用 Codex 原有恢复中状态和加载界面，监听原执行配置变化，并以 500 ms 为兜底间隔重读准备结果。等待上限为 15 秒，从首次确认此原因开始计时；后续单次准备读取也受剩余时限限制。配置就绪后由原调用继续恢复，不额外发送聊天、turn/start 或模型请求。计时依赖 renderer 定时器，后台窗口节流或事件循环阻塞可能推迟反馈；它不是网络请求时限。

切换会话或原恢复尝试失效后停止旧等待，检查间隔最多 100 ms；已经发起的配置读取不能强制中断，其迟到结果不会继续恢复。页面请求在切换路由后才失败，或恢复已取消时，也不会再覆盖新会话的错误提示。相同本机会话沿用原 manager 的恢复合并，适配器另合并准备过程及同一路由的重复历史分页请求。每个会话独立，不把其他会话的配置、模型或权限复用过来。

## 分页失败与重试

已适配的历史页面在加载更早内容失败时，即使已显示部分消息，也显示 Codex 原有“无法加载消息 / 重试”提示。点击“重试”会清除当前页错误并实际调用原分页加载器；继续使用原游标、已加载内容和滚动锚点，不通过整页刷新重建历史。重复点击合并到同一次重试，失败后仍可再次点击；不在失败时自动循环拉取全部历史。

15 秒后配置仍不可用，则保留真实 `execution-config-loading` 失败及重试入口，不假造配置就绪。其他读取错误直接沿用真实失败结果，不套用配置等待。原生 transcript 投影状态本身为 `error` 时保留 Codex 原有整页重载按钮路径，该类错误不在本次定向恢复范围；原生时间线的边界分页、缺口重试及锚点补偿继续使用原实现。

## 范围、兼容与配置

- 自动等待仅覆盖增强启动中 `local` host、`view` 来源的历史恢复配置准备；远端、durable、executor、后台 recovery 仍走原流程。Fast/Ultra 可选项未勾选时，历史适配仍独立安装。
- 对用户提供的 Codex `26.1023.51421` 资源，已识别 manager 的恢复产品入口和历史页面。按函数结构、复用变量和唯一匹配核验，不按资源哈希或客户端版本号盲改。布局缺失或歧义时独立跳过，保留原脚本，不阻塞基础增强启动。
- 增强脚本为 v25，模型源码标记仍为 v2，历史源码标记单独为 v1。恢复和分页标记分别记录，历史页面是延迟加载模块，启动时 `retry_adapted=false` 不代表实际访问后仍未适配。
- 不新增用户配置键，不改写本地会话、状态数据库、Statsig 身份或安装 ASAR，不修改原模型、权限、服务档和执行配置的真实性校验。Windows/macOS 共享 CDP 适配，macOS 本轮没有原生构建或验收；不扩展 Linux 支持。

本次诊断确认的直接阻塞是执行配置尚未就绪；同时出现的 Statsig/全局状态 `EBADF` 写入失败，其操作系统根因尚未确认。等待和重试不能保证修复持续的文件写入失败，也不把其他机器反馈的身份错配、`EXDEV` 等错误当作本机已确认原因。

Hub 日志 `model_controls_source_adapted` 增加 `history_resume` / `history_retry`；`history_recovery_optional_status` 分别记录运行时安装、恢复和页面适配状态。等待后成功、超时或取消时，Codex logger 记录 `hub_history_configuration_wait`，只有固定原因及次数，不额外记录会话正文、ID、路径或配置。运行时计数分别为 waiting/recovered/timedOut/canceled；首次即成功或其他失败不会伪装成“等待后恢复”。

## 回滚与验证边界

完全退出 Codex 后普通启动即不加载内存适配；无需恢复 ASAR 或历史数据。需要返回旧 Hub 时使用保留的旧安装包，已有受管配置的恢复仍遵循 [模型专题](../dynamic-codex-models.zh-CN.md) 原规则。本次未改变配置格式与备份格式。

Windows 构建、离线回归及原始资源静态验证记录见 [交付](../releases/v0.4.30-9.md)。用户需验收首次打开多个旧会话、模型栏恢复、向上加载较早消息、部分消息加载失败后的“重试”、快速切换会话及 Fast 显示。持续错误时保留新版本 Hub 诊断与 Codex 日志；不把静态命中、模拟通过或按钮出现当作真实请求档位已验证。
