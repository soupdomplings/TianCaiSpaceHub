## 导入模型的多选与批量接入（2026-11-11）

API 密钥页“导入 Hub”及网页导入共用新的原生导入窗口：来源与渠道名、可搜索的模型复选、实际客户端目标和高级选项分区显示，底部反馈与操作固定可见。模型沿原预览默认全选，可清空或只选搜索结果，搜索不会清除其他选择；客户端默认不选。站点、模型服务地址、协议与更新替换映射收在高级选项，密钥始终遮罩，没有再要求抄写本次已准备的 Key。

可一次勾选 ChatGPT/Codex、WorkBuddy、天工 Work、DeepSeek Harness、ZCode 的真实可用模型目标，不展示隐藏的 IDE 或继承模型的目录。来源渠道只保存一次；仅存渠道默认禁用，选客户端则启用，然后按“目标 × 模型”调用现有复制或原生使用接口。每项取最新配置版本和真实来源路由，Codex 生成独立可见别名；不再仅把来源模型加到全局可见列表。首次 ChatGPT/Codex 接入仍由接入设置初始化，客户端正在进行的旧会话沿原规则读取新配置。

处理过程及逐项结果直接留在当前窗口。部分失败保留成功项，未确认的写入不自动重放，也不重复导入密钥或保存来源；来源保存未确认时不开始客户端配置。此改动只复用已经准备好的 `ImportDraft`，原票据兑换、站点 `Origin`、账号代次和登录鉴权没有增加接口或迁移。天才搭档的密钥工具仍按下节的内存引用流程工作，不改成由模型自动填写这个窗口。

关键代码：`src/gui/external_import.rs`、`src/gui/external_import/batch.rs`，共用 `squad_dialog.rs` 的外观和布局。完整流程、兼容、回滚与检查见 [网页导入专题](../hub-external-import.md#多模型与多客户端一次接入2026-11-11)。本轮已完成定向格式化及差异空白检查，四项合成 API 及隐藏原生布局检查已由管理会话执行通过；未进行真实站点导入、实际客户端加载或 macOS 验收，原 V23 真实密钥工具测试不代表本次多选窗口已经实测。

## 天才搭档选择、创建及导入当前用户密钥（2026-11-11）

天才搭档新增四个受限本机工具，复用当前 Hub 已登录的小分队服务和账号代次，不新增站点接口：

| 工具 | 原接口及结果 |
| --- | --- |
| `hub_squad_list_api_keys` | `GET /keys`，可传 `page`、`pageSize`（默认20，最多100）和名称 `search`；只投影 `keyId`、名称、掩码、状态、分组、额度上限和日期，不把原列表中的明文 Key、用户资料、使用账单或任意嵌套字段交给模型。结果保留分页信息，当前页不冒充全部。 |
| `hub_squad_key_options` | `GET /groups/available`，仅给当前用户可绑定的真实分组ID、名称、平台和状态。用户未指定时唯一可用组可直接选，多组有歧义才询问；`null`仅用于用户明确不指定分组的请求。 |
| `hub_squad_create_api_key` | `POST /keys`，仅当前用户原有权限，参数为名称、可选分组、额度上限和有效天数；沿站点默认值，常规明确授权不额外弹确认。返回 `created`、`keyId` 及脱敏元数据，不返回明文 Key，不修改或撤销已有密钥，不触及余额、组织、充值或支付。超时/5xx沿既有待核对写入记录，不自动重放，应先列表核对。 |
| `hub_squad_prepare_api_key` | 指定 `keyId`，复用 `prepare_import_checked` 的 `POST /keys/:id/external-import`、单次 `POST /external-import/resolve` 和模型目录读取。输出内存 `credentialReference`/掩码及真实协议、基址、模型和别名；票据、登录JWT与上游Key不进入助手上下文。 |

已有密钥由用户选择后准备，新建密钥得到 `keyId` 后走同一准备路径；准备成功只产生内存引用，尚未保存渠道或客户端。助手沿 `hub_save_channel` 保存普通渠道，保留原 `import_source`；需要客户端使用时按用户要求启用来源，再用 `hub_configure_client` 保存指定模型到真实目标，最后回读核对。地址和模型从实际导入结果取得，不按组名或模型名称猜测；不新增原生终端命令或通用账户CRUD。外部服务仍用本机凭据表单，用户无需为了小分队已选密钥再抄一遍Key。

工具始终使用当前 Bridge 内的 `Squad` 和 `TOOL_ACCOUNT`。创建/导入票据在原写锁内核对 `ExpectedAccount`，响应后再核对账号；停止/清空后迟到的准备结果不恢复已清理引用。引用只在本次对话内存中，清空、切号和退出清理；已明确保存到渠道的凭据保留。新建站点密钥是真实持久操作，不随清空对话自动撤销。助手对话由管理员承担费用；用户密钥后续实际调用仍按站点原账务规则，不能将管理员承担对话费解释为所有渠道调用免费。

关键代码：`src/assistant/squad_tools.rs`（定义、白名单投影、创建和准备）、`tools.rs`（凭据引用及原配置工具）、`guide.md`（选择/新建→准备→保存→回读）、`mod.rs`/`proxy.rs`（当前会话受控服务读取），`src/desktop/squad.rs::prepare_import_checked`（原导入合同与账号保护）。无新增持久配置格式或站点改动；回退移除这些助手工具即可，既有密钥和已保存渠道不自动删除。

新增两项合成回环已通过，覆盖密钥列表脱敏、创建后选择与导入、模型目录范围、原生保存及来源保留、清空边界、结果不确定不重放和旧账号不导入。最终GUI测试目标编译及57项定向回归通过；另用真实Server/管理员模型完成3轮、8次工具调用，在已登录账户新建临时密钥、列表搜索选定、导入到隔离Hub渠道，再保存临时ZCode的指定模型并核对原生文件。临时密钥已撤销，无额外凭据表单；不请求该用户密钥的推理接口，不改已有密钥或用户原有客户端。具体结果和唯一测试包见 [V23交付](../releases/v1.0.23.md)；真实安装、实际客户端加载、费用结算和macOS待用户验收。

## 当前入口

顶部账户入口显示用户名和账户余额，点击进入个人资料；未登录先显示登录页。Hub 先只读检查站点的可选浏览器授权接口，兼容版本才提供“在浏览器中登录”。未启用接口时正常提示并将“内置登录”作为主操作，保留重新检查；网络或服务临时失败单独提示可重试。不再把缺少接口显示成网络故障或原始 HTTP/JSON。2026-11-09 匿名 GET 线上 `/api/v1/auth/hub/capabilities` 实际返回 **404**，没有登录真实账号；这不能由仅更新 Hub 变成已支持。内置登录继续使用官网验证码、TOTP、OAuth 及原安全回传。

登录后使用五组原生导航：账户、API 密钥、使用记录、组织与扣费、充值 / 订阅。只从服务端已授权菜单形成各组及子项，不增加组织权限。V1.0.8 按用户要求从 Hub 移除站内工具、我的订单、我的订阅、兑换、组织架构、组织审计、组织账号、邀请返利八项入口；站点即使开启这些功能或授予权限，也不会出现在 Hub。网站本身不改。默认账户显示余额、今日扣费、今日请求、可用密钥和近七天站点扣费曲线；曲线可悬浮查看，缺少数据不填零。个人资料用姓名/邮箱和已命名的状态、提醒、并发、通知邮箱、加入时间展示，不再把 `allowed_groups`、`auth_bindings` 等任意字段列成表格。V1.0.9 移除个人资料的“编辑资料”和“安全设置”入口；“退出登录”仅在个人资料正文下方显示，其他页面和顶部不常驻。退出不删除已导入的模型渠道。

密钥、使用记录、组织等使用各自的中文列和相应操作；使用记录仅列时间、模型、输入用量、输出用量、实际扣费，移除“扣费方式”，不改变站点记录及 Hub 实际请求日志。使用记录显示日期条件，仅确有多页时提供分页。列表列宽随窗口调整，空数据/失败提供对应说明，读取失败暂停写入并能从右上角重试。导航刷新只更新选中样式，不触发用户选择或重复读取；后台回包携带实际读取的页面 ID，菜单权限变化后仍与正文一致。

账户、API 密钥、用量、充值订阅购买和个人资料查看均为 Hub 原生 API 页面。组织与扣费、组织管理、组织用量按各自权限显示；管理下保留成员、部门、额度分配、单人及批量限额/余额/菜单权限、用量、挂账/预存及原发票服务。V1.0.10 移除部门预算、设置预算、预算方式、预算提醒、可用分组、分组授权及用量报告，V1.0.14 继续移除组织用量分布和清账规则；不修改主站功能或已保存数据。移除独立“组织架构”入口不删除组织管理内原有部门操作。付款继续当前订单且仅查单确认，不以窗口关闭或跳转确认成功；内部查单/结果核对接口保留，不再提供“我的订单”总列表入口。

## 金额单位与页内操作（V1.0.10）

- 按用户对本站金额口径的明确说明，余额、扣费、额度和详情的数值原样显示，仅统一人民币标识。例如服务端返回 `12` 就显示 `¥12.00`，不乘任何汇率或充值倍率。金额编辑直接保存输入数字，未修改字段保留原始精度；微额扣费保留 4–6 位小数。该决定替代 V1.0.9 的展示换算，不修改旧包和站点账本。
- 金额展示不再读取付款配置或等待汇率，缺汇率也能正常显示和编辑。财务 `*_cents` 仍按站点合同以“分”除以 100 显示为“元”，不是外汇换算；实际充值/订阅的报价和支付合同保持不变。
- 充值 / 订阅页面内直接输入金额、点快捷金额、选择支付方式，或切到订阅方案后购买；移除重复的“充值 / 订阅”弹窗按钮。仅列站点可用的人民币支付方式和在售方案，显示实际规则下的支付、手续费及到账预览。提交前实时重读付款配置，校验方案、价格、充值规则和限额变化；变化时保留草稿，要求刷新确认。创建订单只提交一次，未知结果不自动重放，继续原订单付款和查单。
- 个人余额兜底在组织与扣费页直接开关，保存期间暂不可再点；成功后重新读取实际值，失败保留旧值和可读原因。页内开关与下单携带页面账号 ID、登录代次，后端写锁内再核对，防止切账号后提交旧草稿。
- 组织工作台分“成员与部门、成员额度、组织用量、挂账与余额”四组，共 10 个分区。子页只显示相应操作和筛选；选中业务对象后才启用需对象的操作。成员列表只保留“查看成员”，同一个窗口中查看和修改成员资料、余额、限额、菜单权限、扣费身份；各页保留未保存输入，保存成功停留当前窗口。限额保留 `expected_updated_at`，写权限和锁定仍由原接口核对，无权限只读。
- 额度分配分开显示配置比例、预计分配、本期已分配、已用和剩余；配置取 `custom_share_basis_points`，兼容旧 `equal` 模式的比例。本期数值取站点原字段，不用预计值替换。编辑按成员填写比例、锁定本次均分、均分剩余；最多两位小数，合计不超过 100%，可显式应用本期。未配置组织额度时提示去主站配置，不在 Hub 恢复预算入口。
- “挂账余额”取所有账期的 `outstanding_cents`；另列“已出账待清”“未出账累计”“已清金额”，分别按 `closed` 核对账期，不把未出账当到期欠款。预存余额独立显示余额、可用及预留；缺少字段显示 `—`。原账单、清账、预存抵扣及发票接口保持。
- 批量操作和成员选择使用统一主题窗口，可搜索、选择当前结果、清空选择并显示已选数量；筛选不丢失已选身份，返回不提交。批量余额/限额仍经原确认和 API 保存。账户二级详情、组织工作台、成员编辑和分配窗口统一字体、主题、留白及返回；表单保存固定可见，只有实际溢出的内容区滚动。

“回到主站”仍使用默认浏览器：配套接口启用后交换单次票据获得独立会话；未启用则打开主站并说明浏览器将使用自身登录状态。顶部资料约一分钟自动更新，登录和退出同步。没有读取或解密浏览器档案；站点实际使用 localStorage 认证，单拿 Cookie 不够。

## 切页提速、刷新与导入

V1.0.8 将原来每次本机 API 请求新建的 `Squad` 改为同配置复用一个服务及 reqwest 连接池；代理、配置位置或本机监听端口改变时重新创建。原先切页先串行读取公开设置、账户及组织，再读取正文；现在这些读取可复用短时内存结果，避免每次点击重复请求三项元数据。首次加载和新筛选仍需要站点响应，不承诺消除站点或网络延迟。

| 读取内容 | 最长复用时间 |
| --- | --- |
| 公开站点设置 `/settings/public` | 5 分钟 |
| 账户 `/auth/me`、组织权限 `/user/organization` | 30 秒 |
| 密钥、使用记录、统计/趋势、个人资料、可用渠道、组织列表 | 15 秒 |
| 付款配置/查单、财务与其他详情、任何写操作 | 不缓存 |

V1.0.10 删除显示用汇率请求及其缓存；实际下单前仍实时读取付款配置，不能以账户展示或短时数据替代付款复核。

右上角刷新先清缓存再读取；保存前后、登录、退出及明确401也清缓存。账号ID、登录代次、路径和完整筛选分别隔离；过期或读取失败不回退成成功，失败不缓存，清理后晚到旧响应不能重新填入。单项最多1 MiB、总量4 MiB、32项，均只在当前进程内存，不新增明文账户文件。会话锁、写入锁和服务端逐项授权仍执行；短时权限展示可能滞后，不能据此绕过真实操作的后端权限校验。

原生 API 密钥“导入 Hub”创建票据时漏传 `Origin`，与提供的站点源码合同不符；本机错误又统一包装为HTTP409。现在仅向固定官网 `/keys/:id/external-import` 发送固定同源Origin，随后单次兑换并读取模型目录，三步复用连接。全程核对同账号代次、链接来源与所选密钥，不跟随重定向，不自动重放票据；账户错误展示可读原因而非本机HTTP/JSON包装。最终仍进入原预览和受保护保存，不直接覆盖渠道。此原因来自源码核对和合成合同测试，真实站点导入由用户验收。

## 浏览器接续协议及站点交付边界

Hub 不需部署网站。用户最新要求的默认浏览器双向接续，需要现有天才小分队增加授权接口和页面；原有站点 API 没有此能力。配套源码、应用脚本与回滚见 [站点补丁](../../integrations/tiancai-squad-browser/README.md)。本轮只在此集成目录准备补丁，**没有修改用户提供的站点导出目录，没有部署线上站点**。旧文档“不需要修改网站”属于此前内置登录路线，不能用于宣称新双向接续已经上线。

- 浏览器 → Hub：本机随机 verifier 保留在 OS 秘密存储，只发送 S256 challenge；站点三分钟请求、六位核对码及用户确认；Hub 持证明轮询，单次原子兑换独立会话。
- Hub → 浏览器：已认证站点接口生成一分钟票据，地址 fragment 只带单次票据及证明，不带长期会话；站点授权页清除地址后交换独立会话并重载主站，清账号权限缓存。
- 两端不共享 refresh token，避免各自轮转互相失效。票据用途、有效期、账号状态、密码及撤销版本分别校验；错误证明不消费票据，Redis 故障拒绝继续。
- 取消等待、退出或另一次登录会使旧授权失效。网络轮询不占用会话写锁；接受响应前重查请求身份及当前账号代次，迟到回包不能替换已切换的账号。

## 任务路径与操作语义

1. 点击左侧“天才小分队”，未登录时显示登录主操作。正式程序在站点会话容器里使用原登录、验证码、二次验证或第三方认证。不能假定系统浏览器和 WebView 共享登录。
2. 登录后默认账户概览；API 密钥行可直接导入 Hub。不增加收藏、再写入、再检测等人工步骤。现有导入仍需要用户核对范围并确认保存，这一确认同时决定启用和追加模型。
3. 组织功能按各项权限出现，不强迫个人用户选择组织；扣费来源以站点实际返回呈现，不固定假定所有人都有三个来源。
4. 充值/订阅、订单、兑换、返利、组织成员/预算/结算及账户安全，复用既有站点 API 的权限与业务规则，由原生页面操作；需要浏览器验证或支付时打开受限窗口。原型这些深层入口只展示功能范围，不模拟真正提交成功。
5. 退出账号结束此模块会话并清空账号视图；已经导入的本地渠道不自动删除。撤销站点密钥可能影响后续调用，不能将退出等同于撤销密钥或停止现有任务。

导入继续复用 [现有 Hub 流程](../hub-external-import.md) 和 [v1 契约](../HUB_EXTERNAL_IMPORT_CONTRACT_V1.md)：`POST /keys/:id/external-import` 创建票据，Hub 用 `POST /external-import/resolve` 兑换，两者位于站点 `/api/v1` 下。账号令牌留在站点会话，不放进导入 URL；票据仅内存持有，一次使用，兑换结果未知不盲目重放。

默认“启用”“追加 Codex 可见模型”不勾选；导入普通渠道不会自动初始化 Codex、覆盖 WorkBuddy/天工专用副本或选择模型路由。同源+Key 的更新、同名不同 Key 的新建/明确更新、revision/文件锁/备份/原子替换及后改保护均沿现有实现，不按同名模型合并。新官方模块固定入口不限制现有通用网页导入的合法来源。

## 数据口径与失败恢复

站点余额、扣费、折扣、倍率、订阅额度、组织分摊、图片/视频或按次计费直接来自站点。Hub 本机 Token、路由日志和图谱只描述经过本机的请求；不能覆盖站点全账号统计，不能用本机输入/输出反算账单。账户原型用独立的 21 条合成站点记录；旧 9,069 条 Hub 合成记录及实际日志不变。站点展示输入、输出，不新增首字统计或单列缓存；正式实现按站点 DTO 归一，缺字段显示未知，不把不同协议重复相加。

读取失败保留同一账号的上次数据并标读取时间、暂停修改，提供重新读取；没有快照则显示未知，不填 0。401 回登录；403 不自动提权或当“无组织”，重读权限后回有权限页；429 遵循站点限流，不用轮询刷接口。切换账号清除旧账号缓存和未完成导入草稿，晚到响应必须校验会话/账号代次。付款结果由站点查单核验，跳转或窗口关闭都不能视作已付款。

## 原生承载与分阶段实施〔建议〕

| 路线 | 收益与成本 | 推荐 |
| --- | --- | --- |
| 原生账户页面 + 既有站点 API + 受限登录/支付 WebView | 统一外观并沿用既有后端；不重写浏览器验证，不要求站点改版 | **用户确认的实施路线** |
| 局部 wxWebView + 站点共享布局 | 曾评估，涉及站点布局改动 | 历史方案，已被原生 API 路线替代，不执行 |
| 整个 Hub 迁移 Web UI | 范围远大于此需求，影响所有客户端、托盘及发布链路 | 本轮不扩大到此范围 |

代码证据：[WebView 封装](../../vendor/wxdragon/rust/wxdragon/src/widgets/webview.rs)、[事件](../../vendor/wxdragon/rust/wxdragon/src/event/webview_events.rs)、[构建](../../vendor/wxdragon/rust/wxdragon-sys/build.rs)。已有加载 URL、当前 URL、后端可用性、导航/新窗口事件等 API；这证明有可评估的承载基础，**不证明当前产品已能嵌入站点**。当前 [Cargo gui feature](../../Cargo.toml) 未启用 `wxdragon/webview`。

正式实施先完成一个隔离技术样件：Windows 显式用 Edge/WebView2，缺运行时给安装/用系统浏览器继续的可恢复入口，不静默退到 IE。MinGW 的 WebView2Loader.dll 与 MSVC 静态 loader 路径不同，需按现打包工具链检查；Windows MSI/便携包、macOS WebKit/universal 签名与运行时链接分别核验。API 在仓库里可见不等于两个平台的实机登录/支付已验收。保持 Windows 优先、macOS 次之，不增加 Linux。

网站建议新增专用的 Hub 布局，复用 `AppSidebar` 当前菜单定义、路由守卫、权限 store 及原业务视图，仅调整外层导航和主题密度。原型里的七组页内导航就是此布局的建议，不要求 Hub 自己复制所有权限判断。不能把现有模型广场 `embedded=1` 当成已具备这套布局，也不通过脆弱的 DOM 隐藏脚本长期改造线上页面。

同一站点容器延续自己的会话；持久会话目录、账号退出清理、导航 veto、新窗口、下载以及 OAuth/支付的外部返回，需要核对并在必要时补最小 vendor FFI。当前 Rust builder 没有在本轮证明暴露独立用户数据目录控制，不能承诺现成的账号隔离或浏览器状态共享。登录输入只在站点页，Hub 不保存网站密码或复制 JWT 到模型配置。

导入优先接现有协议入口与待确认队列；若拦截 WebView 内 `tiancaispacehub://import/v1`，仍由原解析器完整校验再入队，不能绕过来源确认、兑换/保存保护。站点页面不获得任意本机文件读写或通用命令执行接口。跨站工具在原自定义页/外部浏览器打开，不把站点账号凭据传给其它域名。当前 HTML 原型仍是 `connect-src 'none'`，没有嵌入真实站点。

实施顺序：

1. **站点布局与承载样件**：导出当前用户菜单解析逻辑供 Hub 布局使用，保留完整原页；验证 Windows WebView2 创建、缺运行时恢复及主题/缩放，随后 macOS。没有业务数据写入前先评审。
2. **登录与只读账户功能**：站点会话下查看仪表盘、密钥、用量、模型广场；账号变化/退出/会话失效清缓存，403/429 与读取失败有继续入口。
3. **原导入衔接**：站点 API 密钥 → 一次性码 → 原 Hub 导入预览 → 受保护渠道保存；随后按现有独立副本规则从客户端使用，不能改默认路由或自动覆盖其它端。
4. **组织与交易全入口**：按原页面加入组织内部功能、充值订阅、订单、兑换、返利、资料及自定义工具；直接沿用服务端规则，不在 Hub 重建计费账本。每一写操作在真实产品里应有明确成功结果；不能把原型的说明弹窗交作正式实现。
5. **Windows/macOS 打包验收**：记录新源码/完整版本与新包身份，MSI 放 target，由用户实机测试；之后按授权再走 Actions。纯原型评审仍不升版。

主要回归范围：

- 个人/活跃成员/部门管理员/组织管理员/独立日志查看者；六权限组合；权限撤回、读取失败、登录切换与晚到响应。
- public settings 的 opt-in/out、精简模式、仅充值/仅订阅、支付关闭但订阅仍开、动态工具增删及跨站页面。
- 登录方式、验证码、TOTP、OAuth 新窗口/返回、刷新令牌/退出；不能用站点会话改变已有模型 Key。
- 原导入来源/票据校验、过期/单次兑换、取消/重复/超时、空目录、同源同 Key 更新及同名不同 Key、并发后改与二次确认；原正常来源和专用副本隔离。
