# XshellB-MCP

**[V1.0.53](../releases/v1.0.53.md) · 批量授权和同名菜单**：打开「设置巡检权限」，将命令粘贴到「批量自动同意」，例如 `pwd; df -h；free -m; uname -a`。中英文分号或换行均可；保存后每项是单独的巡检，不会拼成一行发给 SSH。可以补齐全部内置巡检，也可在「查看支持的命令」检查可用只读命令及参数。已有授权会按命令回填。两栏都有的命令以自动同意为准；未填的内置项每次询问，未填的扩展项不提供。有不支持项时保留草稿和已保存设置。旧脚本仍支持之前的巡检，使用新命令前在目标标签点一次「启动脚本」，重连或重开 Agent 的 MCP 连接以刷新工具清单。

对没有传统菜单、但安装资源中能唯一识别「运行脚本／取消脚本」的 Xshell，Hub **先**用这个命令对，不再先展开功能区查找同名「脚本」项。不能识别唯一命令对时仍使用功能区识别。最终仍以新脚本在所选标签页报到为成功。

**V1.0.52 · 一次点击启动或替换脚本**：先在所选 Xshell 窗口选好已登录的标签页，再到「共用能力 → XshellB-MCP」点一次「启动脚本」。按钮会替换该标签页当前运行的脚本，包括自行启动的脚本；不需要先手动点「取消」，不关闭 SSH 连接。启动期间请保持在原标签页。Hub 只在本次新脚本报到后显示接入成功。[本批验收](../releases/v1.0.52.md)。

新配置默认六项内置巡检每次询问，扩展命令不提供。保存后，运行新版脚本的已接入标签页从下一条请求开始使用新设置。旧版开启「完全访问」只迁移原有六项；原先逐个配置的扩展命令保留原权限。

未预先同意的巡检，客户端在 MCP 握手中声明支持[表单确认](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation)时，由客户端显示具体目标和命令；不支持表单时沿用 Xshell 确认框。在客户端拒绝、取消、确认失败或超时都不会转到 Xshell 再问。客户端自身的工具授权、手动启动脚本对新标签页的授权仍独立。升级还需重开使用中的 Agent 客户端或重新连接 MCP，使它加载新版 Hub 工具进程。见[本次测试](../releases/v1.0.51.md)。

在 Windows Hub 左侧「共用能力 → XshellB-MCP」选择 **ChatGPT / Codex、WorkBuddy 或 ZCode**，点「配置客户端」，再重开客户端或本地对话。打开自己的 Xshell 8 SSH 标签页，回到空闲提示符。在 Hub 选中对应窗口并点 **启动脚本**，这一下即准许已配置的客户端读取该标签页，无需自己找脚本文件。待 Hub 显示「已接入所选标签页」即可使用，沿用原标签页、当前账号及工作目录。

Hub 通过所选 Xshell 窗口的脚本入口，自动把本次内置脚本交给 Windows 文件选择框并打开。不会主动把终端窗口切到前台；系统选择框可能短暂出现。Hub 等待该选择框关闭、所选进程内此次启动的脚本报到后才显示成功。目标不兼容时页面会显示原因和「复制手动启动路径」；手动打开的脚本仍会单独确认接入。脚本依赖 Xshell 自带的 Python；MCP 运行于 Hub 自身的本地 stdio 模式。该配置面向本机客户端。

有实时菜单时，Hub 检查「工具 → 脚本 → 运行」是否可用；可用直接运行，否则在同一分组取消一次并等待「运行」恢复。没有传统菜单且功能区未暴露入口时，按该版本 Xshell 的菜单资源识别「取消脚本」「运行脚本」。此时没有实时启用状态；若能唯一识别取消项，Hub 等窗口返回取消请求后才提交一次启动，不能确定取消项时仅尝试运行。两条路径都等待本次脚本接入，不将「取消录制」或普通弹窗的「取消」当作取消脚本。见[菜单资源](../../src/xshellb/launcher/menu_resource.rs)、[功能区菜单](../../src/xshellb/launcher/accessible.rs)及[Xshell 8 手册 §16.1](https://www.xshell.com/docs/Xshell8_manual.pdf#page=64)。

初始不写入任何客户端，不启动脚本。客户端选配只写入 **XshellB-MCP** 同名条目，沿用现有格式、配置并发保护和受保护备份；同名冲突或后改内容持有者须先在客户端核对。「移除配置」仅移除当前仍和 Hub 版本一致的条目。停止 Xshell 的脚本或关闭标签页使接入失效；保留 SSH 会话时可用「工具 → 脚本 → 取消」。客户端重新发现工具需要重新打开对话或客户端。

工具可列出已接入标签页、读取目标可见文本，并运行启用的巡检。会话变化、取消、过期或离开接入时的空闲提示符时拒绝发送。发送成功只说明 Xshell 收到输入，须读取实际输出。权限保存在 Hub 的 xshellb 目录下的 `check-policy.json`；新配置不存在时才迁移旧版原有六项，在首次保存时关闭旧版整组授权。回退到「每次询问」可取消所有自动同意，再将不需要的扩展设为「不提供」。权限定义见[策略](../../src/xshellb/policy.rs)、[客户端表单](../../src/xshellb/elicitation.rs)。已接入标签页展示的可见文字会交给所选客户端。

代码：[MCP 与客户端适配](../../src/xshellb.rs)、[启动脚本](../../src/xshellb/launcher.rs)、[Xshell 脚本](../../assets/xshellb/attach.py)、[Hub 界面](../../src/gui/xshellb.rs)。设计参考 [NetSarang Xshell 8 官方手册](https://www.xshell.com/docs/Xshell8_manual.pdf)和 [Codex 本地 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)；独立实现，没有再分发第三方桥接项目代码。脚本和会话通信文件位于 Hub 配置旁的 `<配置名>.desktop/xshellb`，目录限制为当前 Windows 用户。只有请求读屏时才生成短期输出，正常读取后删除；实时状态只记录标签、地址、端口和心跳。客户端移除后可停止脚本，并在确认不再使用时删除此专用目录。
