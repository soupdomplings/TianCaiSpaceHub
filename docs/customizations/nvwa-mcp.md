## 需求与边界

实施人员在自己电脑上的 Hub 配置 NVWA 环境，再分别接入 Codex、WorkBuddy、天工 Claw。认证选择为“账号密码”和“认证服务连接”，默认账号密码 `password`。用户切入认证服务连接时，默认勾选“使用共享应用代表指定用户”，使用 `application`；取消勾选才使用真实浏览器页面授权 `browser`。共享应用代表填写的账号取票，不能作为本人密码登录证明。当前可共用同一套真实注册 ClientID/ClientSecret；用户已确认服务端没有限制共享密钥可以声明的用户名范围。Hub 不内置共享密钥，身份含义与边界在配置说明中明确。

NVWA 继续通过产品宿主的真实 HTTP MCP 和 Java 服务执行业务。Hub 读取真实登录上下文、工具目录及响应，不复制工具、不生成权限、不自行开放管理员分析能力。产品必须已经部署 MCP 模块、启用接口并提供可达地址；Hub 不上传 JAR、不操作产品数据库、不切换部署，也不发起模型调用。

新增平台优先 Windows，其次 macOS；本轮不扩展 Linux。修改本机客户端配置不会接入 ChatGPT 网页或云端连接器，不静默安装、重启或批准客户端工具。

## 操作入口与状态

桌面页签现名 **Dumpling-MCP**。默认隐藏，通过“帮助 → 显示 Dumpling-MCP”勾选显示，取消勾选隐藏；选择保存到 Hub 主配置 `showDumplingMcp`，默认 `false`，旧配置缺失该字段也默认隐藏。此开关只控制界面，不撤销登录、停止后台桥、移除客户端连接或删除凭据；当前窗口隐藏后再显示保留表单，未保存字段不因此自动落盘。首次显示自动读取状态，已有快照时重显保留当前内容，需要更新时点击“刷新”。页签采用 Hub 品牌的透明背景线条图标：饺子、环绕轨道及箭头，资源为 [dumpling-mcp.svg](../../packaging/brand/dumpling-mcp.svg)，无方形底色。页内标题、配置帮助及本页对话框同步 Dumpling-MCP，NVWA 服务地址、认证协议和后台标识沿用实际名称。

显示页签后先看到环境选择、环境名称、一个“NVWA 服务地址”和认证选择。账号密码方式显示账号、明文可见密码和“记住密码”，不显示应用注册与签名参数。认证服务连接的主区域显示共享应用复选框、ClientID、明文可见 ClientSecret 和“保存应用密钥”；勾选时同时显示要代表的账号，取消勾选后由产品页面完成个人登录和授权。密码与 ClientSecret 直接可见是用户指定的输入显示方式，不改变加密登录、秘密存储或日志规则。该区域说明“在认证服务管理添加应用服务，获取ClientID和ClientSecret”。认证选择始终可以切换，共享应用勾选不会锁住下拉框；网络操作期间仍按原忙状态保护。环境保存后再登录或授权。

顶部“?”打开随当前界面语言显示中文或英文的原生配置说明对话框，介绍环境/服务地址、默认可编辑 `/mcp`、密码流程、认证服务申请应用与代表账号、取消共享应用后所需浏览器回调、记住秘密，以及“保存环境 -> 登录 / 授权 -> MCP 检测 -> 各端预览”的顺序。共享应用并非本人密码认证的含义在此说明中保留。

“高级设置（特殊部署 / 管理员）”默认折叠，按认证方式显示相关内容：

| 设置 | 当前行为 |
| --- | --- |
| 认证服务地址 | 留空使用 NVWA 服务地址；特殊部署可填写独立地址，不强制同源 |
| MCP 地址 | 默认直接显示可编辑的 `/mcp`；可改为其它以 `/` 开头的路径或完整 HTTP(S) 地址 |

NVWA 服务地址、独立认证地址和完整 MCP 地址必须为 HTTP(S)，不允许嵌入用户名、密码、查询或片段。MCP 留空或 `/mcp` 都使用服务地址的部署路径再追加 `/mcp`；其它路径也保留部署前缀后追加，完整 URL 则独立覆盖。例如占位服务地址 `https://nvwa.example.com/product` 与 `/mcp` 对应 `https://nvwa.example.com/product/mcp`，改为 `/tools/mcp` 则对应 `https://nvwa.example.com/product/tools/mcp`。保存服务地址变更后，相对路径跟随新服务地址，完整 URL 不自动改变。管理接口/后台状态返回 `resolvedMcpUrl`，用于核对实际 MCP 目标；当前 GUI 身份文字不显示此字段，返回地址也不能证明接口已启用或已连接。旧环境的完整 MCP 覆盖地址、认证头、摘要及认证模式继续保留，不因加载新版界面自动改写：旧 `password` 仍显示账号密码，旧 `application` 显示认证服务连接且勾选，旧 `browser` 显示认证服务连接但不勾选。加载旧浏览器环境不会因为新切入服务方式的默认勾选而改成 application。

GUI 将默认显示的 `/mcp` 与原空 `mcpUrl` 统一视为默认值，保存表单及“先保存环境”检查使用同一规则，不因显示默认路径制造未保存差异。新环境默认保存空值；旧环境已保存为 `/mcp` 时保持原值，不因等价保存改成空值而撤销凭据。旧环境未改的 `loginUnit:null`、`mcpAuthHeader:null` 同样保持原表示，避免界面默认显示导致后台判定环境已变、要求重填密钥。旧完整 URL 加载时原样显示，用户可直接修改该高级字段。

密码与 ClientSecret 按用户要求直接可见，新环境的“记住密码”和“保存应用密钥”默认不勾选。密码记住仍在登录成功后写入系统保护存储；认证服务连接的 ClientSecret 改为勾选“保存应用密钥”后点击“保存环境”立即系统保护保存，不依赖登录或授权成功。加载带保存引用的环境恢复对应记住选项，并通过专用受保护读取接口从系统存储明文回填密码或 ClientSecret；保存、登录成功后继续显示本次输入。普通 profile 仅保存 `credentialSecretRef`，普通列表和状态仍不返回秘密或远端 token。加载或刷新已保存密码的环境不会取消“记住密码”，避免下一次登录无意删除自动续认证所需密码；用户主动取消并完成后续密码登录会移除保存密码，认证范围改变则按下述规则处理。

保存应用密钥按以下规则执行：勾选且输入非空时保存或替换；勾选但输入为空时，仅在实际认证范围未变、已有保存引用且保护记录实际可读时复用，单改环境名称不要求重填。认证范围已改、没有引用或记录不可用时，必须重新填写密钥；显式填入新密钥可替换不可读的旧记录。取消勾选并保存会移除原保存密钥。更换或移除保存凭据会挂起已有客户端接入，须核验同一真实身份后恢复，不直接丢弃原本机连接凭据；仅保存相同且可读的秘密保留原引用。顶层 `rememberSecret`、`clientSecret` 是管理保存请求材料，不写入 profile。旧 API 请求不带 `rememberSecret` 时保持兼容。点击“保存环境”后的刷新仍只在完整 profile 与本次快照及表单一致时保留当前内存密码/密钥，防止保存吞输入；内存保留与系统保护保存分别处理。

切换主认证下拉（账号密码/认证服务连接）会清空账号、密码、ClientID/ClientSecret、指定租户、登录机构、记住选项、双因子挑战、身份、工具目录及客户端检测结果，重置认证头/摘要默认值，保留环境名称和通用地址。仅勾选或取消“使用共享应用代表指定用户”时，保留 ClientID、ClientSecret 和“保存应用密钥”选项，其他旧认证输入和状态仍清理。两种切换都对已保存环境提交包含旧 `loginAttemptId` 的取消请求，并使迟到结果失效；取消返回后保留新表单，不重新加载旧认证字段。新方式须保存并重新认证。切换本身不额外显示“已切换”或“请重新检查”状态文字，也不显示 application 身份横幅；真实操作结果、必要挑战和错误状态仍正常显示。顶部配置说明同步区分这两种切换。

### 已保存密码与应用密钥回显

保存或登录成功后，当前表单中的密码、ClientSecret 继续明文显示。勾选“记住密码”并登录成功，或勾选“保存应用密钥”并保存环境后，资料进入 Windows DPAPI/macOS Keychain；再次加载该环境、刷新或重启 Hub 时，读取对应已保存值回填。未勾选保存的输入仅留在本次表单，切换环境、主认证方式或重启后不承诺保留；读取回填不等于再次保存，也不会新增自动记住行为。显式退出、取消登录不删除已保存登录资料，重新载入时仍可按保存记录显示；客户端授权继续遵守各自撤销/挂起规则。

读取使用本机管理 `POST profile/credential/read`，沿用现有实例管理授权、Host/Origin 校验及 `Cache-Control: no-store`。请求必须带 `profileId` 和 `expectedProfileFingerprint`，完整 profile 指纹与当前已保存环境一致；后台只读取该环境自己的 `credentialSecretRef`，不接受任意 secret key 或引用。专用响应通过 `credentialKind/credentialValue` 返回密码或 ClientSecret；远端 token、本机桥凭据和备份不回显，普通配置、列表、状态、客户端配置、诊断和日志不增加明文秘密。

GUI 读取期间沿用忙状态，禁用环境、认证方式和密码/密钥编辑；接收结果时再次核对环境、认证方式与完整 profile，只有对应输入为空且表单仍匹配时回填，保存或登录刷新已保留的当前非空输入优先。没有保存引用时不读取；已有引用但保护记录无法读取时明确提示不能恢复、需重新输入，不静默当作未保存，也不修改保存引用、认证状态或本机接入。此读取只访问系统保护存储，不调用 NVWA、不续 token、不重写客户端连接。

本轮不改变普通环境集合 version `1`、认证保护快照 v2 或系统秘密存储格式，不新增迁移。回退旧版 GUI 会恢复不回填的显示方式，既有受保护资料仍按原格式用于认证；不需要把秘密复制到普通 JSON、文档或客户端配置。Windows/macOS 的实际明文显示、重启回填、当前非空输入优先和读取失败提示分别待用户验收。

### 常用操作流程

常用顺序如下：

1. 在“帮助”勾选“显示 Dumpling-MCP”，选择或新增环境，填写名称、NVWA 服务地址。账号密码方式填写账号和密码；认证服务连接在认证服务管理添加应用服务，获取 ClientID/ClientSecret，默认勾选共享应用并填写代表账号。需要本人浏览器授权时取消该勾选，并核对真实应用回调配置。可通过顶部“?”查看配置说明，保存环境后点击“登录 / 授权”。
2. 核对服务端返回的当前用户、稳定身份和租户。挑战、密码过期和失败都不会开放 MCP。
3. 点击“检测 MCP”，核对真实 `initialize` 和完整 `tools/list`；这一步不执行任何工具。
4. 在“客户端接入”下拉框选择目标客户端，默认 ChatGPT(Codex)，可切换 WorkBuddy 或天工Claw；核对当前选项的实际配置位置。首次接入、配置变化或本机凭据已撤销时，点击“预览接入”并确认；同身份重新登录后可先“检查”已有设置，再“检测本机桥”，无需仅因重新登录重复接入。反馈只对应当前所选客户端，不代表其他端成功。
5. 在客户端完成原生刷新、信任及真实调用，由用户验收实际行为。

环境管理还提供刷新、删除环境、取消登录和退出登录。“取消登录”取消当次登录并保留挂起的已有接入；“退出登录”明确撤销该环境的接入授权。各客户端提供预览移除及预览恢复。网络和文件操作在后台执行，GUI 只接收当前操作及当前环境对应的结果。

客户端接入区只显示一组配置位置、五个按钮和一处反馈，均对应下拉框当前选项。Codex/WorkBuddy 的位置留空按既有规则自动寻找，可显式填写各自路径；天工使用官方本机连接设置。切换时临时缓存各端路径和结果，不新增持久偏好；操作忙碌时禁用切换，异步返回同时核对环境 ID、客户端种类和操作，避免把上一端结果显示到当前端。后台授权、受管记录和备份仍按三端分别处理，不因共用控件合并。

所选客户端有以下按钮，鼠标悬停会显示中英说明：

| 按钮 | 实际操作 |
| --- | --- |
| 检查 | 读取该客户端的连接配置，核对 Hub 管理归属、启用、外部修改和备份状态；显示配置检查结果、当前/历史 MCP 名称和下一步，不读取上游工具目录 |
| 检测本机桥 | 使用已接入的该端本机凭据，经 Hub 桥向 NVWA 读取工具目录，核对真实初始化、session 与分页清单；不执行工具。天工成功后还尝试同步其受管连接的工具目录 |
| 预览接入 | 显示将写入的 MCP 名称、配置位置和操作后果，确认后才添加、更新或重新添加已缺失的受管连接；拒绝时在当前客户端反馈区说明原因 |
| 预览移除 | 显示将移除的连接，确认后只删除该环境、该客户端中由 Hub 管理的条目，并撤销该端授权 |
| 预览恢复 | 显示最近一次修改前的受保护备份，确认后只恢复该条目并撤销该端当前授权；后续外部修改会阻止覆盖 |

“当前可用工具”取自当前环境实际 MCP 地址（`resolvedMcpUrl`）的 JSON-RPC `tools/list`，不是另一条 NVWA 能力查询接口，也不按本地固定清单生成。上方“检测 MCP”直达上游，客户端区“检测本机桥”经所选端本机连接，两者均经过 `initialize`、`notifications/initialized` 和完整分页 `tools/list`，最终显示服务返回的工具对象。接入、检查配置或读取目录成功不等于客户端已执行工具。

“检查”读取配置与“检测本机桥”读取工具目录分别处理，结果在所选客户端的同一反馈区说明。读取配置成功会明确说明已经检查设置；桥尚未检测时提示使用“检测本机桥”。同认证范围、同真实身份重新登录后保留已有本机凭据，可先检查原设置再检测；首次接入、已撤销凭据、目标缺失或实际连接配置变化才需要预览确认。管理 `client/inspect` 的 `requiresClientAccess` 表示当前运行态是否缺少可用本机 capability，`clientAccessSuspended` 区分重新登录期间暂时挂起的旧接入，`clientAccessRecoveryFailed` 区分保护记录无法恢复；挂起不等于可用，也不要求立刻重写配置。界面对检查、接入、移除、恢复及本机桥检测的结果同时更新对应运行状态，避免使用先前检查缓存继续提示首次接入。移除/恢复成功撤销该端运行授权后仍返回 `requiresClientAccess=true`；`false` 或已有 capability 不证明保存的 URL/凭据匹配，不替代真实桥检测与客户端调用验收。预览失败、冲突或拒绝显示在当前端反馈区，不沿用旧检测结论。

工具展示优先使用返回的 `title` 或兼容 `annotations.title`；没有独立标题时，取 `description` 第一行或第一句的有界短简介，保留原始 `name` 工具代码和服务说明。中文界面尽量采用服务已有的中文标题/说明；当前 NVWA 邻仓序列化主要提供 `description`，不保证每个工具都有中文名称。无中文服务字段时明确提示按代码核对，不猜译功能、不硬编码 code→中文映射，也不把 `inputSchema` 中业务参数的 `title` 当工具名称。标题最多显示 80 字符，简介最多 48 字符、说明最多 1600 字符，截断标注省略号；中英界面均保持原始代码。

登录等待期间仍可取消。每次管理登录带随机 `loginAttemptId`；取消登记有界、10 分钟的事务标记，并与登录开启按同一临界区排序，避免取消先到而旧登录后到重新开放授权。网络返回还须核对认证代次，界面不采用旧操作结果。此取消不证明已执行的远端业务被撤销。

GUI 常见登录/检测提示、身份/有效期、预览确认主内容和帮助按当前中文/英文界面语言显示；适配器的人话状态仍为中文，未知后端错误保留固定安全文本，本轮没有全量国际化或统一错误码。未登录时提示先“登录 / 授权”，登录成功显示当前账号与服务返回租户，检测成功说明读取了可用工具清单，接入后提示客户端刷新和信任。默认租户显示“默认租户（__default_tenant__）”，其他非空租户按返回值显示，未知有效期保持未知。管理接口另返回 `resolvedMcpUrl`，当前身份文字不展示此字段。工具清单读取和配置保存均不表示实际客户端加载/调用通过。Codex/WorkBuddy 的配置路径可用不证明应用已安装；天工缺少经核验运行授权时说明需先打开官方桌面客户端。

再次点击“登录 / 授权”时，GUI 先清当前运行态快照、工具清单和旧客户端检测标记，显示登录尚未完成、成功后再显示服务返回账号/租户。等待浏览器回调、双因子或改密时不沿用上一轮“已登录”及旧账号；认证成功后重新读取后台真实状态。

配置帮助同步说明：选择客户端后，下面的路径、按钮和结果只对应该端；同认证范围、同真实身份重新登录不必重复接入，但应检查现有设置并检测本机桥。重新登录期间旧连接暂不可用，失败或挑战不会借用上一轮 token；身份或实际认证范围改变后仍须明确重新接入。更名不自动修改客户端中的 MCP 名称，需要改名时仍单独预览确认。

## 三种认证方式

| 方式 | 当前认证链路 | 默认 MCP 头 | 个人身份含义 |
| --- | --- | --- | --- |
| 账号密码 `password` | 动态公钥 -> `/nvwa/login` -> `/nvwa/getLoginContext` | `Authorization: <raw token>`，无 `Bearer` | 服务端完成密码及必要挑战后确认本人身份 |
| 认证服务连接，取消共享应用 `browser` | 浏览器 `#/authorize` -> 本机一次性回调 -> 票据交换 -> 登录上下文 | `authorization-ticket-token: <ticket token>` | 浏览器中的实际个人授权身份；不能用打开页面代替换票和身份验证 |
| 认证服务连接，勾选共享应用 `application` | 应用签名申请一次性 ticket -> Basic 换票 -> 登录上下文 | `authorization-ticket-token: <ticket token>` | 共享应用代表填写的用户名；不是本人密码认证 |

认证服务连接需要真实 ClientID/ClientSecret；共享应用还需代表账号，浏览器方式还需可接受的本机回调。Hub 没有内置共享密钥，也不将打开页面或保存密钥视为认证成功。主区域勾选“保存应用密钥”后点击“保存环境”即交给系统保护存储，后续同环境可复用引用；身份与租户仍由真实认证核验。顶部配置说明区分应用密钥立即保存和密码登录成功后记住。

用户已确认登录 token 与 ticket token 两条链路可用，并补充两类不同的实际期限规则。内部分别保留 `personal_token` 与 `mcp_token` 及各自期限策略；password 使用登录 token 直接访问 MCP，browser/application 使用交换后的 ticket token。密码默认闲置 30 分钟超时，正常认证访问可延长会话；ClientID + ClientSecret 换票 token 默认固定 24 小时，调用不会延长，认证服务应用的 `tokenValidTime` 可覆盖。上述是用户提供的服务规则，本版真实行为尚待验收。允许 profile 显式选择 `Authorization` 或 `authorization-ticket-token`，不推定两种令牌在任意部署中可互换；指定头能否匹配部署由用户核对。其他头名被拒绝，token 不放入 URL。

成功必须有 token 且 `/nvwa/getLoginContext` 返回非空 `user_id`、`identity_id`、租户和登录名。支持上下文 `context` 包装及 `contextUser`/历史 `conetxtUser` 字段，租户继续优先采用返回的 `tenantName`、缺失时采用 `tenantId`。账号密码的指定租户留空时，登录请求发送产品默认选择值 `__default_tenant__`。用户确认该值也是产品有效默认租户：返回上下文为此值时正常接受，界面显示“默认租户（__default_tenant__）”；之前将它当作必须拒绝的占位值属于实现误判。本轮仅采纳服务返回的非空租户，不以表单值补造上下文。填写账号或指定租户与返回上下文不一致时仍拒绝认证。重新登录先挂起旧客户端授权和匹配 session，同认证范围、同真实身份核验成功后可恢复；身份比较固定使用 `user_id/identity_id/tenant_id`，展示登录名变化本身不视为换人，三项真实身份仍须完全一致。实际认证范围变化、身份不同或显式退出仍撤销旧授权；更换保存凭据、取消登录只挂起。工具缓存重新读取，进行中请求不跨新登录代次或切换为另一人的身份。

### 账号密码与登录挑战

Hub 先获取 `/anon/framework/api/encrypt/key`，按服务端真实公钥与 alias 加密账号和密码：alias `3` 使用 UTF-8 标准 Base64 后每 50 个字符分块的 RSA PKCS#1 v1.5，各块 Base64 密文拼接；alias `2` 使用原文 UTF-8 的 SM2 `C1C3C2`。与当前产品前端一致，登录请求发送 `encryptType="3L"`，不固定公钥、不使用旧 AES 默认值，不因获取公钥失败改为明文。密码原值不裁剪空格。

成功业务状态 `0`、`200` 和有有效 token/上下文的 `203` 才可完成认证。`201` 首次登录改密、`202` 密码过期返回必须完成的产品页面操作；本版不实现 Hub 改密表单。`204` 返回双因子会话，仍未认证，不能检测或调用 MCP。仅收到此挑战后，GUI 显示验证码输入和“发送双因子验证码”按钮，session 由后台状态内部管理，不要求手填。管理 provider 使用 `/anon/nvwa-nros/v1/msg/send`；收码后第二次登录带 `extInfo.twofactorSessionId` 与 `extInfo.validCode`，继续由产品校验。发送渠道和实际到达仍待用户验收。

此前已移除 GUI 的图形验证码 ID/码输入。当前验证码获取方法、图片 schema 未从真实契约确认，**没有集成验证码图片获取或展示**。`402` 提示到 NVWA 产品页面处理，或切换到已配置的浏览器个人授权；产品页面操作不保证后续 Hub 密码登录能够完成，也不自动复用浏览器会话。provider 仍保留受限 `verifyId/verifyCode/validCode/twofactorSessionId` 契约兼容，不借附加字段覆盖用户名、加密模式或服务端密码校验设置。

账号密码错误、锁定、停用、账号过期、在线数或多终端限制及维护状态分别使用固定安全提示。所有挑战和错误均不把旧规范“0～400 都登录成功”作为判断依据。

### 应用签名与浏览器回调

应用取票使用 `authorization-cer-client`；SHA-256 为默认摘要，SM3 可选，MD5 仅显式兼容。SHA-256/SM3 按规范在签名串中分别加入 `1`/`2`，digest 为小写 hex；MD5 沿用参考连接器的大写 hex。新摘要支持取决于部署版本，服务端时间校验也要求双方时钟正确。成功取得的 ticket 通过 `/nvwa-ticket/v1/ticket/{ticketId}` 与 `authorization-client-basic: Base64(clientId:clientSecret)` 交换，Basic 材料不是 MCP token。

显式登录的认证 HTTP 401 按失败步骤提供固定安全说明，区分申请票据、票据换成连接凭证及读取当前账号租户；可据此核对应用资料、认证地址、签名算法或重新授权。验证保存登录的真实 HTTP 401 另由结构化错误进入下文按需续认证，其他核验失败不一律清除身份。诊断和续认证实现都不改变服务端认证结果，也不证明当前部署的真实 401 已解决；请求/响应 body、密码、密钥、ticket 或 header 不进入诊断。

浏览器 URL 使用产品地址的 `#/authorize`、`response_type=code`、`client_id`、已编码 `redirect_uri` 和随机 `state`。本机回调为 `/callback/<64位hex随机state>`，仅绑定 `127.0.0.1`，事务 10 分钟、最多 64 个，必须匹配当前环境指纹与登录代次。有效回调在换票前单次消费，换票失败也不能重用；若回传 state 参数必须匹配路径，取消后晚到回调不能重新开放授权。支持单一 `code`/`ticket`/`ticketId` 票据，重复票据字段拒绝，兼容性 `tokenId` 不作为第二个票据使用。回调 code、ticket 与应用密钥不进入日志或可见错误。当前共享应用能否接受该本机回调 URL/端口、部署是否使用 Hash 路由，以及换票后 MCP 行为，均待用户真实验收；不假设标准 OAuth discovery、PKCE 或 refresh token 已存在。

### 有效期、恢复与重新认证

内部 `TokenExpiryPolicy` 区分 `Unknown`、`Fixed` 与 `SlidingIdle`；管理状态分别返回 `personalExpiryPolicy`、`mcpExpiryPolicy`（值为 `unknown/fixed/slidingIdle`）和可空的两份 `ExpiresAtMs`。系统保护认证快照保存每个 token 的 `expiryPolicy`，普通 profile/集合版本仍为 `1`，秘密不进入可见状态。

账号密码登录的个人 token 与 MCP token 都采用 `SlidingIdle`，新登录的 `expiresAtMs` 保持空值。Hub 不把首次登录响应的 `expiresAtMs` 或 `createTime + validTime` 当作硬到期，不用本机访问时间推算或延长服务端 touch。界面与中英帮助说明“默认闲置 30 分钟超时；正常认证访问可延长，由服务判断”，因此连续使用不会仅因登录后已过 30 分钟被 Hub 判定失效；实际会话是否有效仍由服务及真实认证结果决定。

浏览器/共享应用换票 token 采用 `Fixed`，优先使用该 token 响应自己的 `expiresAtMs`；否则使用自己的 `createTime`（毫秒）加有效时长，先取正数 `validTime`（秒），再取正数 `tokenValidTime`（秒），没有有效正值或为 `0` 时默认 `86400` 秒。应用配置的 `tokenValidTime` 通过交换 token 返回的自身时长体现，不读取或修改应用服务配置。缺少服务创建时间时保留未知准确期限，不以本机换票或恢复时间补造 24 小时到期点；一次性申请 ticket 的 `validTime=600` 不继承给交换 token。时长上限与溢出校验保持。有准确固定期限时界面显示 UTC 到期时间与剩余时间，并说明调用不延长；没有准确时间时只显示固定默认 24 小时、应用可覆盖和服务未返回准确期限。`Unknown` 策略继续显示期限未知。

恢复系统保护快照时，先核对下述版本和认证范围，再按 `auth_mode` 确定两份 token 策略：password 清除旧非零绝对期限，保留真实 401 的 `Some(0)` 失效标记；browser/application 保留原准确期限，不按恢复时间补造新期限。个人与 MCP token 仍分别记录，不能把某个 token 的过期推定为另一 token 也过期；恢复前的真实身份核验、认证代次和同身份保护不放宽。

后台把认证状态和每端本地连接凭据通过系统保护存储保留；重启后恢复记录还要核对认证范围及真实上下文身份，不能直接放行旧 token。运行期同身份核验缓存最长 60 秒。已知期限过期或已有真实 HTTP 401 失效标记时，在下次使用、尚未发送 MCP 请求前，password 仅用此前成功登录时显式记住的密码重新登录，application 仅用此前显式保存的 ClientSecret 重新申请 ticket 并换 token；未保存或保护记录不可读时要求人工认证。没有新增后台定时续期，普通配置也不新增秘密字段。

`/nvwa/getLoginContext` 身份核验的真实 HTTP 401 由结构化错误识别，先标记并保存当前认证失效，再在同一次发送前预检中按上述条件续认证；不再把该 401 一律当成必须清除身份的核验失败。HTTP 403、网络超时、异常 JSON 等其他核验失败只拒绝当前请求，不据此清除已登录身份或提交密码/密钥。确认用户或租户已变化时仍撤销对应旧认证代次并要求显式登录；迟到结果不能撤销替代登录。

主桥请求和上方“检测 MCP”的直连检测收到真实上游 HTTP 401 时，使用同一失效标记与系统保护保存路径。标记同时核对该请求的认证代次及实际 token，不能把旧请求的迟到 401 标到新登录或已经续成的新 token。已经发出的原 MCP 请求仍失败，尤其 `tools/call` 绝不换 token 后自动重放；失效状态供下一次使用时续认证。HTTP 403、网络错误及协议/JSON 异常不会触发这条 HTTP 401 续认证路径。

自动续认证成功后必须严格保持原 `user_id`、`identity_id`、`tenant_id` 和认证代次，保留同身份的各端本机 capability/session；身份变化不被当成成功续期。自动认证请求失败或返回验证码、双因子、改密等挑战后，同一代次的下一次自动尝试至少等待 60 秒，再有使用请求时才重试；该失败冷却保留在本次运行内存中，手动登录不受等待限制。这与最长 60 秒的身份核验缓存是两项不同规则。挑战仍需人工继续；browser 没有已确认 refresh 契约，过期必须重新浏览器授权，不能切换成共享应用代表用户认证。

手动重新登录也可延续已接入客户端，前提是**实际认证范围未变，且同一组真实 `user_id/identity_id/tenant_id`**。开始新登录代次时，旧 token 不再可用，已有 capability 和匹配 session 只作为挂起锚点保留，客户端请求不能使用它们。真实身份核验成功且三项均一致后，恢复原各端本机凭据，并将运行内匹配 session 绑定新代次；无需仅为 token 更新重写客户端配置。首次登录、身份不同或没有可保留凭据时仍须预览接入。登录失败、取消当次登录、浏览器等待、双因子或改密期间保持挂起，不能显示为旧身份已登录；之后同身份登录仍可恢复。

同身份登录成功后，若勾选“记住密码”或保存登录凭据，`server::remember` 可内部保存/更新 `credentialSecretRef`，随后提交已核验身份并保留原客户端接入。保存相同认证范围的环境时，仅改环境名称、等价 URL/default 表示或保持原保存凭据，不撤销现有登录与接入。更换或取消保存凭据时先停止旧认证并挂起原接入；新的密码或密钥必须经过真实身份核验，不因凭据已保存而恢复授权。

系统保护快照新增 `schemaVersion=2` 与 `authScopeFingerprint`。认证范围包含环境 ID、实际产品/认证服务目标、解析后的 MCP 目标、认证方式、ClientID、账号、租户、登录机构、MCP 认证头、签名算法及非秘密扩展。产品/认证 base 尾斜杠、空认证地址回退、空 MCP 与 `/mcp`、默认认证头及头名大小写按实际等价目标规范比较；租户空值与显式 `__default_tenant__`、登录机构 `None` 与显式空值保持区别，不合并实际不同的请求语义。环境展示名称与 `credentialSecretRef` 不属于认证范围。更名不自动迁移客户端 MCP 名称，仍须显式预览确认名称更新。改变实际认证范围会撤销旧授权，不能靠规范化合并不同服务、账号或租户。

登录中途保存的系统保护快照可以包含 `pendingIdentity` 与三端 `capabilities`，此时运行态 `auth=None`，快照不保留上一轮远端 token。恢复分开校验身份/本机凭据与远端 token：身份和本机凭据有效、只有 token 格式无法恢复时恢复挂起锚点，须真实同身份登录后恢复，不把旧接入当作从未存在；身份、本机凭据或记录格式损坏时报告 `recovery_failed`，客户端状态返回 `clientAccessRecoveryFailed`，不静默伪装为首次未接入。RPC session 与活动请求不持久化，客户端需重新初始化 session。

旧保护快照只有完整 `profileFingerprint` 与当前环境吻合才迁移，启动时先写入 v2 再恢复，避免之后更名或记住凭据更新引用时再因旧指纹丢失恢复锚点；新快照只有版本受支持且 `authScopeFingerprint` 吻合才恢复，未知版本拒绝恢复。以前已被旧实现删除的本机凭据无法凭新版推算回来，必要时仍需一次预览确认重建；不从客户端文件无身份锚点导入凭据，也不以受管记录存在代替身份核验。普通 profile 与集合仍 version `1`，不增加秘密字段或自动将挂起状态视为有效认证。

显式退出登录、实际认证范围变化、确认身份不同，以及某端移除/恢复，仍撤销相应旧凭据和 session，不因本次保留机制复活；取消登录与更换保存凭据只保留不可使用的挂起锚点。已发出的 RPC 不跨新登录代次续跑；响应返回前再次核对代次、该端 capability 与 session，旧请求结果不进入新登录状态。未知结果按现有 `outcomeUnknown/retryable` 规则处理，不自动重放工具请求。

## 本机 HTTP 桥与 MCP 行为

桥由 Hub 后台承载，默认 `127.0.0.1:3849`，与模型网关/IM 的既有入口分开。每个 profile 和客户端都有独立随机本地连接凭据；客户端只配置 `/mcp/<profileId>/<codex|workbuddy|tiangong>` 的本机 URL 与本地 `Authorization: Bearer ...`，真实 NVWA 密码、密钥和 token 不写入客户端配置。管理接口另用受系统保护的实例凭据，并校验本机 Host 与存在时的 Origin；旧公开网关管理 API 不挂载这些 NVWA 操作。

本机管理 GET `/manage/status` 返回配置和安全状态；POST `/manage/profile/save`、`profile/delete` 使用 `expectedRevision`，登录为 `login/password`、`login/browser`、`login/application`，另有 `login/twofactor/send`、`login/cancel`、`logout`、`tools/detect`。每端使用 `client/inspect`、`client/preview`、`client/apply`、`client/remove`、`client/restore`，字段为 `profileId/clientKind/overridePath?`，实际修改还需最新 `expectedFingerprint`，恢复需当前 `backupRef`；所有操作均需要后台管理凭据。成功包装为 `{ok:true,data:...}`，失败为安全 `{ok:false,error:{code,message}}`，不返回 token/原条目。本地请求体最多 2 MiB。

运行状态的 `clientAccess` 字符串数组继续只列 active 本机凭据对应的客户端种类；新增 `suspendedClientAccess` 只列重新登录期间挂起的 `codex/workbuddy/tiangong`，不返回凭据。`client/inspect` 的 `clientAccessSuspended` 布尔值让 GUI 优先提示完成同身份登录后恢复旧连接，避免把挂起误当作需反复接入；这两类状态均不证明客户端配置匹配或实际工具调用成功。

NVWA 宿主采用 stateless HTTP MCP。本地桥支持 POST JSON-RPC、DELETE 本地 session；GET/独立 SSE 流不是本版传输实现。客户端 Accept 需包含 JSON 与 event stream，远端响应仍须为有效 JSON，SSE/HTML/重定向或 HTTP 200 下的协议 error 均不会被当成成功。支持协议版本 `2025-11-25`、`2025-06-18`、`2025-03-26`，初始化还核对 `serverInfo`、tools 能力及 RPC ID。

initialize 成功后给客户端本地 `Mcp-Session-Id`。session 绑定 profile、client、本地凭据、登录代次与协议；本地 session 不传给 stateless NVWA。RPC 原 ID 转为独立上游 ID，响应再映回原 ID，同一 session 的重复活动 ID 被拒绝。取消通知只映射该 session 的活动 ID，不转发可能含私有正文的 reason。DELETE 仅释放本地 session/映射，不宣称取消已经到达远端的业务写入。

### 天工工具刷新与重复会话头

用户同轮反馈天工刷新工具返回 HTTP 404。静态核对官方 `discoverViaStreamableHttp` 同时设置 `mcp-session-id` 和 `Mcp-Session-Id`，两个值是相同 session；HTTP 头名不区分大小写，浏览器 fetch 可合并成 `会话值, 会话值`。此前 Hub 按整串查找 session，会将这种合法重复形态视为未知会话，可能出现 initialize 成功后 `tools/list` 返回 404。该静态机制与反馈吻合，但没有捕获真实请求/响应，不能认定为用户 404 唯一原因或已经修复其实机问题。

本机 MCP POST 与 DELETE 共用 `session_header` 解析：只对 `tiangong` 接受完全相同的重复值，既读取 `get_all` 的多头值，也拆分逗号合并值；合计最多 4 个值，各值修剪后必须非空、长度不超过 128、仅含 ASCII 可见字符且全部相同，归一为一个原 session。Codex/WorkBuddy 仍拒绝任何重复形态。空值、冲突值、过多值或非法字符返回 HTTP 400；没有头仍按原流程返回 `None`，不生成 session、不绕过 initialize。真实未知/过期 session 仍按原 admission 返回 HTTP 404，profile/client/凭据/认证代次/协议核验不放宽，initialize 仍禁止复用已有会话，失败的工具请求不重放。

回退此次会话头兼容后，天工相同 session 的重复/合并头可能再次按整串查找而触发 404；认证和环境格式不迁移。回退前结束客户端旧会话、重新核对接入和身份，不能用重放失败工具请求验证；真实未知/过期会话仍应重新建立，不能当作需要放宽校验的重复头问题。

限制包括最多 512 个本地 session、24 小时空闲期限、最多 256 个活动 RPC；远端响应最多 8 MiB。Hub 检测只发 `initialize`、`notifications/initialized` 与分页 `tools/list`，最多 100 页、10000 工具，并核对名称、输入 schema、cursor 循环及响应 ID；零工具目录合法，工具数未知与零分别显示，不硬编码历史数量、不调用 `tools/call`。

任何已经发送的 `tools/call` 在断连、超时、无法解析、ID 不匹配等情况下返回 `outcomeUnknown=true`、`retryable=false`，不自动重试。产品返回的工具结果和权限 error 保留业务语义，不伪造成功或提升权限。认证及桥自身错误只含安全阶段、HTTP/业务 code 和固定提示，响应 body、认证 header、密码、密钥、回调 query 不进入诊断。

## 三客户端配置与预览

Codex、WorkBuddy、天工 Claw 新接入的 MCP 名称统一使用**已保存环境名称**，例如环境名 `MCP196` 对应 Codex `[mcp_servers.MCP196]`、WorkBuddy `mcpServers.MCP196` 和天工的 `MCP196` 连接名称。本轮沿用 1～64 位 ASCII 英文字母、数字、下划线和连字符的名称校验；接入预览/保存时非法名称会提示修改并保存环境名称，再重新接入。检查、移除和恢复不因当前环境名称不合法而阻止清理原有受管项。此前 `nvwa-` 加 profile ID 的 SHA-256 前 16 位 hex 名称作为历史受管名兼容，不继续用于三端新接入。

三客户端旧 hash 名或以前环境名的受管条目，更新接入时按原 profile、实际配置文件或官方桌面连接范围与 Hub 管理记录识别，并迁移到当前已保存环境名；预览显示目标名称，有旧名时说明变化。迁移同时核对旧受管项及新名位置的完整指纹，保护备份保存所涉名称的前像和归属，journal 核对完整 before/after；拒绝同名非受管条目、外部修改、归属歧义、未完成操作及预览后变化，保留其他配置。每个客户端继续使用独立本地凭据，GUI 检查、移除/恢复显示当前实际受管名；仅登录、改未保存表单或检查不会迁移。

Codex 在同一份 TOML、WorkBuddy 在同一份 JSON 中核对完整文件及所涉名称前像后，完成一次文件替换，移除旧名称并添加环境名称；文件锁及原子替换不表示非协作编辑器没有并发窗口，元数据提交失败仅在所涉文件目标仍精确等于本次结果时补偿。天工官方 PUT 不支持修改 `server_name`，确认迁移后按“删除旧连接 → 创建新连接”执行，每步前后核对旧/新两名的静态配置；动态工具目录和连接状态不当作静态设置修改。DataServer 没有多连接原子事务、CAS 或原生改名接口，不能将其描述为一次原子改名。天工响应未知、只完成部分步骤或元数据提交失败时，均不自动补偿、不重放，保留 `pending` 保护并要求核对；仅完整 before/after 可确认时收敛事务，部分状态不承诺自动恢复入口。完成迁移后的“预览恢复”是另一个需用户确认的操作，可按备份恢复原双槽，不等于迁移失败自动回滚。各端迁移与失败/恢复边界均待用户验收。

### 历史接入记录存在、客户端连接已缺失

历史登录资料与客户端 MCP 配置是两份独立状态：环境仍能登录，不表示客户端条目还在。旧受管记录存在、目标已确认不存在，且记录不是 `pending` 时，检查说明“此前的接入记录仍在，但客户端中的连接已不存在”，引导登录后点击“预览接入”并确认，重新添加连接。缺失不再统一视为用户修改，三端明确归属的唯一历史受管名可继续按已保存环境名称重新接入；检查展示“历史 MCP 名称（客户端中已缺失）”及“重新接入 MCP 名称”。旧条目仍存在时，更新预览则展示当前名与更新后名称。登录成功或点击检查本身都不迁移名称、不写客户端配置。

重新添加仍需最新预览指纹、目标前像和归属核验。目标仍存在但已外部修改、同名非受管项、多个归属、未完成事务或预览后变化仍拒绝覆盖；不可读取目标不能当作已缺失。三端本轮均按保存环境名重建，但此前缺失问题反馈只涉及 Codex，不能推定另外两端已经出现相同问题或通过验收。

外部删除后的旧备份只保留历史引用，不作为当前可执行恢复入口。用户确认重新添加后，三端 version `2` 定向备份记录所涉名称真实“条目缺失”的前像，相应旧归属的恢复指纹记录为 `missing`；恢复本次重新添加时移除新建连接并保留缺失标记，不把原来已经删除的旧条目重新创建。本轮沿用此前 Codex v2 的多目标结构与范围兼容，保留 Codex 旧 v2 读取；WorkBuddy/天工旧 v1 单目标备份继续可读，天工作用范围为 client/profile/无文件路径。普通管理记录仍 version `1`，不重算旧键、不在管理响应中返回秘密条目；同为 v2 不表示旧 Codex 专用实现能理解 WorkBuddy/天工新多目标备份。

同一文件的路径别名用于归属匹配：先拒重解析点/符号链接，再核对 canonical 路径；目标尚不存在时从最近存在祖先加规范路段，其他读路径错误不降级。Windows 核对大小写、分隔符及普通/UNC verbatim 前缀等价；实际事务沿用选中管理记录原始路径，旧 ledger key 与 v1 备份不重算。多活跃连接、同名多个可恢复记录或不完整 pending journal 停止自动处理，不能按排序猜归属；不宣称文件锁与原子替换消除了非协作编辑器的全部竞态。

| 客户端 | 实际配置范围 | 生效与证据 |
| --- | --- | --- |
| Codex | 桌面用户 home 的 `.codex/config.toml`，新接入使用 `[mcp_servers.<已保存环境名>]`，旧受管名按保护规则迁移；不盲从启动 Hub 进程的 `CODEX_HOME` | TOML 保留其他表和设置；用户仅确认此前包一次接入，新增名称迁移、原生信任与真实调用待验收 |
| WorkBuddy | 优先 `WORKBUDDY_CONFIG_DIR`/`CODEBUDDY_CONFIG_DIR` 下 `mcp.json`，否则用户 `.workbuddy[-实例号]/mcp.json`，仅 `mcpServers.<已保存环境名>` 及明确归属的旧名 | JSON 保留其他根项与 MCP 条目，旧/新名在同一文件替换中迁移；品牌或专享版需显式核对路径，需原生刷新或重启，并保留信任流程 |
| 天工 Claw | 经核验的官方桌面 DataServer `/data/mcp/connections` 窄 GET/POST/PUT/DELETE API，名称为已保存环境名；复用现有运行授权，不指定数据库文件 | 删除旧名再创建新名，每步核对双槽；未知/部分/元数据失败不自动补偿，无多连接原子事务/CAS/原生改名。新接入保持 `is_connected=0`、空工具目录，严格检测后可仅更新当前受管/未改动/启用且凭据匹配的目录；弱 `test/discover ok` 不当连接证明，每轮加载待用户验收 |

Windows 标准路径分别形如 `%USERPROFILE%\.codex\config.toml` 与 `%USERPROFILE%\.workbuddy\mcp.json`；macOS 为用户目录下同名文件。GUI 可以显式指定 Codex/WorkBuddy 的绝对文件路径，只允许相应文件名，Windows 的两端文件名核对均忽略大小写，拒绝符号链接与 Windows 重解析点；不能悄悄同时改全局和项目配置。天工只用原生 API，不直接读写 SQLite，也不修改运行审批。

管理 `tools/detect` 可带 `clientKind="tiangong"`：严格 Hub 目录检测通过后，仅当前拥有且启用、未被改动、本地凭据匹配的天工受管条目才更新 `is_connected/tools_json`，返回 `tiangongDirectoryUpdated`。目标期望名称取保存环境名，检查按明确归属找到当前实际 `server_name`；用户尚未确认改名时仍可同步原受管名称。临写前再次读取实际连接，按同一归一化规则核对 URL 和静态设置的单条目指纹，再次确认启用、本地 Bearer 和认证代次。内部 `entry_fingerprint` 使用 `serde(skip)` 不返回管理响应，目录同步不把包含旧/新槽的复合预览指纹当作单条目指纹；动态目录/连接状态与静态配置保护分开。DataServer 没有 CAS，最后一次读与写之间仍有外部并发窗口。该更新不接管同名用户条目、不自动启用禁用项，也不证明真实工具调用已经成功；GUI 顶部“检测 MCP”只检测 Hub 上游链路；每端“检测本机桥”传对应 clientKind，真实经过该端本机凭据、initialize/session、分页 tools/list 及本地 DELETE。天工目录未更新时单独提示，不显示客户端真实调用已通过。

接入预览先核对所选已保存环境是否已登录；未登录时说明先“登录 / 授权”，不继续写接入配置。移除和恢复预览仍可在未登录时执行，便于清理旧连接。确认框按界面语言说明所选环境、目标客户端、MCP 名称、实际配置文件（天工为官方桌面连接设置）及操作后果：接入会添加或更新该环境的受管连接，三端均显示目标名及旧名变化；移除/恢复显示实际名，移除删除该连接并撤销该端授权，恢复还原受保护备份并撤销当前凭据。确认前显示必要冲突说明与下一步，不展示原秘密条目或本地 Bearer。检测成功只说明读取工具清单，配置成功后仍需客户端原生刷新/信任和用户真实调用验收。

检查及预览的后台契约仍返回目标路径、受管归属、目标指纹、是否有外部修改、启用状态、最新可用备份引用和加载/连接状态；检查另返回 `requiresClientAccess`、`bridgeCheckedAtMs` 和 `bridgeState`，区分本机授权缺失与桥检测记录。移除/恢复成功撤销运行授权后返回 `requiresClientAccess=true`，其 `false` 不表示配置匹配或实际调用通过。实际接入、移除、恢复必须使用最新预览指纹，保存前再读目标；GUI 登录和客户端操作前核对表单与已保存环境一致，修改过的字段先保存，避免显示环境与后台实际环境不一致。外部文件侧加锁、核对完整读入文件后原子替换，保留无关项；不协作编辑器仍有竞态窗口，不能宣称跨进程原子 CAS。天工原生接口也没有 CAS，只能前后核对，失败不重放。

## 配置、凭据与备份

Hub 主配置的 `showDumplingMcp=false` 是界面偏好，与下述独立 NVWA 环境/凭据配置分开；隐藏页签不删除它们，也不改变客户端连接。此字段由帮助菜单保存，旧配置缺失按默认隐藏处理。

NVWA 不复用模型 API Key、IM 授权或普通网关渠道。普通 profile 字段为 `id/name/productBaseUrl/certificationBaseUrl/mcpUrl/authMode/clientId/username/tenant/loginUnit/mcpAuthHeader/signatureAlgorithm/credentialSecretRef`；缺失字段用兼容默认值，默认 password、SHA-256、桥端口 3849。`certificationBaseUrl` 留空回退产品地址。`mcpUrl` 接受空值、`/mcp`、其它以 `/` 开头的路径或完整 HTTP(S) URL；空值和 `/mcp` 都为默认，新环境保存空值，旧环境已存 `/mcp` 则保持原值，避免等价保存撤销凭据。路径解析保留产品部署前缀，完整 URL 独立覆盖。`resolvedMcpUrl` 是管理状态中解析后的地址。`tenant` 留空不等于已核验租户，密码请求使用产品默认选择值后仍须核对真实上下文。集合与 profile 保留未知非敏感扩展字段；递归拒绝密码、密钥、token、认证 header、cookie、票据和登录挑战值等敏感字段，扩展最多 16 层/10000 节点，不能用扩展影子覆盖标准字段。集合版本 `1`，最多 64 环境、配置 1 MiB；`_revision` 只作为管理 API 比较依据，不落盘。

以实际 Hub 主配置 `<目录>/<stem>.toml` 为作用范围，旁边派生：

| 文件或存储 | 内容 |
| --- | --- |
| `<目录>/<stem>.nvwa.json` | 环境集合、非秘密字段及 secret 引用；文件锁与原子保存 |
| `<目录>/<stem>.nvwa.lock` | 集合操作锁 |
| `<目录>/<stem>.nvwa-secrets/managed.json` 与 `managed.lock` | 定向客户端操作的归属、路径、指纹和备份引用；不包含明文 Bearer/远端 token |
| Windows：`<stem>.nvwa-secrets/<scope-key-hash>.dpapi` | 当前 Windows 用户域 DPAPI 加密值，不使用 `LOCAL_MACHINE`；原子保存 |
| macOS：用户 Keychain，service `TianCaiSpaceHub.NVWA` | 以配置 root 与 key 的 SHA-256 派生 account 保存字节；不通过命令行参数暴露秘密 |

系统存储包括显式保存的登录凭据、认证会话、本地客户端凭据、后台 GUI 实例引导和定向备份。scope hash 防止多份 Hub 主配置串用同名 key。敏感目标备份只保存待改 MCP 条目的前像，单目标操作保存一槽，三端名称迁移包括旧/新名称所涉槽，已确认缺失则记录空前像；按 32 KiB 块交给 SecretStore 保护，不备份整份第三方配置。普通元数据仅持有引用与指纹。

重新登录的挂起锚点只进入上述系统保护认证快照：`pendingIdentity` 保存已核验身份，`capabilities` 保存各端本机凭据，没有旧远端 token；当前保护快照版本为 `schemaVersion=2`，用 `authScopeFingerprint` 绑定实际认证范围，普通环境配置及 GUI 客户端下拉选择均不新增持久字段。旧保护快照先按完整旧指纹核对再迁移；不能把文件可读或本机凭据存在当作登录完成。保护记录恢复错误仅反馈固定安全状态，不显示凭据或原始记录。

需要新建/替换应用密钥时，先以独立随机 key 写 SecretStore，再按 `_revision` 比较保存配置；配置失败删除本次新 blob，成功后再删除旧引用。同认证范围输入相同且实际可读密钥时保留原引用。只改展示名称或等价默认地址保留现有登录及接入；更换/取消保存凭据会挂起接入，实际认证范围变化才撤销旧范围的登录及本机凭据，保存密钥不自动登录。取消保存选项后完成环境保存才移除旧密钥；若仍需认证，重新填写或重新选择保存。旧 API 不带保存选项保持兼容，不新增明文落盘路径。

维护边界：环境保存持同一 persistence 锁跨配置提交、运行态撤销/挂起与保护快照写入，避免迟到 HTTP 401 的保存将旧授权标成新认证范围；这仍不是跨普通配置和系统存储的原子事务。配置提交后的授权处理或旧记录删除失败仍返回操作错误，不能把该错误一概解释为普通配置未保存；排障应刷新状态并核对实际引用，不能据失败提示盲目重放保存。配置提交前失败的清理机制与客户端定向写入的补偿机制分别处理。

写入前登记操作恢复记录，写后只读核对实际目标。写入响应不明确时不重放，读取确认一致才报告配置保存。Codex/WorkBuddy 元数据提交失败，只在所涉文件目标仍等于本次写入结果时补偿还原；并发变更则保留记录并要求人工核对，不能覆盖新修改。天工未知/部分/元数据提交失败均不自动补偿，保留 pending 并要求核对完整目标；成功迁移后的显式预览恢复另行确认执行。

## 移除、退出、迁移与回滚

“预览移除”只操作选中的客户端和该 profile 受管条目，并撤销该端本地授权/session；恢复也撤销该端当前凭据，其他客户端独立处理。“退出登录”使该环境授权、本地 session、工具缓存、系统保护的认证会话和在途浏览器事务失效；远端 logout 尽力执行并单独返回是否确认，不代表远端业务写入回滚。“取消登录”只停止当次登录并保留挂起锚点，两者不能混用。已保存登录凭据仍按用户记住选项保留，客户端配置仍需分别移除。存在未移除受管条目时拒绝删除环境；成功删除才清除其凭据引用和认证记录，不以删 profile 掩盖配置移除失败。保存环境时区分展示变化、凭据保存变化与实际认证范围变化，具体以上文规则为准。

“预览恢复”只允许当前受管目标的最新 `backupRef`，同时核对最新预览指纹及备份记录的写后指纹。仅恢复该条目并保留其他设置；用户已修改的目标不能自动还原。移除前也保留系统保护的定向备份，恢复结果仍需按原生刷新/信任方式生效。

三端名称迁移的恢复按受保护 v2 旧/新槽前像处理：原旧名存在时恢复该旧名及原归属，原旧名已缺失时仍保持缺失；不能只恢复新名而留下重复旧名。成功迁移后的天工恢复是独立预览确认操作，仍使用官方连接 API 逐步核对，没有多连接原子回滚或失败自动补偿；部分/未知/元数据失败保留 pending 并停止，仅完整 before/after 可收敛，不承诺部分状态自动恢复入口。回退三端名称统一改动前，应先使用认识本轮备份的新包按需移除或恢复环境名连接、核对结果并退出授权；旧包只理解当时范围，可能只查 WorkBuddy/天工 hash 名而遗留环境名连接。旧 v1 和此前 Codex v2 可由本版读取，但旧 Codex 专用 v2 实现不负责读取两端新 v2 备份；不以用户改环境名替代受管迁移，也不删除记录绕过冲突。

客户端目标已外部删除时，旧写后指纹与真实缺失前像不同，检查不提供旧备份恢复入口；重新接入须用户预览确认。恢复本次重新添加会还原到“缺失”，不会复活历史已删除条目。回退此次缺失重建修复，旧程序可能再次把历史受管目标的缺失当作外部修改而拒绝接入；回退前用本版按需预览移除/恢复本次连接，退出授权并在所用版本重新核对，不能靠删除 Hub 记录强制接管同名配置。

桥端口改变需要后台重新绑定并重新核对/接入各客户端保存的 URL，不能把旧地址仍然当作可用入口。配置 root 改名、复制到其他 Windows 用户或电脑、回滚到不认识 NVWA 的旧版本，均不能推定 DPAPI/Keychain 引用会跟随恢复。回滚前先通过本版定向移除或恢复所需受管条目、退出授权，再保存非秘密 profile；旧版不负责加载本机桥，新版存储不并入旧模型配置。

本轮新增的 MCP 路径值不被此前仅接受完整 URL 的 NVWA 版本理解。回退此路径功能前，应将已存的 `/mcp` 或其它路径解析为明确的完整 HTTP(S) MCP 地址并保存，再按原流程处理授权和客户端条目；默认空值继续兼容。旧完整覆盖地址不需要自动改写。

回退此前期限修正后，旧程序可能仍按密码初次登录绝对期限判断失效，且不提供新的固定/闲置状态说明；新增 `expiryPolicy` 只在系统保护快照中，普通环境格式不变。回退前退出授权并在所用版本重新认证，不把新策略字段或旧恢复记录当作已完成跨版本会话验收。

此次按需续认证修复沿用普通配置 version `1` 和 DPAPI/Keychain 秘密存储格式，不新增明文秘密或迁移记录。回退该修复可能恢复身份核验 401 直接清除登录、直连工具检测未统一失效标记及自动失败无 60 秒冷却的旧行为；届时仍须人工重新登录。回退前正常退出 Hub 并在所用版本重新核对身份和授权，不重放此前失败的工具请求，也不把存储格式兼容当作跨版本运行会话已验收。

回退本轮恢复机制前，先在新包退出登录清除已认证或挂起的锚点；旧包不负责按 `schemaVersion=2/authScopeFingerprint` 的新规则恢复接入，也不承诺兼容 `pendingIdentity`，重新登录或保存更名可能再次撤销原接入，须按所用版本重新核对和预览接入。普通环境集合仍 version `1`、客户端受管记录与定向备份格式不变；不得手工修改指纹或复制客户端秘密绕过恢复。回退客户端下拉只恢复三端独立控件，临时路径/结果缓存不迁移，后台记录和隔离不改变；不重放已失败或结果未知的工具请求。

回退此前页签界面改动后，旧包仍按原页签名称和显示规则工作，不提供新的按钮/工具说明。此前 Codex 环境名阶段的原 v1 ledger 与单目标备份可由后续包读取，Codex version 2 定向多目标保护备份只由支持该格式的包理解；当时 WorkBuddy/天工仍沿用 hash 名。回退前用对应新包检查并按预览移除或恢复环境名连接，避免旧程序只识别旧 hash 名而遗留新项；最新引用与完整目标指纹仍需一致，不能把改环境名称当作直接修改任意客户端项。当前三端统一及其回退边界以上方现行规则为准。
