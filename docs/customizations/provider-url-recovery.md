# 大模型地址缺少 /v1 时自动修正

维护日期：2026-11-07。适用版本：`v0.4.30-13`。关联 TC-015。
实现状态：已实现；隔离验证、构建和测试包身份见 [v13 交付](../releases/v0.4.30-13.md)。真实服务及 Windows/macOS 客户端行为待用户验收。

## 当前行为

普通 API 渠道保存时只清理首尾空白和末尾 `/`，不再凭地址外形直接补 `/v1`。请求先使用用户填写的 Base URL，加上协议对应的 `/responses`、`/chat/completions` 或 `/messages`。例如填写 `https://example.invalid/proxy`，先请求 `/proxy/responses`；明确返回 HTTP 失败后，再尝试一次同源的 `/proxy/v1/responses`。

补版本的请求沿用同一模型、请求体、鉴权与协议，不切换提供商。补版本成功并确认是对应协议的有效结果，才保存该渠道的 `/v1` 地址；后续请求直接使用保存后的地址。两次都失败，保留原地址、原 HTTP 状态和错误正文。原地址成功时只请求一次；连接超时、响应状态未知、请求体无法重放或已开始的成功流，不额外换路径重放。原有传输重试和 WorkBuddy/天工 502/503 同地址重试保留，补版本至多额外一次。

运行时适用于普通 API 的 Responses、Chat Completions、Anthropic Messages，以及可重放的图像/搜索 HTTP 操作。ChatGPT 账号渠道使用官方固定地址，不参与；WebSocket 握手不参与。已有 `v1`、`v2`、`v1beta`、`v4` 等显式版本路径不叠加 `/v1`。包含查询参数、片段、URL 用户名密码或已填完整操作路径的地址不猜测修正；合法路径前缀保留。

## 成功确认与保存

- JSON 结果检查协议字段和错误状态，网页、错误 JSON、空对象不能作为成功证据。验证读取最多 32 MiB；超过时本次候选不作为成功结果，返回保留的原错误，不保存地址。
- SSE 先检查有效协议开始；首事件错误或无效正文返回原错误。开始交付后保留原字节，只有观察到对应协议的有效终态才保存；中断或错误不保存，也不重发已经开始的流。旁路验证最多 32 MiB、单事件 1 MiB；超限只放弃自动保存，不截断已交付的流。Responses 使用有效 `response.completed`，Chat 使用结束原因和 `[DONE]`，Messages 使用 `message_start`、结束原因和 `message_stop`。
- 补版本响应发生重定向时，不据此确认新地址。原错误先有限读取并保留；超过 1 MiB 或读取不完整则放弃补版本，继续交付原错误。
- 保存前在内存锁内重读磁盘配置，要求同名渠道唯一、全部字段仍与请求发起时一致，再沿用文件锁、revision 校验和原子写入。迟到结果不覆盖删除、改名、换 Key 或其他渠道修改；无关设置保留。保存失败不使已成功的调用失败，下次仍可能重新探测。
- 天工的非流式整体截止时间继续有效；补版本探测共享其剩余预算，并预留原错误返回时间，避免候选超时将已取得的原错误变成外围超时错误。剩余时间不足时直接保留原错误。

每次只修正被实际验证的渠道。WorkBuddy/天工的专用副本与普通来源仍按 [渠道用途与同步规则](client-channel-scope.md) 隔离，不按相同 URL 批量改写。

## 模型目录入口

“大模型接入”原有获取目录流程使用同一规则：先 `/models`，再 `/v1/models`；两者均失败显示原地址错误。编辑窗口获取成功只更新表单，点击保存或空模型保存的自动获取流程才提交。Codex 可见模型页获取成功时仅将已确认的 URL 修正保存到对应渠道，可见模型列表仍需用户按原流程保存。

显式配置独立 `modelsUrl` 或智谱专用目录时，目录成功不能证明对话 Base URL 也应改变。网页导入继续使用主站指定且校验过的模型目录，不增加兑换/导入目录重试，不跟随这些接口的重定向；导入地址保留主站合法路径，实际模型请求按上述运行时规则处理。

## 配置兼容与身份

`ProviderConfig` 新增可选 `baseUrlRepairOrigin`，默认不存在，仅在验证成功的自动修正时记录原 Base URL，不含额外凭据。只有该原地址追加 `/v1` 正好等于当前地址时，路由、私有推理内容范围及天工历史回放使用原身份，确保修正前后工具续轮可匹配。手工换其他地址、模型或 Key 的原有隔离规则继续生效；不能把任意同站路径视为同一服务。旧配置无需批量迁移。

## 回滚与验收

回退前退出 Hub，备份 Hub 配置，再使用保留的旧包。旧版本可忽略可选来源字段，已修正的 `/v1` 地址可继续使用；旧版不保留此自动修正身份语义，必要时使用回退前配置备份并重新开会话。客户端专用渠道的定向撤销仍核对完整快照，修正后的渠道视为发生过修改，旧备份可能需要先核对再处理，不绕过变化保护。

本轮只允许临时配置和本机合成 HTTP 服务的隔离回归、构建及安装包静态核验，不启动产品、安装器或真实模型调用。用户需验证原地址可用、缺版本后修正、双失败保留原错，以及流式回复后的工具续轮；macOS 本轮未原生构建或实机验收。实际结果集中记录在 [v13 交付](../releases/v0.4.30-13.md)。
