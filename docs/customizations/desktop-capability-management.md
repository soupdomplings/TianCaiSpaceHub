左侧默认三端依次为 ChatGPT(Codex)、WorkBuddy、天工 Work；访问或成功配置已在这三个位置中的客户端时不重排，只更新使用记录。列表外端进入时替换最久未使用的那个位置，其余位置不动。收起时“⋯”在第三端下方；展开后该按钮隐藏，“客户端”标题右侧显示“收起”。原型仅用合成内存，正式版需用 Hub 自己的记录，不以资源网格排序改动导航。常规只列已发现或已配置端；显式八端容量场景才加入 A–E 规划占位，不列 Magpie 全部 74 名。

全局公共页不继承上次客户端，添加时仅以最近端作为可更改的初选，不据此默认多端应用。Skill 与通用 MCP 固定可见，空状态直接添加；建议 `showDumplingMcp=false` 只控制 MCP 内部的 Dumpling 入口，隐藏不撤销连接。这个入口语义尚未实施，现产品仍按旧行为；原型默认展示 Dumpling 便于评审。窄窗保留文字导航、键盘路径与合理滚动，不扩展 Linux 支持。

## 状态概览如何保留完整信息

全局运行图显示“当前活动客户端 → Hub → 使用中的模型 → 使用中的渠道”。已打开或有进行中请求的端出现；模型和渠道只在请求进行中出现，结束后成对退出，记录继续保留。客户端已关闭且闲置时不占图，无活动端仅保留 Hub。完整配置在客户端管理页，不把历史配置铺进运行图。

- 运行图移除客户端/打开数量/模型/渠道的整行列标题，空间留给节点与线路；名称、必要状态和详情入口保留。
- 模型/渠道逐行配对，常规模型节点最高 200 CSS px，宽度不足时收紧；长名可查看全文。线路按实际节点中心测量，不加节点拖拽。
- 归属按 scope / entry / model / source 确定；同名不合并不同专用身份。普通入口无法归到具体进程时保持未知，不因为 Codex 打开就算作 Codex 请求。
- 点选只高亮关系，其他活动端仍可见；Codex 执行状态并入本端详情，不另设重复卡片。
- 连线只有新鲜进行中请求才流动；失败、终态、空闲、读取失败和 Hub 不可用停止，恢复后等待新证据。全局暂停与系统减少动态效果适用。
- 默认演示三个已打开客户端、一条 WorkBuddy 请求；“全部关闭”仅 Hub；八端容量中的 A–E 为规划占位，不代表已适配。

已打开、接入配置、本机服务、上游目录、真实请求和外部执行分别取证。内部摘要仍需观察时间和明确来源，缺字段显示未知；不能用动画、文件存在或某一次成功替代其他证据。当前 dashboard/remote/IM/client_overview 只能提供部分数据，新观察字段仍待产品实施。

## 客户端状态与请求、渠道的范围

客户端标题旁显示短状态：已打开、空闲、处理中、未启动、接入需更新或未知。正文改为六个可点击节点的概览图，不再一行一行列状态卡：

```text
客户端 ────── 天才 Hub ────── 模型
  ┆               ╲              │
Skill             MCP         聊天与执行
```

默认三端已有配置：空闲时模型节点显示该端使用数量，有请求时显示进行中数量；Dumpling 连接纳入 MCP 摘要。模型数量来自配置，不是请求成功证明。天工 Skill 显示适配待核实，聊天执行仍可能待授权。首次接入是顶部显式合成场景，页面提供“查看已配置示例”；新建 Dumpling 环境不再改变全局场景或令所有客户端显示未接入。

上排表现模型请求链路，下排表示本端扩展与执行关系；Skill/MCP 用静态配置关联线，不暗示它们的所有调用都经过 Hub。点客户端/Hub 看简短证据，点模型进入本端模型，点 Skill/MCP 进入本端开关，点聊天与执行看账号/执行详情。配置不等于实时请求，只有有证据的进行中模型链路流动。

Codex App / VS Code / CLI 在执行详情中分别判断，不用其执行连接证明普通模型归属。WorkBuddy 明确外部执行尚未接通；天工的模型、本机请求、执行授权和桌面消息同步也分别判断。运行图和客户端页使用同一组 `review3ClientEvidence` / `review3CodexEvidence` 合成观察，产品检测能力未扩大。

模型/渠道点击“进行中请求（N）”时，按完整路由先列请求集合，分页选具体记录，不自动挑最后一条。列表不继承无关统计筛选，记录详情可回集合；原请求日志列表/详情不改。渠道“查看配置”直达普通来源或精确专用条目，缺快照则说明未读取，不拿同名渠道替代。

## 模型添加与生效方式

我的模型只管理模型与来源，去掉客户端分配、客户端参数标签及已加入客户端筛选。客户端“模型 → 从我的模型加入”已带目标；其他端模型行可“用于其他客户端”。兼容新增直接保存并显示“使用中”，已有差异才处理；各端参数独立与来源选择同步保持。

不再在成功后显示“已保存、待写入、待加载、待调用”等多阶段结果。内部仍必须真实保存与读回；读取失败/写入失败保留旧选择。仅当某客户端需要用户继续操作时，在当前页给一条可操作提示：

| 内容 | 具体下一步 | 现行依据 |
| --- | --- | --- |
| 天工模型 | 无需重启，在客户端选择使用 | [天工](gmclaw.md)，保持 `restartRequired=false`、`makeActive=false` |
| WorkBuddy 模型 | 若客户端没有显示新模型，重新加载配置再选择 | [WorkBuddy](../workbuddy.md)；不同版本的文件监听和重新加载须实机核对，不统一承诺自动热加载 |
| Codex 可见模型 | 按原流程退出后通过 Hub 增强启动 | [动态模型](../dynamic-codex-models.zh-CN.md#使用方式)；原 preflight、运行实例与退出等待保持 |
| Skill / 通用 MCP | 目标确需重新打开、授权或信任时给相应入口 | 由真实适配器按版本/传输报告，不能从天工模型规则推导 |
| Dumpling | 保留原一次“连接并检测”与必要认证 | [NVWA](nvwa-mcp.md) |

“使用中”表示本端配置选择/包含这一项，不表示正在执行请求；不为验证开关而自动发模型/工具调用。模型停用只处理本端配置，不取消进行中请求、不删来源和其他端；读取失败、占用、并发后改时保留原选择，必要时重核后确认。

原型上述动作只改内存，不写真实配置，不安装、不授权、不重启。正式保存、生效、日志的业务证据仍保留在后端和详情中，普通使用路径无需逐项确认这些阶段。

## Skill 管理：选择客户端就使用

首期为紧凑资源列表：名称/必要描述、使用客户端图标与数量；点击摘要打开图标网格，3–4 端直接显示，更多端按需展开搜索。客户端页直接操作本端；点名称查看来源、SKILL.md、资源和依赖。读取原有技能后展示本端使用选择，外部内容独立，同名不同内容不合并。Hub 的索引与受管记录属于内部机制。

客户端选择采用每行 2–4 个的紧凑图标网格：图标在上、名称在下，单块最大宽 124 CSS px、最小高 84 px，图标容器 26 px；不再横向撑满弹窗。点击已有资源的目标后，配置成功才点亮；使用中的排在前面，组内保持原目录顺序；再点并成功停用后变暗。失败不改旧选择和顺序，读取失败保留上次选择并禁用修改。这个排序只用于资源选择网格，不重排左栏。新增表单的勾选只是目标草稿，一次“添加并使用”成功后才成为实际使用。

新添加在一个弹窗中选择本地目录或仓库、必要内容与目标，点击“添加并使用”。从客户端页发起锁定当前端；全局少量目标直接显示网格，更多端按需展开搜索。依赖或覆盖只作必要决定后继续任务；失败保留草稿。Skill 目录作必要非空校验、仓库作 HTTP(S) 校验，不冒充真实仓库拉取、SKILL.md 解析或资源安装。

正式适配要求：

- 默认独立副本，来源版本/内容指纹与资源清单可定位；来源更新选择同步，端内修改保留。不直接照搬 Magpie 默认链接和副本反向回收。
- 用户级/项目级按客户端真实能力开放；项目显式指定，不能用 IM 最近目录代替。客户端、安装身份、scope 和规范化路径共同定位。
- 导入保持资源相对关系，不越出根目录、不制造残缺副本；缺依赖给一次“同时使用”决策，不静默执行脚本或安装运行时。
- 关闭开关只禁用/移除这个端的一项；客户端没有原生禁用能力时，通过受保护移除并保留恢复内容实现“未使用”，不伪造原生 disabled 字段。
- 外部原有内容不因显示在列表就被接管。明确停用时一次说明备份/移除范围；后改或冲突保留原内容。删除公共定义与停用单端是不同维护范围，不挤入日常步骤。

## MCP 管理：直接配置到所选客户端

管理页为“工具服务 / Dumpling-MCP”，普通服务使用资源列表与客户端摘要。添加服务而非逐个手填工具，工具由服务提供。

2026-11-08 用户进一步提供天工 Work 和 ChatGPT 配置截图，明确需要完整配置表单；前两轮用途三选一、单粘贴框首屏均被否定。**当前默认打开“表单配置”，旁边是可编辑的“JSON 配置”页签**，不是将完整表单藏在手动或高级入口。两种视图共享同一份内存草稿，客户端选择与“添加并使用”在同一窗口。

| 区域 | 当前合成原型的字段与操作 |
| --- | --- |
| 基本资料 | 服务名称、可选简介；不设置用途三选一或必填分类 |
| 连接类型 | 显式选择 Streamable HTTP、STDIO 或 SSE；默认 HTTP，不自动替换导入的 SSE |
| 远程服务 | 服务地址；无需认证 / Bearer Token / 自定义请求头；按选择显示 Token 或认证头名称和值；Headers 键值行可添加、删除 |
| 本地服务 | 启动命令或程序路径；参数逐行添加/删除；环境变量键值行；传递的环境变量名称；可选工作目录。命令与参数分离，不需拼完整 shell 命令或手写参数数组 |
| JSON 配置 | 可编辑单个服务对象或 `mcpServers`；表单生成 JSON，JSON 切回表单时解析字段，也可直接添加使用；多服务先明确选择当前要添加的一项，不默认取首个 |
| 使用客户端 | 同窗紧凑图标网格；全局可选端，从客户端页添加则锁定本端；草稿选择不冒充已使用 |
| 已有配置复用 | 默认折叠的“从已配置客户端复用”，沿用原服务身份，不创建同名重复定义 |

未填完的地址或命令也能切到 JSON 继续编辑，最终添加时校验完整性。格式或结构有误留在 JSON 视图并保留原文；重复键值不能无损转为 JSON 时留在表单，明确提示合并。多服务选择可返回原 JSON 修改。切换 HTTP/STDIO 保存各自草稿，不把远程凭据带入本地；同一传输内认证变更清理旧的专用凭据。帮助收进页签旁的“？”，普通字段直接可见。

导入保留 `command/args/env/env_vars/cwd/url/headers/type`、可选资料及未编辑的附加字段，JSON 包装层的附加字段在视图往返时也保留。Windows 路径、空参数及 `${...}` 保持字面值；不读取真实进程环境、不执行命令。常见 Bearer 头填到认证字段，未编辑时保留原大小写，避免重生成改变内容；重复请求头按大小写无关检查。完整 JSON 是可迁移草稿，不代表所有客户端共用同一原生结构；正式适配器必须映射字段并核实支持，不能静默丢字段或换协议。

成功才点亮并让使用端排前；读取失败、revision 冲突或占用保持旧选择与已填内容，部分成功只重试失败端。普通页面不新增保存/加载/调用多阶段。Dumpling 继续下面的环境与 NVWA 流程。

参考事实见 [研究记录](desktop-ui-research.md#mcp-添加流程对照与本机天工核对)：Magpie 与天工均有表单/JSON；用户 ChatGPT 截图补充逐行参数、变量传递与工作目录。采用配置能力，不照搬天工强制分类或长说明。通用 OAuth、运行时安装与真实客户端原生写入仍未实施，全部交互仅合成内存，不读取用户配置。

MCP 不能无差别复制 JSON：各端的 stdio、Streamable HTTP、旧 SSE、变量语法、凭据引用、项目范围和信任规则需分别验证。未适配的资源提供具体原因，不把未知当作客户端不支持；不能静默换协议或新建桥。新增本地命令配置不执行该命令，不自动下载包或运行时。模型 Key、IM 授权与服务认证不相互借用。

普通页面仍只呈使用选择；缺授权、客户端要求信任、配置读取失败才显示具体问题和继续操作。协议检测、目录读取和真实调用证据留在诊断详情及日志，不把它们当成每次使用必须点击的检查列表。停用被 Skill 依赖的服务时，先决定是否一并停用依赖项，不能偷偷让另一项失效。

### Dumpling-MCP 如何保留

Dumpling 按现行 [NVWA 专题](nvwa-mcp.md#操作入口与状态) 补齐“配置环境 → 登录/授权 → 连接客户端”。环境选择旁直接编辑/新增；配置不再藏在只有说明文字的弹窗中。

- 账号密码：账号、明文密码、记住密码。
- 认证服务连接：ClientID、明文 ClientSecret、保存应用密钥；共享开关打开时填写代表账号，关闭时走浏览器个人授权。
- 高级：独立认证地址、MCP 路径或完整地址、认证头、租户；密码方式的登录机构、浏览器方式的限定账号、共享应用的 SHA-256/SM3/MD5。客户端自定义配置位置放连接详情，天工沿用官方本机设置。
- 主认证切换清理旧认证输入；共享开关保留应用资料。重新授权不沿用旧成功；环境改范围后须再授权，单改名称不强制失效。表单保存失败保留草稿。

以上为合成状态演示，正式版必须完整复用既有三种认证、挑战、秘密存储、独立身份和 prepare/preview/apply/detect/restore，保留旧值等价规则及并发保护。已授权仍是一键“连接并检测”；每端连接独立，授权成功不把全部端标为使用中。隐藏仅影响入口，不注销、不撤销。

客户端维护放断开/撤销，环境维护放编辑/删除整环境；凭据显示保存遵守原约定。通用 MCP 管理不会把 Dumpling 退化为 URL 文本模板，也不会因为普通页简化文案而删除检测证据或原保护。

## 下拉与目标选择规范

全原型的单选下拉统一圆角、留白、箭头与弹出层，长列表（至少 6 项）显示搜索；保留原值和 change 语义。方向键/Home/End 选择，Enter 确认，Esc 收起，Tab 继续，禁用项不可选；弹窗内弹出层保持在同一顶层，按屏幕边界调整方向。减少动态效果和深色主题共用变量。只有明确多端使用时才出现按需展开的多选，来源同步只列实际有差异的端。

现 vendor 有 Choice/ComboBox/ListBox，尚未核实完整可复用的原生自绘弹出层绑定。正式版应先验证 wxDragon 公共选择组件在 Windows DPI/键盘/辅助技术和 macOS 中的表现，再决定局部绑定扩展；不能声称 HTML 控件可直接移植或系统弹出列表已美化。

## 共同的领域与适配层〔建议，非现有接口〕

正式实现以 [可复用接口合同](desktop-client-adapters.md#4-推荐给-hub-的正式实现待原型确认) 为准：`discover/read` 返回原生配置事实与新鲜度；`ClientCapabilities` 分类型/版本报告能力；`set_use` 共用内部 plan/apply 编排；`restore` 定向恢复。GUI 的开关、添加和客户端页共用同一个领域服务，不复制一套业务。

| 内部对象 | 内容与保护 |
| --- | --- |
| CapabilityDefinition | 稳定身份、内容/服务定义、来源、版本/指纹、依赖和凭据引用；不因编辑公共定义就改所有独立副本 |
| ClientInstallation | 目标安装身份/scope/项目、精确目标、归属、写前/后指纹与备份；配置事实与请求证据各自保存 |
| ClientAdapter | 只读发现、格式/传输/作用域、内部规划、应用、停用与恢复；真实能力决定可选目标 |
| SetUseRequest / Plan | 资源引用、使用意图、目标、最新 revision、必要决策和操作代次；无争议计划自动执行，冲突才请用户决定 |

格式处理分开，原锁/revision/定向备份/原子替换/后改保护保持，未知字段/注释保留。多文件/多端无统一原子事务：成功端保留，失败只重试该端，结果未知先读回，不显示虚假“全部回滚”。操作完成后从真实结果更新选择，不能点击即提前标成功；读取失败不把原勾选清空。当前没有这些统一管理 API 或 schema，不在纯原型中迁移旧配置。

## 实施顺序与回归增加项

1. 原生导航、公共布局、运行/客户端概览图和 Codex 设置先验证；明确每项原能力去向。
2. 模型来源、直接保存/跨端独立复用与差异同步闭环，继续原模型 API 与专用路由。各端需要重新加载时给具体下一步。
3. 新增 Skill/MCP 领域和受管记录，先做一端完整链路再逐端开放；Dumpling 接合原适配。新客户端按 [建议顺序](desktop-client-adapters.md#5-新客户端的建议顺序) 分开实施，不把协议和 UI 一次整体替换。
4. 聊天、日志、历史/修复与系统窗口收口，Windows/macOS 分别验收。下一次实际功能构建核对版本后递增，不覆盖 v13。

新增回归覆盖：发现/读取/禁用状态、同名异内容、多安装/作用域、资源与路径边界、依赖/认证/信任、幂等/连续点击、占用/并发/后改、定向备份恢复、分端失败/结果未知和取消/迟到；模型请求与配置使用分离，原始日志和 Dumpling 认证链路保持。完整场景组见适配研究，不以开关原型通过代替产品测试。

## 页面常驻说明收敛

页面只保留数据、使用选择、必要状态和操作。统一圆形“？”按当前页面/子页说明按钮、范围和规则，不切页、不提交草稿，关闭恢复焦点。帮助保留统计分母、缓存/时区口径、独立复用与能力边界；编辑、冲突和认证时再说明本次影响。技术路径、协议字段和受管标识放详情/高级区域。普通页面不列保存/加载/调用进度，错误也不能假装未使用。
