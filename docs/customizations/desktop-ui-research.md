# 桌面 Hub 参考研究与讨论建议

研究日期：2026-11-07。项目基线：唯一 `main`，HEAD `25d024b2baa6af25f66bd69d5b237e0caa35df80`，Cargo `0.4.30-13` 加既有未提交开发。状态：**研究建议已形成第三稿合成原型，尚未实施到产品**。公开资料事实、Hub 源码事实和设计建议分别记录；跨端独立复用策略获用户确认，用户随后要求制作原型；原型效果仍待评审。

用户指出第 2 稿把运行连接状态当作概览主体，缺少用量统计与波动趋势。本轮先研究 Magpie 等管理工具的公开截图、文档和相关源码，再讨论布局与配置复用；没有安装或运行这些软件。

## 已确认的跨端复用策略

2026-11-07，用户针对跨端复用后的更新方式明确回复“按照你推荐的来”。据此确定：

- 默认复用一次，生成目标端独立且受保护的配置；各端可以分别调整模型参数，修改一端不联动覆盖其他端。
- 普通来源更新后提示差异，由用户选择需要同步的目标与改动，保留各端调整；不默认后台覆盖副本。
- 重新应用继续核对来源、条目身份、revision 和后改，复用现有备份与受保护保存；同名模型不作为跨端借配置的依据。
- “跟随公共配置”保留为后续显式可选能力，本次没有实现或默认启用。

这是产品规则的确认。第三稿仅模拟独立复用、参数调整与选择同步，不等于新产品功能或用户实机验收；Codex 继续使用普通路由，不能把可见模型当作单一来源专用条目。

## 2. 概览保留运行状态概览统计〔最新评审决定〕

全局导航建议叫“概览”，按用户最新要求页内“运行状态 / 使用统计”，运行状态置前且默认打开。运行状态改为多客户端同时汇入 Hub 的活动路由视图，证据收进行详情，取消重复矩阵与客户端切换。客户端页的接入设置、模型、Skill 与 MCP、历史与维护继续保留，ChatGPT 设置不会被统计页替代。

```text
侧栏                 概览                  运行状态 | 使用统计
概览                 今天 / 最近 7 天 / 30 天 / 自定义
客户端               接入点或客户端 · 模型来源 · 模型（联动筛选）
  ChatGPT(Codex)      请求数 | 输入用量 | 输出用量 | 请求完成率
  WorkBuddy          用量趋势：输入（含缓存）/ 输出，或请求数
  天工 Work          按小时或天；悬停看明细，点击时段进入请求记录
模型与渠道           模型用量排行                 接入点用量分布
Skill 管理           最近异常与处理入口           查看相应请求
MCP 管理             统计范围 / 数据更新时间 / 缺失项说明
聊天接入
请求记录
设置 / 帮助
```

这是内容层次示意；第三稿已据此制作合成原型，最终原生排版仍待评审。用户后续明确移除首字统计、输入输出分别显示且缓存并入输入，实际请求日志保留。

1. **统一范围**：时间、接入点/客户端、来源、模型同时影响指标、曲线、排行和明细。普通入口仍标“普通接入”，能够确认的 WorkBuddy/天工条目才标到相应端；未知归属不能猜成 Codex。
2. **四项默认指标〔按用户最新决定〕**：请求数、输入用量、输出用量、请求完成率。输入归一后包含缓存，不重复叠加或单列缓存数量；统计不含首字指标，实际请求日志保留原字段。可靠定价与覆盖率具备后再开放“估算费用”；账号余额、套餐额度另列，不能混成本地花费。
3. **主趋势**：默认输入（含缓存）与输出两条 Token 曲线，可切换请求数。不再统计首字或等待/耗时曲线。未采集区间保留缺口，不填假零值或用过度平滑制造数据。
4. **波动解释**：有可比数据才显示较上一等长时段变化；当天对比前一天相同已过时长。覆盖范围改变、日志清理或样本不足时说明原因，不展示误导百分比。
5. **下钻**：点击时段、模型或异常数量，带同一筛选进入请求记录；返回保留范围。取消、客户端断开、不完整分别列数；错误入口指向精确条目，保留已有修复流程。
6. **空与旧数据**：从未有记录、日志关闭、筛选无记录、读取失败分别表达。读取失败保留旧结果并标更新时间，不能显示“今日 0 次”；打开概览不主动发测试请求。

年热力图可作为后续选项，第一版优先小时/天用量波动和日志下钻，避免热力图占据主要阅读区域。

## 3. 统计的源码基础与缺口〔Hub 事实〕

| 已核对事实 | 实际限制 |
| --- | --- |
| [请求日志](../../src/ai_gateway/request_log.rs) 已有时间、模型、渠道、结果、输入/输出/总 Token、缓存、耗时、首字字段，存 SQLite | 有统计基础，仍须开发时间聚合、分组、覆盖率和 GUI；不是每种协议都上报全部字段 |
| [GUI API](../../src/gui/api.rs) 固定读取最近 200 条；[后台查询](../../src/ai_gateway/handler.rs) 只有 limit，底层最近列表上限 500 | 不能拿最近 200 条画今日总量或 30 天趋势，需要全范围聚合和分页明细 |
| 没有可靠的发起客户端进程身份，渠道用途能确认部分专用入口 | 首期统计接入点/条目，未来再加明确的入口元数据；历史未知保留未知，不按同名模型或 User-Agent 猜测 |
| cost_usd 可空；本轮核对的通用、专用入口和生图写入处均为 None | 不能直接显示真实账单金额；需要定价版本、映射、币种和有效覆盖率，缺价显示未知 |
| 有摘要/正文开关、写队列及丢写计数，也能清理日志 | 口径是经 Hub 记录且仍保留的数据；不是全机器使用量。统计不应要求开启请求正文捕获 |

建议增 summary、series、breakdown、分页 records 四类只读查询，共用范围对象和统计快照标识，保证指标、图表和明细一致。具体 API/schema 尚未设计或实现。

实施前约定口径：

- 请求按 Hub 一次逻辑请求计，上游重试另算；当前记录不足以还原每次上游 attempt，不能从最终结果反推调用次数。
- 完成率以有终态请求为分母，running 不进入；取消、断开、不完整另列并解释。没有独立证据时不称上游成功率。
- Token 未知不同于零，展示有用量记录占比；缓存按协议归一，不能在 total 上再次叠加导致重复。
- 按用户决定移除统计页的首字、等待与分位数指标；请求日志的首字、耗时、缓存和实际上游字段不变。协议缺失字段的现有解析行为也不在本轮修改；输入中缓存的归一规则在未来统计实现前按协议核实，不能简单把已有 input 与 cache 相加。
- 明确时区与半开范围，处理夏令时；进行中请求更新不能重复计数。
- 首期统计保留的请求记录，清理后反映保留范围；长期独立汇总及其清理语义另设计。
- 暂不自动读取 CLI 会话。以后若增加第二来源，必须标范围并去重，不能把同一请求的网关与会话记录相加。

## 4. 跨客户端一键复用〔推荐设计〕

我的模型保留模型与来源，不重复管理客户端分配或各端参数。添加入口集中在客户端“模型 → 从我的模型加入”，目标已知时直接选模型；跨端复用从原客户端模型行开始，不重复填地址和 Key。

**复用对象是来源引用、模型映射、公共参数与端差异；结果仍是各端独立、受保护的配置。** 不把 WorkBuddy 专用 URL 复制给天工，也不按模型同名借用渠道。现有副本的来源更新规则保持不变。

具体场景：WorkBuddy 模型给天工使用。

1. 原客户端模型行提供“用于其他客户端”，展开兼容目标，选择“天工 Work”即表达添加意图。
2. 程序读取原条目、普通来源和两端最新 revision，核对映射、协议、认证、参数与目标差异。已知目标和作用域不重复询问。
3. **兼容、只新增、无争议**：自动生成目标配置，经原受保护保存写入，反馈“已加入天工，打开客户端后使用”；相同受管配置跳过，失败保留草稿。
4. **需要决策**：同一面板只展示差异及必要选项，如目标已有不同配置、来源已更新、缺凭据、强度不能映射。处理后应用，不强迫每次走固定多页向导。

“一键”指选明确目标后自动完成读取、预检、转换、备份、保存与反馈，不省略必要认证与冲突决策。配置完成仍不同于真实调用成功；本轮没有写入真实配置。

| 情况 | 处理建议 |
| --- | --- |
| 普通来源已改，WorkBuddy 副本仍旧 | 展示当前值与来源最新值的差异。现有保存 API 使用普通来源最新值；如需保留旧来源值，应先显式建立可用的普通来源，仍须满足认证限制。不能暗取专用副本秘密或悄悄切来源 |
| 来源身份缺失、删除，只留下同名模型 | 保留草稿并选来源，不按名称借别的 Key/账号；当前部分元数据只是来源名，实施需身份与指纹方案 |
| ChatGPT 账号来源用于天工 | 保持天工现有排除规则，说明原因，提供选择兼容来源的入口 |
| 目标不支持参数且 Hub 不能转换 | 展示差异并选择处理；不静默换模型/协议或把 max 降成 high；有选项不等于上游支持 |
| 给 Codex 使用但普通路由有多个同名候选 | 保留权重、粘性等规则；如承诺指定来源，必须另核实/建立明确映射并预览影响，不能只加可见模型就宣称锁定来源 |
| 配置被用户或客户端后改 | 延续 revision、锁、指纹、备份、原子替换和后改保护；冲突返回差异面板并保留草稿 |
| 多端部分失败或结果未知 | 逐端列结果，失败只处理该端，未知先只读核对；不重复写成功端，不虚报全部回滚 |
| 客户端运行或需要重新加载 | 沿用原预检，给明确下一步；不强杀、不自动重放真实请求 |

“以后全端自动跟随”是另一种同步策略，应显式选择受管范围并保留端覆写。用户已确认首期采用 **复用所选配置一次，各端独立调整，来源变化提示差异**，保持已有同步契约。[隔离规则](client-channel-scope.md)、[WorkBuddy](../workbuddy.md)、[天工](gmclaw.md)。

## 5. Skill / MCP 与使用方案〔推荐设计〕

按用户最新决定，两类管理采用资源列表与各客户端“使用中 / 未使用”开关；已有内容选端即用，新内容一次“添加并使用”。程序自动读取、核对、转换和受保护保存，用户不必分别完成收藏、写入、加载、调用检查等步骤。失败保留旧选择和草稿，缺授权、依赖或发生冲突时才展示必要决策并继续原任务。

程序需要读取客户端的原生配置和技能目录，让已有条目也能直接管理。同名不同内容保持独立身份；MCP 按传输/认证/作用域转换，Skill 保留完整资源与依赖，不做万能 JSON 复制器。多端结果真实反馈，成功端不因另一端失败被撤销。正式管理领域尚未实现；原型只模拟内存选择与固定原生条目，不读取用户配置。详见 [管理规格](desktop-capability-management.md)。

Dumpling 继续原环境认证与 prepare/apply/detect/restore，保留一次连接并检测。正常资源管理不列多阶段状态，但诊断、日志、实际请求证据和写入保护仍保留；确需重新加载或客户端信任时就近给具体入口，不承诺所有端自动热加载。

后续“日常编程 / 资料研究”等命名使用方案可组合引用模型、Skill、MCP，先证明单项操作可靠再做。跨端仍为独立副本、选择同步，不照搬 Magpie 默认链接与副本反向回收，也不承诺跨端原子事务。客户端可用能力与外部模型入口详见 [Magpie 深入研究及适配合同](desktop-client-adapters.md)。

## 6. 布局与视觉〔推荐设计〕

- **固定结构**：侧栏分概览、客户端、共用资源、记录、设置；正文一行标题与主操作，下一行页内导航或筛选。概览不常驻每页上方。
- **密度**：客户端/模型用同一平面的紧凑列表和分隔线，汇总指标可合成横条；编辑进入详情区，减少卡片套卡片。
- **层级**：直接选择模型、加入目标或打开客户端；技术内容归接入设置/高级参数/历史与维护。低频动作按对象收纳，不能只靠无文字图标表达不同写入范围。
- **样板数值**：以 DIP 为单位，侧栏约 196–216、内容边距 20–24、行约 48–56、控件约 32–36；正文系统字体 13–14、标题 18–20、按钮圆角 6–8、内容面 12–14；汇总指标移除外框，减少嵌套边框，用留白、浅底色和很轻的阴影分组。Windows 与 macOS 系统字体分别验证。这些只是初始样板值。
- **颜色**：单个品牌强调色，状态有文字/形状；图表序列颜色与结果状态色分开。浅深色共用语义，网格弱于数据，避免大面积渐变与彩线抢主次。
- **窗口**：按可用 DIP 从两列变单列；1366×768、1920×1080、缩小窗口和 100%/125%/150% 作为 Windows 验收组合。筛选换行、指标变 2×2，重要操作保留可见，不靠缩小字体塞内容。
