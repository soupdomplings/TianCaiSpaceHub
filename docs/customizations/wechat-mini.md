# 微信小程序与手机配对

2026-11-20 用户确认尚未注册小程序。开发者工具内的预览、自建服务部署、微信体验版上传、真机配对和真实到账分别验收。体验版需要已注册的 AppID 和小程序管理员的上传权限。[小程序项目](../../miniapp/) · [中转服务](../../mobile-relay/)

## 远程连接

在目标电脑开启 Hub 的远程连接，从配对页生成手机二维码。用户在小程序里扫码，再回目标电脑确认手机。此后设备在线且客户端就绪时，可使用手机流量查看会话、继续对话、处理审批与追问、下载产物。手机端清除本地数据或更换手机后重新扫码。电脑可撤销已配对手机。

二维码里的每次配对密钥仅在本机生成，手机扫描取得。Hub 将设备令牌、配对密钥和已提交写请求记录放入系统保护存储。小程序中转服务管理微信身份、设备关联和在线状态，转发 AES-256-GCM 加密的请求与响应。设备、请求标识和方向绑定在认证数据中。公网服务域名由运营方配置到小程序后台和发行配置，桌面读取 `TIANCAI_MOBILE_RELAY_URL`。默认未配置时不会尝试注册或连接公网服务。

桌面仅用原有会话接口处理手机请求，模型凭据留在目标端，审批回复仍交给原始运行端。历史和新事件各自使用原有游标，实时过程沿用[网页显示规则](remote-web.md)。手机通过会话内已登记的文件标识分片下载产物。停用远程连接后结束手机连接任务。需要回退时可在电脑撤销绑定、停用连接并保留原生会话。

## 界面、账户与验收

底部两个入口分别是「远程连接」与「天才小分队」。两端手机使用同一套 iPhone 风格分组列表、深浅色、输入工具栏和底部问答面板，支付使用微信收银台。个人公告、活动、余额及用量由站点账户提供，使用站点个人资料里的一次性绑定码授权。设备配对独立使用微信身份。

V1.0.58 起，四项「显示内容」勾选统一移到会话所在电脑（发送端）Hub 的「远程连接 → 设置 → 显示内容（本机发送）」，手机作为接收端跟随该电脑，不再提供本地开关，也不再使用旧的 `display` 缓存。小程序在进入会话时读取目标端 `history.displayContent`，随后逐条使用事件的 `data.displayContent`，同一批手机轮询内的设置变化也逐条生效。旧目标端缺少字段时按全关处理并提示更新。默认关闭时，新生成文件进入手动打开的产物清单；打开后，随后生成的产物可显示在对话中。历史阅读、用户上传的附件、原生追问及审批沿用各自的入口和权限。

测试分为本地演示和真实联动：没有 AppID 时，可用开发者工具导入本批提供的 `miniapp-preview/`，检查会话上方的 Hub 设置位置提示、手动产物和原生问答流程；演示电脑为合成数据，不会读取真实 Hub。需要验证 Hub 改勾选后手机同步，必须给正式工程配置真实 AppID、合法 HTTPS 中转域名，上传体验版后在手机微信扫码配对目标 Hub。单独安装 MSI 不会发布或更新小程序。具体目录与步骤见[V1.0.58 交付](../releases/v1.0.58.md)和[小程序工程说明](../../miniapp/README.md)。

生产部署需要同一合法 HTTPS 域名、微信登录配置和站点配套接口。平台开通虚拟支付且商品与站点报价一致后才可付款。统一服务核实微信订单身份、实付金额与支付状态，由站点的幂等到账流程更新余额。配置、部署和回退见[服务部署说明](../../mobile-relay/README.md)和[站点补丁](../../integrations/tiancai-squad-mini/README.md)。尚未注册时可在微信开发者工具中导入[本地演示工程](../../miniapp/README.md)，演示使用单独的合成数据。

Windows 定向测试已验证微信 JavaScript 生成的数据可由 Rust 解密、请求与响应的方向绑定、手机请求的路由限制、已登记文件的跨片读取以及配对控件状态。中转服务 7 项离线测试通过。站点补丁已在隔离源码副本实际应用，Go 路由和两个受影响 Vue 组件编译通过。正式域名、两台实机、真实微信登录与账款仍需注册和部署后验收。
