用桌面浏览器打开本目录的 `index.html`，无需安装依赖。页面只使用虚构数据，选择和对话只保留在标签页内，刷新复位。样稿本身不连接产品。已采纳的首批改动在 [V1.0.43 原生测试版](../../releases/v1.0.43.md) 中试用，具体范围见[桌面视觉专题](../../development/desktop-visual-system.md)；其余页面仍以各自的原生实现为准。

## 建议先试这三件事

1. **判断状态**：打开概览即看到请求趋势，在图旁从“今天”切到“近 7 天”。点击下方某个客户端直接进入，顶栏箭头可返回或前进。左栏五个客户端默认全部展开，可手动折叠分组。
2. **改一次配置**：在“模型与渠道”左边选择厂商，在右边点击模型名称或圆圈。选中的行显示蓝底对勾，顶部更新选中数量，点击“保存更改”才应用。客户端选模型也能点整行或用键盘空格切换。
3. **看操作影响**：“ChatGPT / Codex → 检查项目”，点击会话标题、目标项目或右侧圆圈都能勾选该行，底部实时显示将影响几条会话、几个项目。厂商模型、客户端模型和待恢复会话使用同一个多选控件。这里演示正向恢复，不混入备份撤销；取消不会归回任何会话。预览设置里的深色外观和减少动态效果是即时开关。

## 为什么这样改

现有 Hub 已经有浅深主题、短转场和统一反馈；迟滞感也可能来自加载或重建控件。建议先解决按钮、页签和卡片同样抢眼的问题，再检查哪些切换确实需要动画。

| 部位 | 示意与落地原则 |
| --- | --- |
| 导航 | 所在页由侧栏选中项和顶栏小号页名表示，正文去掉重复的大标题、分类标签和解释，只保留读屏标题。分组、列表和筛选使用同一块可中断移动的选中底色；普通操作按钮与多选框维持各自的交互。未展示的模块不代表要删除。 |
| 内容 | 概览用一条主趋势和五行客户端；模型页用“左选厂商、右改模型”；日志保留高密度表格。正文用实底，材质留在侧栏和浮层。 |
| 反馈 | 结果留在 Hub 窗口顶部中央的胶囊中，遇到窄窗时避开工具按钮。成功绿勾约 3 秒，错误展开具体原因，停留更久，可主动关闭；悬停或键盘聚焦暂停倒计时。需要决定操作范围时才用弹窗。 |
| 动效 | 底色在约 235 ms 内对齐目标的位置和尺寸，快速改选从屏幕当前帧继续，文字本身不缩放。分组在正常排版中伸缩，子项每隔 16 ms 依次显现。功能页换页约 145 ms / 2 px；筛选只换数据。浮层从入口展开，收起后保留对话。上述时长是样稿选择。 |
| 平台习惯 | 保留系统字体、系统窗口键位和 Windows 窗口控制；减少动态效果时直接呈现结果。没有模仿 macOS 窗口装饰。 |

参考 Apple [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 和 [Motion](https://developer.apple.com/design/human-interface-guidelines/motion) 对内容可读性、动效用途和减少动态效果的说明。

**体验连续导航**：快速点左栏“概览 → ZCode → 模型与渠道”，再在厂商列表来回选择。点击分组标题可中途逆向展开；收起当前项所在组时，底色落在组名，打开后回到当前项。顶部“工作空间”和“客户端”共用一个面板，切换时持续关联当前触发项。可以把鼠标移进面板继续选；移出或按 Esc 收起。键盘可用方向键切换组和条目，Esc 把焦点还给触发按钮。系统或预览设置启用减少动态效果时直接就位。

**辨认当前位置**：顶栏左侧只读出当前页面所属路径，例如“工作空间 / 模型与渠道”或“客户端 / 天工 Work”。右侧为两个独立的快捷分组，悬停查看另一个分组不会改变路径；前进、后退和助手跳转都会同步更新。

**体验助手浮窗**：点右下对话图标，默认浮窗为 446 × 505 像素，小窗时自适应。消息区可独立滚动，输入区固定在底部；右上角斜箭头可扩展到半个 Hub 宽且同高，窄窗则保留边距。收起保留本标签页里的草稿和消息，清空则开始新对话。Enter 发送、Shift+Enter 换行，输入法选词不触发发送。为便于评审，只提供本地模拟回复和两个快捷操作。

## 推荐实施顺序

第一批从共享的 `src/gui/theme.rs`、`visual.rs`、`motion.rs` 和 `shell.rs` 入手，只选概览和“检查与修复”作首轮原生验收。保持原生焦点、Tab/Esc、窗口拖动和托盘行为；数据尚未返回时保留框架和上一份可用内容，新结果到达只更新相关区域。Windows 在常用缩放和高对比度下优先实测；macOS 单独核对系统减少动态效果、颜色和焦点。玻璃材质不作为首轮依赖，系统不支持或需提高对比度时用同色实底。

确定控件密度、交互和刷新观感后，第二批将同一规范依次用到模型与渠道、客户端、请求日志、小分队和助手。复用已有 wx 原生窗口与后端，不因网页样稿引入 WebView 或改变配置、恢复及撤销逻辑。

**验证边界**：在 Windows 的 Chrome 中检查了浅／深色、四类页面、五端导航、选择保存、勾选归回项目、失败筛选、收起续聊、错误提示自动收起、窄窗口和减少动态效果。未运行真实 Hub、模型或安装器；原生 Windows 与 macOS 的最终效果留到产品实现后验证。

本次补查：取样快速改选前后同一块底色的位置，检查文字不动、变宽选项的最终宽度、折叠中途反向与后续栏目的位置、跨触发项和面板间隙时不收起、离开与 Esc 的收起及焦点、前进和返回。同步更新三张预览图。

后续浏览器评审补查：核对侧栏／快捷分组／返回后的面包屑，厂商列表整行及空格多选、计数与保存；助手的普通／半窗尺寸、草稿保留和输入；成功与完整错误提示均在窗口内，原生弹窗打开后提示仍可见，370px 窄窗不溢出。
