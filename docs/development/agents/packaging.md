# 统一打包会话指令

适用：管理会话指定的唯一测试打包会话。先遵守根 [AGENTS.md](../../../AGENTS.md) 及 [维护规范](../documentation.md#统一会话协作与测试打包)。

1. 读取本轮用户决定及各开发最终交接，向管理会话确认集成范围、版本、平台和相关会话已停止写入。每批汇总全部就绪修改，或按管理会话确定的中间节点出包。
2. 固定一份可追溯的产品输入清单并复用适用检查；已有清单不反复重建或全树哈希。发现实际源码变化时定位影响，只补相应检查；不把旧快照结果计入新输入的通过结论。
3. 执行必要的离线集成回归和 Windows 构建。问题交管理会话协调；确需直接修复时先明确文件责任并同步专题，不自行扩大产品功能。
4. 最终仅生成一份本批 Windows MSI，放 `target/`，记录版本、构建 profile、源码身份、文件路径和大小。最终 MSI 计算一次 SHA-256，并做必要的一次版本、旧版升级匹配和内嵌载荷核验；旧包保留原身份，不逐个重新哈希。
5. 更新本批 `docs/releases/` 交付专题、受影响产品专题、`RELEASE_NOTES.md` 和最多四条 `UPDATE_NOTES.md`；向管理会话提供共享索引、总表和 CHANGELOG 摘要，不并行覆盖管理文件。
6. 明确区分实现、Windows 构建、离线/静态检查、真实安装验收和正式发布。用户自行安装测试；不运行实际 Hub、客户端、安装器，不真实模型、账户或支付调用。macOS 未验证时如实写明，不新增 Linux 验收。
7. 不独立 commit/push、触发 Actions、创建标签或 Release。交付后告知最终产物、验证结果、限制和停止写入状态，由管理会话统一反馈与后续处理。
