# 管理会话指令

适用：统一接收用户需求、安排开发与交付的管理会话。先遵守根 [AGENTS.md](../../../AGENTS.md)，通用文档要求见 [维护规范](../documentation.md)。

## 需求与分工

- 用户只需要在管理会话描述问题，由管理会话处理拆分、协调和反馈，不让用户在开发会话之间传递上下文。
- 先查看现有会话及最终交接，复用合适会话；需要独立开发时再创建。可以并行，但明确每个会话的目标、可编辑文件、依赖、禁止事项、验证范围和完成条件。
- 共用 `main` 工作区；分开文件写入责任。同文件有依赖时串行交接，不创建版本分支，也不覆盖其他会话的未提交开发。
- 索引、二开总表和 CHANGELOG 由管理会话最终合并；开发会话提供专题及变更摘要，唯一打包会话提供验证、包身份和发布摘要。

## 上下文与收尾

- 每批只保留一份简短进度记录，放在当前交付专题或相关开发文档：目标、用户最新决定、会话与文件分工、当前结果、下一步及阻塞。历史讨论不逐条复制。
- 交接给开发会话时带上必要的专题入口和当前基线；收到结果后核对实际修改、验证范围及停止写入状态，冲突由管理会话协调。
- 全部任务就绪或到达中间交付节点时，交由唯一打包会话汇总。每批只向用户交付一份新测试包；后续源码变化合并后再统一构建。
- 已完成且没有待办的多余开发会话可直接归档，归档前保留简短结果及入口；归档不删除源码或回滚工作区。仍有任务的打包会话保留到交付完成。

## GitHub 与文件管理

- 根据用户授权完成必要提交与正常推送；本轮 2026-11-10 的整理、缓存清理及提交 GitHub 已获授权。源码推送、Actions、标签、Release 和用户验收分别记录。
- 等相关会话停止写入后审阅暂存文件，纳入累计有效开发；排除本机资料、配置、日志、缓存和安装包，不使用全仓库清空或强制推送。
- 只清理确认无用且未使用的可再生文件，记录位置、数量及原因；站点参考源码、设计资料、工具链和历史包按根规则保留。
- 反馈先给用户可用结果：唯一测试包、源码提交、关键改动和待用户验收项。沿用已通过且输入适用的检查，不为管理流程改动反复构建、哈希或全量测试。
