## 上游变化

- ChatGPT OAuth / `auth.json` 账号渠道、账号用量及令牌刷新。
- OpenAI/ChatGPT Responses WebSocket 及 Codex 初始化相关选项。
- 内置 GPT-6 Sol/Luna 等模型目录更新。
- 请求诊断改进及 Linux 分发文件名修复。

这些能力来自上游；本地二开的范围是衔接和保留以下定制。

## 二开衔接与保留

| 范围 | 整合结果 |
| --- | --- |
| 品牌与桌面 | 保留 TianCaiSpace Hub 名称、图标、打包身份、启动最大化及取消检查更新 |
| WorkBuddy | 保留独立渠道、配置备份、模型/别名选择、Claude 五档思考、缓存规则及 502/503 重试 |
| ChatGPT → WorkBuddy | 使用账号引用和刷新能力；不要求用户复制账号令牌，也不混成普通 Key 渠道 |
| 动态模型 | 保留手动模型、同步和远端获取、路由补齐及家族能力继承；补充账号渠道模型获取 |
| 通用 Chat Completions | 保留 `openai_chat` 和关闭推理开关，保持旧 DeepSeek Chat 行为 |
| OAuth 浏览器 | 启动能力独立于已停用的更新入口，保留 Windows URL 参数完整性 |
| 路由与配置 | 延续现有渠道隔离、优先级、会话路由及未知渠道保留行为 |

后续再次合入上游，应逐项对照 [二开功能总表](customizations/README.md)，并把这次新增的网页导入和配置并发保护纳入保留清单。

## 已有验证记录

原交付记录为 GUI 完整测试 839 项通过、0 失败、2 忽略，Windows GUI 开发构建及命令行启动检查通过；账号、WebSocket 及二开衔接有本地模拟回归。真实上游权限、账号能力和连接结果仍以用户实际验收为准。这些数字不用于证明后续 `0.4.29-2` 的改动。

## 回滚

备份配置后可回到本地整合前提交 `7f38f16` 构建对应版本。旧版本不具备新账号/协议能力；未知渠道保留机制不等于旧版可以调用新渠道。不得在新旧程序同时编辑同一配置时执行回退。
