## WorkBuddy 等待宿主的原因

WorkBuddy 5.9.3 使用 Electron 37.10.3。正式包的原生启动会过滤 `NODE_OPTIONS` 中的 `--require` 及其路径，并覆盖进程环境；后台进程继承到的同样是过滤后的值。V27 只核对了 JS 层继承和普通 Node 合成预加载，遗漏该原生入口限制，桥接实际没有加载，因此一直显示等待宿主。

本轮按受支持的临时主进程调试入口，在恢复原启动前为唯一后台管理器接上显式 preload，保留其原身份、环境、stdio 和重建行为；安装资源只读。具体机制、失败回退及实际验证以 [WorkBuddy 专题](../customizations/workbuddy-builtin-sharing-assessment.md) 和本页最终状态为准。
