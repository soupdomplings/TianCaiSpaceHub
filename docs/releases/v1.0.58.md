日期：2026-11-20（北京时间）。本批将四项显示勾选移到发送端 Hub，并同步调整网页和微信小程序；Windows x64 release、唯一 MSI 静态核验和独立小程序测试工程已完成。V1.0.57 原包保持原身份。源码基于 `main/68c2103ab0dc2654c0d66a8a1f9babb579b7b9a1` 加既有及本批工作区修改，尚未提交、推送或发布。

## 本批行为

在**运行原生会话的目标电脑（发送端）**打开 Hub「远程连接 → 设置 → 显示内容（本机发送）」，可勾选思考过程、工具执行、文件变更、产物。四项默认全关，点击后自动保存，重启后保留。控制的是本机向所有网页与小程序提供的后续内容。保存不重启组网，也不改模型、原生会话或配对凭据。

| 访问例子：A 查看 B 的会话 | 显示控制归属 |
| --- | --- |
| B 的 Hub：运行原生会话，是发送端 | 在 B 勾选，统一控制网页和手机收到的新内容 |
| A 的 Hub：打开网页，是接收／访问端 | A 的四项勾选只管 A 自己提供的会话，不覆盖 B 的选择 |
| 手机小程序：查看 B 的会话，是接收端 | 跟随 B，没有独立四项开关 |

两台 Hub 可以互相访问，发送／接收角色按当前查看的会话来源决定，不固定绑定某一台机器。切到 A 的会话时，改由 A 的发送设置生效。

网页和手机不再各自提供四项开关，而是提示设置位置。目标 Hub 在历史与后续事件中提供统一选择，从下一条实时事件开始使用。切换不补旧过程、不重读历史或重建订阅；已显示内容和历史、正文、审批、追问保持原规则。关闭产物时，新文件仍能在「查看产物／本会话产物」手动下载。旧浏览器和手机缓存不迁入 Hub，更新后在目标端重新选择；旧目标端缺少新字段时默认全关并提示更新。

维护入口：[Hub 页面](../../src/gui/remote_connection.rs)、[本机配置](../../src/remote_network/display.rs)、[事件投影](../../src/remote_sessions/transcript.rs)、[网页订阅](../../web-remote/src/use-session.ts)、[手机会话](../../miniapp/miniprogram/pages/chat/index.js)。协议与回退见[会话契约](../development/remote-session-contract.md)、[远程网络](../customizations/remote-network.md)、[网页](../customizations/remote-web.md)和[小程序](../customizations/wechat-mini.md)。

配置在 `remote-network/network.json` 增加可选 `displayContent`，旧配置默认全关，版本仍为 1。仅受信本机管理接口可写，网页与手机没有对应写路由。回退需要同时恢复目标 Hub、访问端内嵌网页和小程序；旧版保存网络配置可能不保留新字段，再升级时重新勾选。

## 电脑与网页验收

1. 从托盘退出旧 Hub，安装本批新 MSI，打开确认版本为 `1.0.58`。两台电脑都用于测试时，两端都更新；从访问端 Hub 重新打开会话网页。
2. 在目标 Hub「远程连接 → 设置」确认四项默认全关；网页与小程序只显示设置位置提示，已无自己的四项勾选。
3. 打开同一目标设备的原会话，运行一项会产生公开思考摘要、工具执行或文件变更的正常任务。在目标 Hub 勾选对应分类，核对网页和手机之后收到的同类内容出现；取消后不再追加该类新内容，先前已显示内容保留。
4. 关闭「产物」生成文件，核对手动清单仍可下载；再开启后生成新文件，核对新产物可显示。勾选前已开始的条目在完成时不补旧文件卡。用户附件、正文和原生追问／审批继续可用。
5. 重新打开旧会话，核对没有补出旧过程；重启 Hub，确认勾选保留。若测试两台不同目标，分别设置不同分类并核对它们各自生效。

## 小程序如何测试

**无 AppID：先看本地演示。** 用微信开发者工具「导入项目」选择本批的 `miniapp-preview/` 目录，使用游客模式或工具提供的测试号。进入「演示工作电脑 → 周报整理」，核对新设置位置提示和手动产物入口；发送一条示例消息后在「本会话产物」下载样例文件，原来的问答与拒绝动作继续可操作。这份工程使用独立合成数据，不连接真实 Hub，不能证明真实电脑改勾选后的手机同步。

**真实手机：需要体验版与中转服务。** 目前仓库 `miniapp/project.config.json` 仍为 `touristappid`，小程序服务地址为空。本批 MSI 不会自动注册、部署或发布小程序。已有真实 AppID 与 HTTPS 中转服务时，按[工程说明](../../miniapp/README.md)设置 AppID 和 `HUB_MOBILE_ORIGIN`、构建并上传体验版；手机微信打开该体验版，扫描目标 Hub「远程连接 → 配对」的手机二维码，并回电脑确认。进入原会话后按上节逐项核对。原手机绑定可保留，只有更换服务域名、清除本地数据或撤销后才重新配对。

正式小程序、桌面 Hub 和中转服务各自部署。更新 MSI 后，还应在开发者工具重新编译本批小程序或重新上传体验版；手机上仍打开旧体验版时不会自动获得本次界面调整。
