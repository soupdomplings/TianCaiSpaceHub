## 本轮行为

- 服务方式勾选“保存应用密钥”并点击“保存环境”，立即交给 DPAPI/Keychain，不依赖登录成功；密码仍仅成功后记住。非空保存/替换，空输入仅复用完全未改环境中可读取的原引用，改字段/无引用/不可读时要求重填；显式新密钥可替换不可读旧记录。取消勾选并保存移除原密钥。加载有引用的环境恢复勾选和保存状态，API 不返回/回填秘密；顶层 `rememberSecret/clientSecret` 不写 profile，旧 API 不带选项保持原语义。未改旧 null 机构/认证头和默认 MCP 表示保留。配置失败清新 blob，成功后清旧引用，字段/引用变化撤销旧授权、保存不自动登录；提交后错误及跨存储边界见专题。
- 新 `TokenExpiryPolicy` 区分 `Unknown/Fixed/SlidingIdle`。password 个人/MCP 两份 token 为闲置策略、初次准确到期为空，默认闲置 30 分钟且正常认证访问更新会话；Hub 不用初次登录时间硬判或本机推算 touch。换票 token 固定默认 24 小时、调用不延长，应用 `tokenValidTime` 可覆盖。准确期限优先自身 `expiresAtMs`，否则自身服务 `createTime`（毫秒）加正 `validTime/tokenValidTime`（秒），缺有效正时长或 0 用 86400 秒；缺创建时间保留未知，不造本机期限，不继承 apply ticket 600 秒。UI/中英帮助显示规则或 UTC 到期+剩余时间。
- 系统保护快照保存 `expiryPolicy`，管理状态返回两份策略；恢复旧快照按已核对模式清除 password 旧非零硬期限、保留真实 401 零失效标记，browser/application 保留原期限、不按恢复时间补 24 小时。普通配置 schema 仍 v1，指纹、身份恢复核验、代次及不重放保护保持。显式登录 401 区分取票、换票及读取账号租户；恢复/运行核验仍固定安全错误。服务规则由用户补充，本版未做真实期限实测，不能宣称真实 401 已消除。
- Hub 独立 NVWA MCP 页签的认证选项为“账号密码”和“认证服务连接”，新环境仍默认账号密码。主动切入认证服务连接默认勾选“使用共享应用代表指定用户”，主区填写代表账号、`ClientID`、`ClientSecret`；取消勾选保留浏览器个人授权流程。既有 password/browser/application 环境保持实际认证模式，不因改标签而转换。连接说明改为“在认证服务管理添加应用服务，获取ClientID和ClientSecret”；签名参数仍在高级设置，密码登录不显示应用字段。
- 右上角新增 `?` 配置说明按钮，点击打开原生帮助对话框，说明环境地址、应用服务申请、两条服务认证链路、密码登录、凭据保存、MCP 检测与各端接入。去除认证切换常驻文案、应用代表用户横幅与高级默认说明，把步骤集中到帮助；实际错误与认证状态保留。
- 普通登录只需一个 NVWA 服务地址。独立认证地址、MCP 路径或地址、租户和机构在折叠高级设置；MCP 默认直接显示 `/mcp`，可改其他路径或完整 HTTP(S) 地址。路径保留部署前缀并随服务地址变化，完整 URL 作为固定覆盖。
- 主认证下拉切换清除旧账号、凭据、应用 ID、验证与检测状态；共享复选框切换保留 ClientID、ClientSecret 和保存密钥选项，其他旧输入/状态清理。两者都取消旧授权并使迟到结果失效，通用地址保留。密码与 ClientSecret 按用户要求直接可见，登录加密、保存及日志规则不变。保存后仅在完整环境一致时保留内存秘密、不写普通配置；双因子仅在挑战时显示，验证码图片未实现。密码登录使用原始 `Authorization`，换票使用 `authorization-ticket-token`，有效期分别记录。
- `__default_tenant__` 是用户确认的有效默认租户，本轮取消之前误将返回值当作占位而拒绝的逻辑。仍只取返回的非空上下文租户、优先 `tenantName`/回退 `tenantId`，保持显式账号/租户匹配，不从表单补造身份。显示当前账号及返回租户，默认值显示“默认租户（__default_tenant__）”。
- 独立本机 HTTP 桥默认监听 `127.0.0.1:3849`，用每环境、每客户端凭据隔离权限，绑定实际用户、稳定身份、租户和认证代次，映射上游请求 ID，退出/重新登录撤销旧访问。响应和未知业务结果保留，不自动重放工具请求。
- GUI 常见登录/检测提示、身份/有效期、确认主内容和帮助有中英；适配器说明仍中文，未知后端错误保留固定安全文本，未做全量国际化或统一错误码。接入预览先检查登录，移除/恢复可未登录；确认说明环境、客户端、文件或天工设置及操作后果，不显示裸内部 server ID。工具清单与配置保存不承诺实际调用通过；仍需客户端刷新/信任及用户验收。重新登录先清旧快照/工具清单/客户端检测，等待浏览器/双因子/改密时不沿用旧“已登录”账号，成功后重读真实状态。
- Codex、WorkBuddy 只修改受管 MCP 项；天工只走已核验官方桌面 DataServer 的 connection 接口。操作先预览再按指纹写入，备份目标前像并保护秘密，拒绝覆盖同名非受管项目或用户改动。
- 普通环境独立保存，密码/应用密钥默认不记住；Windows 使用用户域 DPAPI，macOS 使用 Keychain，无明文降级。重启恢复后必须重新核验身份。

## 基线对齐与回滚

开发前发现工作区混有旧基线与最终发布内容。先保存全部脏文件、未跟踪资料、索引/工作区 binary patch、引用及哈希清单到本机忽略目录 `.build-tools/nvwa-v5-pre-alignment-20261008/`，再恢复最终 `origin/main` 内容并以旧 HEAD 预期值保护快进 `main`。不删除用户资料，不清空运行配置；详见 [仓库清理记录](../development/repository-cleanup.md)。

回退程序前先通过 NVWA 页移除各端受管项，按需要恢复对应目标备份并退出登录。旧程序不提供本机桥，遗留客户端地址将不可用；独立普通配置及系统保护材料不会变为旧版明文配置。已有模型、IM、天工任务、聊天和其他 MCP 项不由本轮迁移。

仅回退到 10 月 8 日 NVWA 首版时，本轮空 MCP 地址或 `/` 开头的路径须先改成完整 HTTP(S) 地址；首版不支持默认派生和相对路径。既有完整地址保持兼容。

回退本轮应用密钥/期限整合后，旧程序仍采用原保存时机/提示，也可能按密码初次绝对期限判断失效。普通环境 schema 不变，系统保护引用格式沿用；新增期限策略只在保护快照中。回退前退出授权，再在所用版本重新核对/认证，不能据存储可读推定会话已跨版本验收。
