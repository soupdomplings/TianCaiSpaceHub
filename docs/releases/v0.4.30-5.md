维护日期：2026-10-10。当前完整二开基线为 `0.4.30-5`，源码只维护 `main`。本轮新增 [NVWA MCP 接入（TC-014）](../customizations/nvwa-mcp.md)，并按用户反馈简化认证表单，承接最终 `v0.4.30-4` 产品、CI 修复和发布核验文档，保留 TC-001～TC-013。上游来源仍为 CodexHub `v0.4.30`；此前包、标签和验收保持 [原版本身份](v0.4.30-4.md)。

## 本轮行为

- Hub 独立 NVWA MCP 页签的日常认证选项为账号密码、浏览器个人授权；只需填写一个 NVWA 服务地址。独立认证地址、MCP 路径或地址、租户和机构在折叠高级设置；MCP 默认直接显示 `/mcp`，可改为其他路径或完整 HTTP(S) 地址。路径保留服务部署前缀，随服务地址变化；完整 URL 作为固定覆盖。共享应用代表用户仅在管理员高级设置启用，旧配置保留；密码登录不显示应用 ID、密钥或签名算法。
- 切换认证方式清除上一种方式的账号、凭据、应用 ID、验证与检测状态，并取消旧授权；通用环境地址保留。保存后只在完整环境一致时保留当前内存密码/密钥，不写入普通配置。双因子仅在服务返回挑战时显示，不要求手填图形验证码 ID；验证码图片接口仍未实现。密码登录 token 使用原始 `Authorization`，换票 token 使用 `authorization-ticket-token`，有效期分别记录。
- 独立本机 HTTP 桥默认监听 `127.0.0.1:3849`，用每环境、每客户端凭据隔离权限，绑定实际用户、稳定身份、租户和认证代次，映射上游请求 ID，退出/重新登录撤销旧访问。响应和未知业务结果保留，不自动重放工具请求。
- Codex、WorkBuddy 只修改受管 MCP 项；天工只走已核验官方桌面 DataServer 的 connection 接口。操作先预览再按指纹写入，备份目标前像并保护秘密，拒绝覆盖同名非受管项目或用户改动。
- 普通环境独立保存，密码/应用密钥默认不记住；Windows 使用用户域 DPAPI，macOS 使用 Keychain，无明文降级。重启恢复后必须重新核验身份。

## 基线对齐与回滚

开发前发现工作区混有旧基线与最终发布内容。先保存全部脏文件、未跟踪资料、索引/工作区 binary patch、引用及哈希清单到本机忽略目录 `.build-tools/nvwa-v5-pre-alignment-20261008/`，再恢复最终 `origin/main` 内容并以旧 HEAD 预期值保护快进 `main`。不删除用户资料，不清空运行配置；详见 [仓库清理记录](../development/repository-cleanup.md)。

回退程序前先通过 NVWA 页移除各端受管项，按需要恢复对应目标备份并退出登录。旧程序不提供本机桥，遗留客户端地址将不可用；独立普通配置及系统保护材料不会变为旧版明文配置。已有模型、IM、天工任务、聊天和其他 MCP 项不由本轮迁移。

仅回退到 10 月 8 日 NVWA 首版时，本轮空 MCP 地址或 `/` 开头的路径须先改成完整 HTTP(S) 地址；首版不支持默认派生和相对路径。既有完整地址保持兼容。

## 用户待验收

单服务地址默认与自定义部署覆盖、认证切换清空/取消迟到、旧管理员应用配置、保存后凭据保留和并发修改保护；账号密码成功/错误/锁定、RSA/SM2、图形验证码受限提示与双因子按需显示、身份/租户核对、两类 token 期限和过期行为；浏览器回环 URL/端口/白名单及 ticket 完整兑换；三端原生加载/信任/调用、重启和跨身份隔离、配置冲突/恢复/未知结果，以及 Windows/macOS 安装升级。当前仅支持所核对的 stateless JSON MCP；上游 SSE 或远端 session 请求明确拒绝，不能将未支持协议视为已连接。
