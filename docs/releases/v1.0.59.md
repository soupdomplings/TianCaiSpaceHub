# V1.0.59 · 安装升级时关闭 Hub

日期：2026-11-20（北京时间）。用户反馈旧 MSI 在文件占用页选择“关闭应用程序，然后尝试将其重新启动”后，Hub 仍不能关闭。本批修复 Windows 安装器策略及相应提示，Windows release 与唯一递增版本的新 MSI 已完成；保留 V1.0.58 和更早产物的原身份。源码基于唯一 `main/68c2103ab0dc2654c0d66a8a1f9babb579b7b9a1` 加既有及本批工作区修改，尚未提交、推送或发布。

## 问题与修复

原文件占用页来自 WiX 默认 `MsiRMFilesInUse`，发布 `RMShutdownAndRestart` 事件；旧包没有明确禁止 Restart Manager 自动重开，也没有允许结束超时不响应的进程。Hub 界面和无窗口后台使用同一 EXE，均可能占用安装文件。截图与源码可以确认上述策略缺口，不能据此判定现场一定发生了重启循环。

本批在 WXS 中设置 `MSIRMSHUTDOWN=1`，保留正常退出通知，并允许 Windows 在超时后结束仍占用文件且不响应的进程；设置 `MSIDISABLERMRESTART=1`，安装后不自动重开。文件占用页改为“关闭应用程序并继续安装”，默认选择关闭，保留暂不关闭及取消；保留标准进程列表与 Windows Installer 的关闭事件协议。开始页提醒先保存编辑。成功页只有点击“打开 TianCaiSpaceHub”才启动新版，点击“完成”仅结束安装。

实际文件占用由 Restart Manager 判断，不添加同名进程批量结束或外部 PowerShell／taskkill，不调整普通 × 隐藏托盘、既有系统关机、GUI 自有后台清理或独立客户端的退出逻辑。系统禁用 Restart Manager、权限不足或跨登录会话时，安装器仍可能要求手动释放文件或重启系统。详细行为、官方依据和回退见[桌面与打包](../customizations/desktop-and-packaging.md#v1059-windows-升级时关闭-hub)。

## 用户验收

1. 先保存 Hub 中尚未保存的编辑，保持旧 Hub 运行，启动本批新 MSI。该 MSI 自带关闭策略，不必先运行新版 Hub 才能生效。
2. 文件占用页应为“关闭正在使用的程序”，默认“关闭应用程序并继续安装”。点确定，观察旧 Hub 及后台占用释放后继续升级；无响应的进程可能需要等待系统超时处理，不把等待误认为已经重新启动。
3. 安装成功后点“完成”，确认 Hub 没有自动打开。随后手动打开并确认版本 `1.0.59`，模型、配对及显示设置保留。
4. 如改点“打开 TianCaiSpaceHub”，只在安装成功后启动新版。开始前或文件占用页取消应结束此次安装。选择“暂不关闭”时保留 Windows 的重启提示流程。

本批静态核验和构建不替代上述真实升级结果；如仍出现文件占用，记录发生在关闭等待、成功页后还是手动打开后，以便区分退出失败和新启动。
