# V1.0.36 · Windows 本地测试包

本批以 V1.0.35 为升级起点，集成 `7952c60` 的两项 GPT-6.2 能力模板、`aa1bdfe` 的渠道选路与导入调整、`559ea1c` 的旧清单兼容核对，以及 `f1afde5` 的默认生图模型。Dumpling-MCP、远程组网和天工启动没有新增改动，无须为此包重复全测。

## 安装与测试顺序

升级前先记下旧版 ChatGPT / Codex 勾选的模型、顺序及现有渠道数量。从托盘真正退出旧 Hub，再运行本次 MSI 覆盖升级，打开 Hub 确认显示 **1.0.36**。保留现有配置，不必卸载或重置。

| 优先级 | 怎么测 | 预期结果 |
| --- | --- | --- |
| 1 · 旧配置 | 升级后直接查看 Hub 的 ChatGPT / Codex 模型列表，不先保存。 | 原勾选、顺序和别名保留；之前为空则仍为空。没有新增渠道。 |
| 1 · 聊天与路由 | 选一个已启用且确实提供 `gpt-6.2-astra` 或 `gpt-6.2-sol` 的厂商，把该型号添加到客户端，再重复保存。在 ChatGPT / Codex 里选它发送一句话。 | Hub 客户端列表只有一个该 ID；渠道数量不增加，请求日志命中提供该型号的渠道。上游可用时正常回复。没有对应渠道的型号不会因为模板存在就可用。 |
| 1 · 生图与改图 | 在 Hub 开启请求日志详情，进入 **ChatGPT / Codex → 接入设置 → 默认生图模型**，选择渠道实际支持的 `gpt-image-2.6-sunburst`、`gpt-image-2.6-flare` 或别名，不重启客户端。请它画一张图，再在同一对话让它修改图片。 | 两次均应返回图片，聊天模型不变。独立图片请求的「Codex 请求」可以是 `image2` / `gpt-image-2`，「上游请求」的 `model` 应为所选型号，选别名则应为映射后的真实 ID；如果只有 Responses 记录，检查上游 `image_generation` 工具的 `model`。选回「沿用客户端默认」后，下一张图使用客户端原来的型号。 |
| 2 · 导入与搭档 | 小分队从同一来源先导入模型 A，再导入 B，两次都选 ChatGPT / Codex；也可让天才搭档再添加同一个 A。 | A、B 都保留，A 能继续调用。首次导入新来源可创建一个渠道，后续不按模型复制渠道或重复添加 A。 |
| 观察 · 桌面刷新 | 保持 ChatGPT 打开，在 Hub 保存聊天模型后重新展开客户端的模型菜单。 | Hub 已更新目录。本版未实现强制刷新桌面菜单；若未出现，记录重新展开、新开会话或完全重启后哪一步可见。这个观察与默认生图模型即时生效是两件事。 |

反馈异常时，提供失败的是哪一步、所选公开 ID 和渠道、操作时间与提示原文即可；如涉及图片，可附日志里客户端与上游的 `model` 值。不需要密钥、完整日志或图片正文。
