# 0.4.29-5 macOS 网页导入开发状态

日期：2026-09-30。基线：`16eab074bb02bd42e968e92e62590705d7841501`（`0.4.29-4` 源码提交）。用户已授权提交 GitHub 并创建 `v0.4.29-5` 预发布；当前正在准备源码提交与 Actions 构建，最终结果在本页续记。

## 已实现

- App `Info.plist` 声明 `tiancaispacehub` 协议；原生 URL 事件接入共享导入流程，窗口隐藏/最小化时恢复并激活。
- 启动期回调前 URL 内存暂存；CLI 和重复 App 用同用户 Unix socket 转交，重复进程不启动额外后台服务。
- 菜单/CLI 通过 Launch Services 注册当前完整 App，macOS 系统管理关联；不提供 Windows 式解除注册菜单。路径含空格可用，裸程序不能替代 App 注册。
- 两端使用相同导入链接和接口；HTTP/HTTPS 兼容、预览前获取模型、默认禁用、空模型补全和配置并发保护沿用现有代码。
- 既有 macOS 构建工作流加入 Cargo 锁文件、plist 协议和 universal 双架构检查，以及包内导入说明。

## 验证与产物

已完成以下编译与静态核对：

- Windows `cargo check --locked --offline --features gui --bin codexhub` 通过。
- Windows `cargo check --locked --offline --features gui --tests --bin codexhub` 通过；包含可移植 macOS GUI 事件桥的类型检查，仅编译测试代码，未执行测试。
- `cargo fmt --check`、`git diff --check` 通过；App plist、工作流 YAML 和 8 个 Bash 步骤语法、变更文档的本地链接已核对。

新增 macOS IPC 和 App 路径回归用例仅写入源码，未执行。Windows 编译不能覆盖 macOS 原生接口、Unix socket 或 Apple Event 实际行为。共享队列已区分导入失败与启动/无效链接错误，后者不会误减在途导入数量。

所有本版本安装包按用户要求由 GitHub Actions 生成，本地不打包。Windows 工作流使用 Cargo 锁文件，并将导入说明纳入便携 ZIP；macOS 工作流生成 universal DMG/App ZIP。当前尚未取得本版本 Actions 产物。按用户要求不启动 Hub/Codex、交互验收或真实模型调用。所有 `0.4.29-2`、`0.4.29-3`、`0.4.29-4` 包及历史结果保留原版本归属。

macOS 后续构建沿用 [release-macos.yml](../../.github/workflows/release-macos.yml)：手动对分支运行生成 Apple Silicon/Intel universal DMG 和 App ZIP，上传 Actions artifact；只有标签触发发布 Release。有 Developer ID 配置时走签名/公证，无配置时为 ad-hoc 测试包。两种方式都需实机验收首次网页唤起、已运行/隐藏窗口、连续导入、CLI/重复进程转交、错误链接和 App 移动/多副本行为。

启动边界：wxDragon 队列暂存已送达 `MacOpenURL` 的事件；更早的 wxWidgets 初始化阶段沿用其单 URL 暂存机制。因此尚不能保证冷启动极早阶段连续打开多个链接全部交付，应在主窗口出现后继续导入；详见 [GUI 维护](../gui-runtime-maintenance.zh-CN.md)。

## 配置与回滚

没有渠道配置迁移或新的导入开关。App 复制到“应用程序”并打开后可从网页导入；需要时用“文件 → 注册网页导入…”更新系统登记。升级前退出旧 Hub；多个 App 副本可能影响 macOS 的关联选择，保留所需副本后重新注册。

回退前退出新版并备份配置，恢复旧 App；`0.4.29-4` 及以前没有 macOS 网页导入接收代码。socket 路径及权限、源码入口见 [网页导入](../hub-external-import.md)，开发记录见 [二开变更记录](../customizations/CHANGELOG.md)。
