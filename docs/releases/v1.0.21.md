## 范围与兼容

- 天工页右上“增强启动”，使用 Hub 已保存且启用的外部模型初始化本地工作区并恢复任务；接入设置保留普通启动，旧启动 payload 和 IM `/tg` 不切换模式。
- 本地就绪独立于真实官方登录；失效、退出和可取消登录不销毁当前外部对话。后台身份核验不主动清除官方记录，官方资源仍按真实授权处理。
- 新任务优先已选外部模型，旧任务的内置、丢失或空绑定不静默替换，发送前明确选择。首次仅自动刷新登录/初始化页，已打开的普通工作区保留任务和草稿。
- 再次增强会更新候选外部模型和新任务首选；保留当前任务、草稿与执行中的选择，Hub 重启后可重挂，手工刷新使用最新同步名单。
- 适配只在已确认的本机天工窗口内存加载，不改安装 ASAR、不生成假账号或 token。结构不兼容完整放行原脚本，普通启动作为回滚入口。实现、首次启用步骤、模型集合更新与限制见 [天工专题](../customizations/gmclaw.md#外部模型免登录增强启动v1021)。
- 天才搭档 Server 的旧来源被桌面更新移除后，确认准备时重新发现当前官方安装，兼容登记 Store 根及 npm 新旧布局。启用或重新进入未就绪模块时单次提醒，修正启用响应仍忙导致安装确认被吞掉的竞态；确认才准备，取消不下载，保留手动准备入口。见 [搭档专题](../customizations/genius-buddy.md#v1021-运行端来源与准备提示修正)。

## 用户测试与交付边界

安装新 Hub 后，在天工模型页确认至少一个外部模型已保存，点击右上“增强启动”。若天工是用普通方式打开且没有本地通道，先正常退出后重试；已有普通官方工作区则先由用户退出官方账号回到登录页，再首次启用本地模式。本批不自动刷新工作区或结束用户任务。

重点测试无官方登录进入工作区、原项目和任务恢复、外部文本/工具续轮、停止/重开、登录失效或退出继续对话、可取消官方登录与原草稿保留。旧内置任务应保持历史并提示明确选择外部模型，不应自动发送到其他模型。真实可用以用户本次验收为准。

搭档侧测试：已安装桌面程序时确认准备能够复用；没有可用来源时先询问，取消不下载/安装；确认后再准备。保持未就绪重新进入模块应有一次提醒，常规状态刷新不重复弹出；两功能仍共享同一包，移除只处理 Hub 自管安装。

Windows 优先；本机 1.0.4 安装资源检查不代表 macOS 原生构建或所有天工版本验收。不运行实际 Hub、天工、其他客户端或安装器，不真实调用模型/账号/支付，不触发 Actions、标签或 Release；源码按既有授权正常提交并推送，测试 MSI 仅保留在 `target/`。
