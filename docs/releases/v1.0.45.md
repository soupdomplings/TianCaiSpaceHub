本次重点是「目标桌面能看到旧会话正文，但网页读不出来」，以及新建后首条消息前出现 `no rollout found for thread id`。无需删配置、移动会话文件或重建项目。网页始终读取目标运行端的同一条原始会话。

建议先在访问端和目标端安装同一版 Hub，真正退出旧 Hub 后再启动；保持目标端 Codex 已启动并接入 Hub。从访问端 Hub 重新打开会话网页，按以下步骤验收：

1. 打开此前失败、桌面仍看得到内容的**同一条旧会话**，对照最后一问一答，再点「更早的消息」。若当前渠道不能恢复执行，已取到的正文仍应可读。
2. 新建 Codex 会话，点「选择工作目录」。若要使用新目录，先到目标 Hub → 远程连接 → 添加工作目录，经系统选择器添加，再回网页刷新。创建后先刷新网页，再发送第一条消息；回桌面检查仍是同一会话、消息只出现一次。
3. 在提供连接码的电脑打开「远程连接」：有来访设备时，页首显示「设备请求访问本机」，点「允许连接」才授权。已有配对无需重做。选择本机「打开会话网页」，检查能打开客户端、项目和原始会话。
4. 在长页上打开、收起天才搭档，再滚到底：按钮悬浮在 Hub 内右下角，正文不应跳动，滚动条可拖到最底。日志表格、消息等局部列表仍可独立滚动。

实现和兼容边界：[本机网页转发](../customizations/remote-network.md)、[Codex 历史与首发](../customizations/remote-sessions.md)、[目录与网页行为](../customizations/remote-web.md)、[浮层布局](../development/desktop-visual-system.md)。旧会话若在目标端的两种读取方式下都没有记录，会显示原因，不能据此断言会话已删除。没有启动实际 Hub、客户端、安装器或调用模型；真实双机、Windows 实际安装与 macOS 待用户验收。本版为本地测试，未推送、打标签、运行 Actions 或创建 Release。
