## 实际行为、兼容与回滚

| 问题 | 本批实现 |
| --- | --- |
| 会话移动没有可见确认 | 工具栏和右键的「归到 AI Gateway」「移动到 Provider」共用确认窗，显示选中数量和实际目标，其他 Provider 可在窗内更改。点「确认移动」才调用原迁移接口；取消、Esc 或关闭不执行。按钮按内容和系统缩放布局。见[移动会话](../customizations/codex-history-recovery.md)。 |
| 查到历史却无法补项目且没有原因 | 区分整库已分组数、可补回卡片和待重分会话。当前账号已归组的本机对话可按唯一项目根及子目录证据补卡，全部归组正确时待重分为 0 仍可补卡。旧无账号记录依同账号备份佐证，缺佐证时需用户确认后勾选再检查。SQLite 活动账号侧栏优先，旧 JSON 保留；账号、目录、云端项目及未知结构各自显示原因，无可处理项时按钮灰色。详见[检查与修复](../customizations/codex-repair-center.md)及[项目恢复](../customizations/codex-partial-project-recovery.md)。 |
| 空模型清单直接勾选保存未同步客户端 | 空清单可跨渠道勾选并保存，同 ID 去重；非空保存启用 Hub 网关，清空不关闭其他端共用网关。已接入同一 Hub 时备份并补齐缺失目录和发现字段，自定义／CC Switch 目录及显式禁用分别提示。首次接入仍需初始化，写入失败保留已选清单并可重试。Hub 保存、后端回读与桌面菜单分别反馈。见[动态模型](../dynamic-codex-models.zh-CN.md)。 |

移动保持原存储格式，移回时选择原 Provider 并确认。项目检查只读，应用前完全退出客户端；SQLite 按当前账号和检查时状态事务写入本次项目键，撤销校验后来修改。JSON 沿原回执，SQLite 使用第 6 版回执，应在本版或兼容版本撤销。模型沿 `codexVisibleModels`，客户端补缺字段有备份，不覆写现有自定义目录或手动禁用。相关专题记录具体范围和回滚，打包会话不操作真实配置、数据库或客户端。

## 用户验收

1. 安装本批新包后，在会话管理选一条及多条会话，从工具栏和右键分别打开两种移动。核对选中数量、目标和两个可见按钮；取消／Esc／关闭应不移动，确认后检查实际归属。
2. 保留原项目丢失现场，进入「检查与修复 → 删除配置后，项目或分组会话不见了」重新检查。核对整库统计与可补卡片／待重分数量；待重分为 0 时仍可应用有证据的卡片补回。不可处理时应显示原因和下一步。退出客户端后应用，再重开原项目及一条原会话；撤销走独立入口。
3. 已接入本 Hub 的电脑，从空模型清单跨渠道勾选两项并保存，重新打开页面核对，再查看真实客户端模型菜单。遇到自定义目录、显式禁用或文件写入失败时核对具体提示，处理原因后可重试；后端返回模型不等同桌面菜单已刷新。
4. 升级时先保存尚未保存的编辑，文件占用页默认选择关闭并继续安装；成功后点「完成」应保持 Hub 关闭，再手动启动核对版本 `1.0.61` 和原设置。开机启动及卸载清理继续沿 V60 的范围验收。

真实 Windows 安装、缩放与移动、原现场项目补回／撤销、客户端模型菜单待用户验收；macOS 本批未构建或验收，不新增 Linux 范围。本会话未提交、推送、触发 Actions、创建标签或 Release；共享索引／总表／CHANGELOG 及后续源码提交由管理统一处理。
