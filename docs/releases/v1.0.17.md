## 本批实现

- **Hub 自管 CLI**：先复用系统现有 Codex CLI，补齐新版独立安装目录发现；缺失时首次启用自动下载官方完整运行包，保存至 `local-assistance/runtime/standalone/`，用 `runtime/current.json` 记录可用程序。设置保留“一键准备”和失败重试，运行时跨任务保留，清理 `runs/` 不删除它。用户指定路径无效时保留错误，不自动覆盖选择。首次准备需要联网并沿 Hub 出站代理；不执行远程安装脚本、不改 PATH、用户 Codex 配置或认证。增加 `flate2`、`tar` 完整解包依赖，保留官方辅助程序和资源；下载流按官方摘要至多核对一次，不反复扫描或哈希整个运行树。
- **协助完全访问**：`fullAccess` 默认 `false`，原 `allowWorkspaceWrite` 兼容。显式开启时独立 config/thread/turn 一致使用 `danger-full-access` / `dangerFullAccess` 和 `never`；不再受天工父任务 `confirm` 限制。明确 `analysis_only:true` 仍为 read-only/readOnly，并保持 `never`，人类信息问题继续回天工。每项任务固定权限快照，追问不受设置中途变化影响；不更改天工外层 MCP 调用授权。
- **来源与图谱**：真实任务入口验证后调用受信 Responses wrapper，复用 ActivityStore 响应体生命周期。活动的真实发起端仍是 `tiangong`，另标记 `source: local-assistance-mcp`；日志沿原 `client_id` 列保存来源，列表、详情、筛选、统计统一显示“协助处理 MCP”。概览按真实请求将协助 MCP 连到实际 `route + model`，等待/结束/取消按既有规则退流与暗淡；配置、目录读取和进度轮询不创建模型边。旧日志不回填、不需数据库迁移或新增普通客户端。

完整默认值、关键代码、兼容与恢复见 [天工本机协助](../customizations/tiangong-local-assistance.md)，概览/日志实现见 [实施记录](../development/v1-implementation.md#v1017-协助模型请求来源2026-11-10) 及 [桌面视觉规范](../development/desktop-visual-system.md)。
