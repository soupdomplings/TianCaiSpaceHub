适用场景：旧会话还在“最近”，用户已重建项目并把一两条会话移回。Hub 保留这些手动归属，按当前项目和原目录补回其余能确定归属的会话。新旧项目同根时，也能处理仍挂在不可见旧项目 ID 上的历史。操作与匹配边界见[历史恢复专题](../customizations/codex-history-recovery.md)。

## Windows 验收

1. **直接用当前状态测试**：保留已经重建的项目和手动移入的会话。选一条还在“最近”的旧会话作对照；不用再删配置。完全退出 ChatGPT / Codex，打开 Hub → ChatGPT / Codex → 接入设置 → 检查与修复。
2. 选择「删除配置后，项目或分组会话不见了」，先检查待恢复数量，再点修复。重新打开 Codex，选「分项目显示」。刚才选的旧会话应出现在重建项目下，打开仍是原来的消息。
3. 手动移入的会话应保留且不重复，刻意移到别的项目的会话不应跳回。再次检查时，同一批会话不应再计入待修复数量。
4. 如需验证撤销，完全退出客户端，在检查与修复的记录中还原本次操作，再打开查看。只撤销 Hub 本次变更。

真实安装和客户端验收由用户完成；本机合成测试不代表已验证真实桌面显示。
