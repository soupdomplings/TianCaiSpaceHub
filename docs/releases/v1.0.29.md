## 当前行为

- 首次在软萌猫娘的 WorkBuddy 分享面板显式启用，打开 WorkBuddy 取得当前账户最小授权；授权只保存在 Hub 自有的系统保护存储中。面板显示独立分享就绪后，可以真正退出 WorkBuddy，后续请求与续期由 Hub 执行。重启 Hub 后显式启用可恢复授权；失效时重新授权。
- 模型目录沿 WorkBuddy 主 Agent 选择器解析，按真实 ID 去重；不同 ID 的同名项附 ID。模型列表和详情展示上游提供的积分倍率，未知值不猜测、不换算 Token 或人民币价格。
- 停用分享清除本机独立授权并取消执行，保存的模型条目保留。首次授权时宿主仍在线，退出登录／切号／换组织立即撤销旧授权；宿主真正退出后，服务端撤销在后续请求或续期中发现。
- 助手回答“能做什么”先说现有可用能力，提供五个可见客户端的官方下载入口与安装步骤。当前不下载或运行安装器，也不将链接说明当作已经安装。

用户另提出将 `codex-windows-fast-patch` 接入搭档诊断修复。本批只讨论：优先复用现有“检查与修复”执行层，技能补充专项知识和缺失能力；尚未新增助手修复工具，不执行本机 ChatGPT 修复，不将整套脚本自动套用到当前包。

## 待用户验收与兼容限制

1. 软萌猫娘打开 WorkBuddy 分享，首次启用并登录；就绪后从客户端菜单真正退出 WorkBuddy，使用所选目标客户端调用模型。
2. 重启 Hub 后点击启用恢复，检查不再启动 WorkBuddy；验证真实文本、流式、工具续轮及令牌到期刷新。首次握手、账户／组织切换及服务端撤销均需实机核对。
3. 对照 WorkBuddy 自身选择器与积分显示，核对过滤、同名区别及倍率；目录不是额度或调用权限证明，实际扣费以 WorkBuddy 为准。
4. 停用后模型条目保留但不能继续使用；重新启用需授权。检查助手能力介绍及官方下载指引的实际表达。

当前 Windows 5.9.3 接线基于安装资源只读审阅与合成夹具，独立推理／真实续期及扣费待用户测试。独立连接使用系统代理，尚未接入 Hub 自定义出站代理；Responses 远端 `/compact` 仍不支持。macOS 本批未构建或实机验证。未触发 GitHub Actions、标签或 Release。
