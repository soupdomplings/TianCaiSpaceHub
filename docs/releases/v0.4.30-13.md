## 源码与范围

唯一 `main`，基线 `25d024b2baa6af25f66bd69d5b237e0caa35df80` 加未提交修改。完整版本 `0.4.30-13`、Windows 数字文件版本 `0.4.30.13`；MSI 三段 ProductVersion 保持 `0.4.30`。本轮不推送 GitHub、不触发 Actions、不创建标签或 Release；正式 Windows/macOS 包仍待用户测试后授权由 Actions 生成。旧包不覆盖。

普通模型渠道先请求原地址，明确 HTTP 失败后同源补 `/v1` 一次；确认有效协议结果才保存，两次都失败保留原地址及原错。自动修正保持渠道身份和工具续轮匹配，并核对并发配置改动。模型目录成功后的修正同样处理，独立目录和网页导入的请求边界保留。完整默认值、例外、配置与回滚见 [TC-015](../customizations/provider-url-recovery.md)。

WorkBuddy 为 GPT-6、GPT-5.6 家族及其别名增加 `max`，支持保存、重新加载以及 Chat/Responses 字段转换。Claude、GLM 和其他模型的既有档位不变；真实模型是否接受该值仍由上游决定。原因、操作与回滚见 [WorkBuddy](../workbuddy.md)。

## 用户试用

1. 从托盘退出旧 Hub，安装本轮测试 MSI，确认版本 `0.4.30-13`。
2. 对一个缺 `/v1` 的普通 API 渠道获取模型或发起原有客户端请求，确认成功后 Hub 保存补版本地址。原地址本来可用时保持原地址；两条路径均失败时仍报告原地址的错误。
3. 对已有版本地址、独立模型目录和路径前缀核对不重复补版本；流式回复正常结束后继续一次工具调用，核对历史可续接。
4. 在 WorkBuddy 接入选择 GPT-6/GPT-5.6 家族或其别名，思考强度选 `max` 并保存，重新加载后确认档位保留，再由用户检查实际模型调用。已有条目需重新保存才能更新客户端的档位列表。

本轮新增的来源字段可被旧版忽略，回退前退出 Hub 并备份配置；URL 身份语义和专用渠道备份的边界按专题处理。旧档位配置仍可读取，回退程序后旧 WorkBuddy 页面可能把不在预设中的 `max` 回退为 `high`，如需精确还原使用保存前的两端备份。
