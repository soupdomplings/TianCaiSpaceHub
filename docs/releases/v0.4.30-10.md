## 问题与实现范围

用户反馈 v8 的“检测 MCP / 检测本机桥”显示“NVWA 后台响应超过限制”，同一 MCP 在客户端仍能调用。源码确认后台检测返回完整目录，GUI 却只读最多 2 MiB，工具参数、输出 schema 和元数据增大会导致结果回传失败。诊断阶段用户授权的一次只读能力查询成功，仅证明当时该连接可用，不作为新版本或其他用户授权的验收证据。

- GUI 检测请求带 `summaryOnly=true`。后台在需要时先用完整工具定义同步天工原生目录，再向 GUI 返回模块/分组统计与用途示例；不返回输入/输出 schema、操作合同或任意工具元数据。
- 总数来自完整分页清单；真实 `_meta.com.jiuqi.nvwa.moduleName` 优先分组，缺失时用工具命名空间并标明“工具分组”。最多展示 32 组、每组 3 个示例，标题 80、用途首行 120、工具代码 256 字符，省略数明确展示。数量统计不因展示省略变小，不猜译服务未提供的说明。
- 初始化和 initialized 通知核验成功后，若目录达到响应大小、100 页或 10000 工具的读取上限，摘要模式显示“已连通，目录未完整读取，工具总数未知”；保留已读部分概览，不将部分计数或旧缓存计数当总数，不更新天工完整目录或记录完整桥检测通过。
- 认证失败、HTTP 拒绝、无效 JSON/schema、重复工具、循环 cursor、ID/代次不符仍是失败。大目录不会撤销原客户端接入，也不会把认证失败改成成功。
- 受保护管理响应的 2 MiB 与 MCP 单次解码响应的 8 MiB 上限保留，前者不再承载完整 GUI 工具目录；超限提示区分结果读取与连通判断。旧管理调用省略 `summaryOnly` 仍返回完整目录并保留超限失败语义。本机桥新增 `-32010` 表示响应超限，用于有界检测识别；业务调用仍保留未知结果与不重放规则。
- 继承 [v9](v0.4.30-9.md) 的 Codex 历史恢复与 Fast 兼容；本轮未改动这部分实现。用户反馈的另一类“尚未取得接入授权”没有现场状态证据，本轮不修改授权生命周期或宣称修复。

完整接口、限制和回滚见 [Dumpling-MCP](../customizations/nvwa-mcp.md)，沿革见 [变更记录](../customizations/CHANGELOG.md)。无需普通配置、受保护凭据或客户端配置迁移；回退旧包会恢复完整目录回传和旧显示限制。
