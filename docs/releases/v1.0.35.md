## 范围与使用

检测保留本机桥外层 502 后的具体原因，区分登录过期、连接／超时、上游状态和协议不兼容；NVWA 认证与 MCP 请求遵循 Hub 当前网络设置。补默认可用的固定字段接入／检测阶段日志，用于区分重复准备、显式修复与临时会话清理；不启用全局 debug，不另存协议正文，不增加重试或自动删除／重建配置。

日志通过已有 daemon 输出进入 `codexhub-daemon-startup.log`，由“帮助 → 导出连接诊断…”收集。只记录操作、客户端类型、阶段、结果、错误分类、上游状态及随机检测关联编号等；不写入环境名称／ID、配置地址／路径、上游正文、凭据或工具参数。已有连接诊断的脱敏及日志尾部限制继续使用。

转给用户的步骤：

1. 从托盘真正退出旧 Hub，安装本次 MSI，打开后确认版本为 **1.0.35**。
2. 在 Dumpling-MCP 选择原环境并确认已登录，点击“连接并检测”；先保留原网络设置，以便记录原问题。无需先删除环境或客户端连接。
3. 若出现接入／修复确认，按现场需要确认一次并记录是否再次弹出；分别对 Codex、WorkBuddy 各复现一次，保留提示文字与大致时间。
4. 复现后尽快从“帮助 → 导出连接诊断…”保存 ZIP，将 ZIP 和提示文字交回。无需提供密码、密钥或原始用户配置。

本轮仍不能从旧版导出包确定唯一现场根因；新包是获取阶段证据及验证已知修正的工具，不代表现场已解决。新增日志无需用户额外开启调试模式。已有配置、登录和授权格式不变；回退会恢复旧版网络选择及错误展示，旧安装包保留原身份。
