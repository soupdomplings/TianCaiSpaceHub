## 本轮改变的行为

- 天工桌面即时同步不再要求 `package.json.version == 1.1.1`，也不要求固定 renderer JS 文件名或 SHA-256 白名单。核对已安装天工应用身份、精确安装内 `app.asar/out/renderer/index.html`、HTML 声明的本地脚本入口与运行时 App/ChatPanel 字段/IPC 能力，版本变化或重新打包而结构兼容时可继续同步；不执行或读取入口脚本正文，不泛化任意安装布局。
- 组件不依赖编译后的 `__name`，按根视图及完整任务/会话/活动属性定位；App/Panel 均有界检查 Closure/Block，每组件最多 8 个候选，完整字段须来自同一作用域并通过只读 setup schema，完整有效候选必须唯一，不拼接零散字段、不枚举 Module/Global/Script。
- 实际写入的 `scenarios`、`messages`、`showWelcome`、`hasOlderMessages` Ref 与实例 `seedMessages`、`messageSummaries`、`hasOlderMessages` 缓存须可写，纯读 Ref/实例数组不额外要求可写；异步读取后重新核对字段、可写能力、精确任务/会话及原生运行/审批/未保存状态。未知、只读或变化中的结构不修改窗口，不因展示失败重放任务。
- 同用户进程和 CDP 监听归属、唯一精确页面、Hub 回复行来源、草稿/模型/当前选择与原生未保存内容保护继续保留；不整页重载、不自动切会话、不强制重启天工。常规检查/更新路径尝试释放 CDP 对象组，`display` 函数的 12 秒整体限时取消 future 时断开本次 CDP 会话，不宣称显式释放已确认。

多模型配置、厂商参数适配与流式聚合、专用渠道隔离、天工自动授权/重连、真实桌面历史/消息、平台审批、启动按钮/概览、端口释放、完整项目目录与临时回复状态均承接 `v0.4.30-3`，不改写前版验收结论。`/wb` 外部任务仍暂不支持，WorkBuddy 模型配置与桌面启动继续保留；本轮不增加天工 Telegram、主动取消或 MCP 管理。

完整行为见 [天工外部消息](../customizations/gmclaw-im.md)、[模型接入](../customizations/gmclaw.md)、[配置](../configuration.md)、[二开总表](../customizations/README.md)、[变更记录](../customizations/CHANGELOG.md) 和 [品牌与交付](../customizations/desktop-and-packaging.md)。

## macOS DMG 修复与同标签重建

首次运行的双架构 App 编译和 ad-hoc 签名通过，但 `hdiutil create` 在拷贝 App 到新镜像时报告空间不足；宿主仍有约 43 GiB 可用，问题是按源目录估算的新 DMG 卷容量过小。工作流改按 staging 内常规文件的逻辑字节数合计估算 HFS+ 容量，使用 `max(256, ceil(逻辑字节数 × 2 / MiB) + 128)` MiB，忽略 `/Applications` 符号链接，签名和非 Developer ID 路径均复用同一 builder，再输出 UDZO 并执行 `hdiutil verify` 核对新压缩镜像。该更改仅影响 CI 打包，不修改产品运行配置或已发布 Windows 包。

新增 `workflow_dispatch.release_tag`：可从更新后的 `main` 工作流指定既有完整标签，源码 checkout `refs/tags/<release_tag>`；核对标签格式、Cargo 完整版本与实际源提交，更新清单和上传均使用该指定标签。工作流运行提交与产品源码提交分别记录，重建本版时源码仍为 `7b5dd6e…`，不移动 `v0.4.30-4` 标签、不重建或替换已核验 Windows 附件。输入留空时，原普通分支构建只上传 Actions artifact 的行为保留。

CI 修复已保存并推送于 `1bd8ffd6a5bae243a3513325fcf23bb4d2c48bce`，其工作流通过 `release_tag=v0.4.30-4` dispatch [37492460126](https://github.com/soupdomplings/TianCaiSpaceHub/actions/runs/37492460126)。Checkout 和 Prepare Source 校验/实际日志确认产品源码 `7b5dd6e…`、Cargo/标签一致，工作流提交与产品提交分开记录；不移动标签、不替换 Windows 资产。实际 staging 常规文件逻辑大小 `88,148,046` 字节，对应明确 HFS+ 容量 `297 MiB`，公式核对一致；`hdiutil verify` 返回镜像 checksum `VALID`，后续更新清单、Windows 清单核对、上传和 Release 发布均成功，首次失败记录保留原事实。

修复前本地仅完成 YAML 解析、10 个 run 块 `bash -n` 与 3 个内嵌 Python 语法编译；实际创建与校验由上述 Actions 完成。回退 CI 可撤销工作流修复，不改旧产品标签或安装包；旧容量估算再次用于重建可能重现 DMG 失败。没有在本机生成发布安装包、挂载 DMG 或安装 App。

## 升级、兼容与回退

正常退出旧 Hub（含托盘），使用本版包。已从 Hub 启用 `127.0.0.1:18769` 通道的天工可保持运行并由新 Hub 重连；没有通道的手动实例需确认任务/审批后正常退出，再从 Hub 启动一次。旧天工若已继承 `3847` 监听句柄，仍须正常退出旧实例一次迁移，新 Hub 无法撤销旧进程持有的句柄。Hub 退出或升级不代表天工任务被取消。

回退前备份 Hub 配置、客户端模型配置、会话关联和已有各功能备份。回到已发布 `v0.4.30-3` 会恢复固定 `1.1.1`/资源指纹门槛，已保存数据不会自动删除，未知/审批标志不能通过删除关联或重启绕过；回退更早版本的可选字段与布局限制仍按对应专题处理。本轮不修改运行中的配置/安装资源或覆盖旧包，未执行实际回滚。
