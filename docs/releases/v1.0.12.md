## 本轮修正

- VS Code：按固定 Magpie 提交移植便携目录识别，支持已保存程序、PATH CLI、版本目录、Scoop shim 及 macOS 合成 bundle 场景；Profile 只认实际登记和存在的位置。继承默认模型的 Profile 改在默认位置管理模型，资源目标保留，不再生成客户端不读取的模型文件。
- ZCode：Windows 尊重原生 HOME 优先级，按 bootstrap 的绝对 `dataBaseDir` 识别模型迁移目录；Skill/MCP 保持原根及目标身份。已有受管记录与新模型目录不一致时提示核对后替换，不伪报使用，也不删除旧目录。迁移设置不可读或路径无法安全使用时停止自动目标读取，核对权限/实际目录后可重试，不静默回旧位置写入。
- WorkBuddy：保留原 Hub 文件覆盖，补原生 `WORKBUDDY_CONFIG_DIR`；兼容数组、旧单模型对象和 `{models,availableModels,...}` 容器。保留未知顶层和其他模型，可见列表只改本条目；恢复仅还原操作差额，本条目后改则停止。
- Harness：MCP 改用实际 Profile 的 `cordis.patch.yml`，保留旧 `config.yaml`。旧模型目录未建立现代 Profile 时停止假写入并给出处理办法。WorkBuddy/ZCode 的远程 MCP 使用原生 `http` 类型。

本次核对七端模型、Skill、MCP；**没有完整照搬 Magpie 全部适配**。原三端和 WebStorm 双路线继续各自专用服务，来源隔离、路由、revision/锁/备份/原子替换保持。逐端结论、固定参考身份、旧目录处理和剩余边界见 [客户端配置核对](../customizations/client-configuration-audit.md)。代码归属及 MIT 许可见 [第三方说明](../../THIRD_PARTY_NOTICES.md)。
