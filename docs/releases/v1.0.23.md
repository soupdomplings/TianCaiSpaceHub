# V1.0.23 本地测试交付

日期：2026-11-11（北京时间）。开发基线为唯一 `main` / `48747e6`。用户确认 V1.0.22 真实对话已连通，同时反馈浮层被业务页覆盖，要求实际验证助手配置操作并补充使用指引。

## 本轮范围与协作

管理会话复用原有界面、助手后台和只读审查代理，先完成原生遮挡、工具能力与指引、隔离测试边界；首批冻结后已完成验收。打包前用户追加隐藏 WebStorm/VS Code、增加 MiniMax 厂商预设，以及当前小分队用户密钥创建/列表选择到客户端的完整配置流程，继续并入同一份 V23 测试包，由管理会话完成最终集成、文档和授权范围内源码提交。

- 对话浮层启用 Windows 原生兄弟/子级裁剪，展开、定位和切页后维护子窗层级，避免业务页后代重绘覆盖消息与输入。
- 新增随代码维护的中文操作指引，要求先读、执行、回读、如实汇报；补全渠道/副本/动态模型的实际身份与参数。
- 修正 WorkBuddy 不支持字段仍宣称可修改、Codex 内置能力覆盖无效及导航提前报告成功。模型/API/鉴权继续来自小分队配置 GET，其余沿 Hub Codex 流程。
- 已隐藏 WebStorm/VS Code 的可见客户端入口，保留已有配置与后台支持；新增 MiniMax 厂商模板；助手支持列出当前用户 API 密钥、指定已有密钥或创建后取得本机引用，继续配置渠道与指定客户端。

实现、配置兼容与回滚见 [天才搭档](../customizations/genius-buddy.md) 和 [桌面视觉](../development/desktop-visual-system.md)。没有配置迁移；回退不会撤销已保存的配置。

## 验证与边界

用户本轮明确授权管理会话测试，因此实际观察运行中的 V1.0.22，在 1168×754 窗口复现业务卡片/图表遮挡；另向旧版发送一次只读帮助请求，已正常完成。这两项只证明 V22 的现状，不能代替新实现验收，未清空用户的当前对话。

本轮 Windows locked/offline GUI 测试目标编译已通过，16 个不同定向用例通过：配置工具 11、worker 协议 3、几何 1、隐藏原生组件/切号 1。后续仅修改显式启用的真实验收夹具时，复用未变化的产品回归，不重新计数。

真实 Server / 小分队管理员模型 `gpt-6-luna` 验收已通过，整个流程约 93 秒，保持同一个 thread，完成 **7 轮、18 次真实工具调用**，没有工具执行失败。一次本机凭据表单使用合成测试值；新建停用渠道及模型/别名后启用并配置到临时 VS Code，回读与实际原生 JSON 的窗口、输出、强度列表一致。两项批量删除先拒绝、再批准，各只有一次确认；拒绝后配置不变，批准后只删除指定测试条目。首段输出后真实中断为 stopped，随后同会话继续读取成功。关闭回收临时会话，保存配置与共享 Server 保留。记录为 `real-acceptance.json`、`real-verification.json` 与 `real-test.log`。

测试写入限定临时 Hub 配置及临时 VS Code 目标，凭据为合成测试值；复用既有小分队登录及共享运行端，正常鉴权可能续期会话。不运行完整 daemon，避免启动路径修改用户客户端。删除同意/拒绝由隔离 loopback API 对自建测试条目模拟，不代表点击用户真实删除确认框。首次启动夹具使用了与生产不同的路径分隔符，未取到按路径标识的登录；仅校正测试入口的路径写法后通过，失败记录单独保留，不作为产品失败或通过结果。

原生屏幕夹具最终通过，约 13 秒内覆盖浅深色、1168×754 / 900×560、两层页面及滚动、输入/发送命中、业务页叶级 DC 裁剪、收起/最小化/隐藏恢复。16 组实际 ScreenDC 截图及几何元数据保留，管理会话查看浅深色与大小窗口的 4 张代表图，消息/输入/发送完整且业务图表止于浮层边界。最初两次取点受首显 DPI/过渡缩放影响失败，仅在测试窗口启用 DPI 上下文并禁止 DWM 过渡后通过；没有放宽像素、命中和 DC 断言，也未因夹具更改产品逻辑。记录为 `overlay-verification.json` 与 `native-review/`。产品浮层随后未改，这一检查可复用。

追加需求后的最终 Windows locked/offline GUI 测试目标编译通过，累计 **57 个不同定向用例**通过：助手工具11、worker3、proxy2、密钥工具2、客户端身份/可见性3、Shell/概览各1、模型映射及 MiniMax28、账户导入3、天工分享1，以及复用未变产品输入的浮层几何/切号各1。首批16项已包含其中，不重复相加；最终只修改显式验收夹具后的编译没有重跑产品回归。

新增密钥流水线的真实 Server/管理员模型验收单独通过，约45秒、同一个 thread 的 **3轮、8次工具调用**全部成功：读取真实分组，在当前已登录账户创建唯一具名、额度上限0.01且有效1天的临时密钥，再按名称搜索当前 API 列表并选定它，准备真实导入结果，保存启用渠道，配置到临时 ZCode 的指定模型，最后回读及核对 `v2/config.json` 中的真实模型身份。没有凭据表单或额外确认；导入来源与密钥保存在隔离 Hub 配置中，不进入模型上下文。测试结束已撤销且仅撤销本次临时密钥，没有调用该用户密钥的推理接口、充值或操作已有密钥。助手对话本身使用管理员提供的模型。记录为 `real-key-pipeline.json`、`keypipeline-verification.json` 与 `keypipeline-test.log`。
