## 界面和入口

| 入口 | 用途 |
| --- | --- |
| 概览 → 运行状态 | 同时看当前客户端、Hub、进行中的模型和对应渠道；点击节点进入相应客户端、请求集合或渠道 |
| 概览 → 使用统计 | 今天/近 7 天/近 30 天的请求、成功率、输入与输出，曲线及客户端/模型/渠道分布；下钻到真实日志 |
| 天才小分队 | 登录已经部署的站点，管理个人账户、API密钥、站点用量、组织和充值/订阅购买 |
| 客户端 | 本端状态图、模型、Skill、MCP及统一“接入设置”；后者管理配置文件、支持的程序位置和本端维护；初次三端为 ChatGPT/Codex、WorkBuddy、天工 Work |
| 模型与渠道 | 添加实际厂商/API/账号来源、发现模型、别名与渠道设置；新增端专用副本标明归属 |
| Skill / MCP 管理 | 添加并直接用于所选客户端，自动读取已有资源，处理部分失败/冲突；低频恢复在设置 |
| 聊天接入 | 既有 IM 账号、远程会话、目录、模型、任务及审批 |
| 请求日志 | 整库筛选分页、原始详情；保留客户端请求与实际上游行为的差别 |
| 设置 / 帮助 | 外观/网络/客户端配置根/组件维护、页面说明；各页“？”给当前操作帮助 |

Hub默认以普通窗口打开，不自动最大化。侧栏“⋯”展开全部时保持客户端原位置，连续点击不会跳动；收起时才按已记录的访问替换三个位置，已经在三个位置中的端不会互换。第三端下方“⋯”展开，标题右侧仅折叠图标收起。侧栏不显示滚动条，内容超出时仍可滚轮/键盘浏览。这与资源选择中“成功使用端排前”独立。

各客户端右上方正常状态只保留启动按钮，进入和保存后自动读取。WorkBuddy/天工读取或保存失败时才出现“载入更新”，明确操作后读取新基线并保留草稿参数，自动读取不更换草稿的原 revision。Codex仍为原增强启动，WorkBuddy/天工沿原桌面启动流程。启动失败按现有提示修正路径或配置，不把按钮点下当成已经启动。七端统一“接入设置”，配置文件只显示本端/Profile的实际位置，可打开文件夹；新四端可选择程序，Codex维护/历史、天工同步和WebStorm组件仍在此处。WorkBuddy恢复仅有备份时出现，也移到接入设置。

使用统计在顶部选择日期、客户端及已有模型/渠道，无须手填，“清除”恢复全部。四个小指标卡下是平滑趋势，悬浮显示时段、请求、输入和输出；删除查看请求按钮，仍可点曲线或分布行进入真实日志。页面无整页滚动：空间足够时同时显示趋势和分布，统计视口不足560 DIP高时默认趋势，用“用量分布 / 用量趋势”切换。原日志详情、首字/缓存原字段和输入输出口径保持；对象很多的分布表自身仍可滚动。

## 接入一个模型，再给另一端复用

1. 在模型与渠道添加来源，按厂商填写所需信息；也可从天才小分队的 API 密钥执行已有导入流程。
2. 打开目标客户端 → 模型，点击“添加模型”，在当前列表末尾出现“新建模型”。在右侧选择来源和模型，调整本端参数，点“保存模型”才创建独立配置；直接选择已有条目可继续查看，切回来保留草稿，放弃不写。无需先区分新增与复用，也无需返回另一套模型列表。
3. 在另一端重复选择同一来源即可。新端获得独立条目/路由，各端协议、能力及参数分别调整。
4. 来源后续变化时，在对应客户端选择同步内容。未选择的副本保持原配置；不因同名模型而共用其他条目。

Codex 的模型可见列表、初始化/恢复、增强启动、WebSocket、历史和修复入口保留在该端模型/接入设置。WB 与天工保留原多模型和参数配置服务，原保护和撤销继续有效。

新四端统一模型列表和操作位置，参数按本端真实写入能力显示：VS Code 和 ZCode 可配置其支持的上下文/输出、图片和思考强度，Harness 另有协议；WebStorm 原生能力由 IDE 管理，ACP 仅提供上下文/输出和图片，不展示无效的能力输入。连接设置修改本端独立连接，同步来源只应用本次显式选择。后台刷新不覆盖草稿；来源 revision 变化后显示“载入更新”，放弃草稿并载入最新配置后再保存。

“使用中”表示配置已经成功选择/登记。端内尚未刷新时，按该端提示新建聊天、重新加载或重启；Hub 不会开发时自动启动客户端。VS Code 管理的是内置 Chat 的自定义模型，自己的信任提示仍须在 VS Code 确认。

## 新增客户端

| 客户端 | 本轮范围 | 需实机确认 |
| --- | --- | --- |
| VS Code Chat | 已安装/便携位置及已登记 Profile；继承默认模型时在默认位置管理；Skill、MCP 按原生位置 | 所装版本能读取相应配置、信任提示、新会话刷新 |
| DeepSeek Harness | 现代原生模型、实际 Profile MCP、完整 Skill 目录及独立路由；仅有旧模型目录时先建立受支持 Profile | 本机版本与原生 schema/可执行程序路径 |
| ZCode | 按 HOME 和端内迁移定位原生模型；MCP、Skill 仍在原位置 | 本机版本读取、数据迁移位置和实际请求协议 |
| WebStorm AI Assistant | Hub 导出辅助插件，通过 IDE API 读写模型与 PasswordSafe；MCP/Skill 按原生位置配置 | 插件安装并重启 IDE，AI Assistant 262.11879 系列及实际使用 |
| WebStorm Air/ACP | 用户在接入设置显式安装固定 ACP 组件，Hub 写 agent/模型/MCP/Skill | IDE 可识别 ACP agent、模型切换及权限/工具 |

WebStorm 两种模式按各自配置使用；AI Assistant 原生插件与 Air/ACP 不混作一份接入。辅助插件不会由 Hub 自动装入正在运行的 IDE。组件安装/修复会下载固定版本并核验哈希，只有用户点击才执行。

客户端配置根和启动程序位置可在设置中修正。没找到安装或权限不足时给出解决入口；不能把读取失败显示成“未使用”。Windows 与 macOS 的真实加载均由用户验收，当前仅 Windows 有本地构建包。

## Skill 与 MCP

客户端内默认“使用中”仅展示本端实际使用内容及需核对的受管配置；“可添加”列出兼容内容。全局管理页仍保留完整资源与跨端使用选择。页面改为随窗口换列的卡片，卡片显示使用摘要及“管理客户端”；点开后二级页选择客户端，再点“应用更改”才真正修改，←返回不会应用草稿。本端仅列自己的位置；“查看配置文件”只显示路径、原因和打开文件夹入口。

进入时自动读取并收录客户端已有内容，十秒内重复进入合并；右上刷新图标会重新读取，不再同时提供“读取已有内容”和“重新读取”。自动读取不会把资源用于其他客户端。失败才显示重试；受保护的历史恢复集中在设置 → 恢复 Skill / MCP 配置。

Skill 选择含 SKILL.md 的完整目录或 ZIP，也可进入“Skill 广场”选择真实公共仓库内容；附件、脚本和子目录随包保留，Hub 不执行导入脚本。二级页选择客户端后点“应用更改”才真实配置，成功才点亮；管理已有使用时取消某端并应用，其他独立端不随之关闭。原生共享目录的多 Profile 会同时受该物理目录影响。

MCP 的新增界面有“表单 / JSON”两种编辑方式，同一草稿互相同步。使用服务提供方给出的 URL、命令和 JSON，按其传输选 HTTP、SSE 或本地命令；不要求先选择“知识库/网页搜索”等用途模板。地址、认证头、启动参数、环境变量和高级字段均可填写，未理解的未知 JSON 字段保留。

添加时选择要使用的客户端，实际保存并读回成功后点亮；部分成功只点亮成功目标，失败目标可单独重试。同名/外部后改先核对再决定替换，撤销拒绝覆盖用户后来修改。天工资源通过本机原生服务登记，客户端未打开时提示打开后重试，不伪造登记成功。

Dumpling-MCP 从 MCP 管理进入，先配置环境与 NVWA 认证，再选择 Codex/WB/天工接入。原三种认证内容、工具摘要、环境维护及撤销保留；通用 MCP 不替代这套专用授权流程。

## 状态与用量如何判断

- 运行图依据已打开客户端或在途请求显示端；没有打开端、没有在途请求才只显示Hub。来源暂未识别的真实请求仍显示Hub→模型→渠道。
- 模型/渠道依据实际请求路由显示，多端同名依独立路由关联。概览约300毫秒读取活动，不等待远控或聊天状态；极短请求可能在两次读取间结束。结束先停流，约三秒后缓动暗淡并留到离开重进；失败/等待停止流动，日志不受此显示间隔影响。
- 配置成功、客户端打开、本机桥状态和上游调用结果分别判断；绿色不同时代表四种事实。未知状态保留未知。
- 模型节点打开对应请求集合，渠道节点进入准确渠道。新请求来源按专用路由、受管配置或明确请求标识记录；历史没存的来源显示“未标记来源”，不按模型名回填。请求页正文随窗口铺满，低频条件折叠，技术列可横向滚动。
- 输入与输出各一个用量，缓存不单列、不重复加；本机统计依据协议报告的用量，缺报告时不能推算成站点账单。
- 站点使用记录/扣费由天才小分队 API 返回；本机统计不替代站点账务。首字统计不新增，原日志详情保持。

自动读取出现容量或权限问题时，当前资源页显示“N项未读取 · 查看处理方法”。打开后可看具体项目、原因与处理建议，点“打开所在文件夹”核对，修正后重新读取。这不是模型调用失败；原文件保持，不会自动删减。Dumpling页也有←返回入口。

## 天才小分队

顶部账户入口显示用户名和余额，点击进入资料。未登录进入天才小分队先显示登录页，自动检查可用登录方式。当前站点尚未启用浏览器授权接口，使用“内置登录”沿官网验证完成登录；接口可用后，“在浏览器中登录”可复用浏览器已有站点登录态，核对六位码并确认后进入Hub原生工作区。已登录工作区的“回到主站”打开默认浏览器；配套接口启用后接续为同账号独立会话，否则保留浏览器自己的登录状态并明确提示。Hub不需要另部署网站，现有主站需应用[配套补丁](../integrations/tiancai-squad-browser/README.md)才能双向接续，本轮未部署。账户、密钥、用量、充值/订阅购买、资料及条件组织页面仍是Hub原生内容，权限沿站点实际返回。

普通页面数据在内存短时复用：列表/统计15秒，账户/组织30秒，公开设置5分钟。希望马上看到站点变化时点右上刷新；失败不缓存，登录/退出/保存清缓存。首次打开及新的筛选仍取决于站点速度。密钥“导入Hub”进入原预览，确认后保存；仍可决定是否启用，不会自动替其他客户端改配置。

组织列表选中对象后点“管理组织”或“查看用量”；工作台按成员与部门、成员额度、组织用量、挂账与余额分组，当前子页只显示相关按钮与筛选。成员查看直接嵌入资料、余额、限额、菜单权限和扣费身份；预算、分组授权和用量报告入口已移除。额度分配区分配置比例、预计与本期实际金额；挂账区分已出账待清、未出账累计，预存余额单独显示可用和预留，账单、清账及发票保持。部门管理员只得到自己的范围；站点超级管理员的手动财务调整不授予普通组织管理员。批量选择可搜索并明确所选人数，金额/重置确认后提交。个人余额兜底在组织与扣费页直接开关，成功才切换，失败保留旧值并提示原因。

充值/订阅在页面内输入金额、选择支付方式后点“立即充值”，或切换订阅方案后购买；显示支付、手续费及到账，提交前实时核对站点价格、规则和限额。最终以站点订单为准，支付窗口只继续该订单，关闭或跳转不确认付款，需要服务器查单。，余额、扣费、额度和详情只换人民币标识，站点原数字不变，无需读取汇率；财务分单位仍按元展示，缺少金额字段显示 `—`。金额编辑直接保存输入数字，未修改值保留原精度；实际付款报价、发票税费整数舍入、站点账本和付款字段保持原合同。

点击顶部账户入口进入个人资料，只查看资料并提供“退出登录”；没有编辑资料或安全设置入口，退出按钮不在其他页面常驻。退出不删除已导入的模型渠道。

网络中断、超时或 5xx 后，写入可能已经完成。Hub 保留“待确认操作”，阻止同一写入直接重试；先读取列表/订单确认结果，再显式移除标记。不会通过自动重放避免报错。401 尝试一次刷新，失效时重新登录；403 显示权限错误。退出账户不删除已经导入的本地模型渠道。
